# Handoff: Argus 랜딩 — 제품 필름 2종 + 컴포넌트/워크스페이스 2종

## Overview
이 묶음에는 **4개의 디자인 레퍼런스**가 들어 있습니다 — 자동재생 제품 필름 2편과,
그 필름이 기대는 입체 컴포넌트·워크스페이스 페이지 2편. 모두 Argus의 핵심 메커닉 ―
"질문 → **숨은 전제** 도출 → 크루(에이전트) 작업 → 결과"를 한 시스템으로 표현합니다.

1. **ArgusHeroDemo** (필름) — 히어로 상단용. *한 번의 Argus 세션*을 6개 비트로 보여주는 제품 투어.
2. **DecisionVoyage** (필름) — "II. 항적(The Trail)" 섹션용. *항해 해도(chart) 위*에서 의사결정이
   어떻게 이어지는지를 **여러 세션**(갈림길 → 선택 → 전진 → 다음 갈림길)으로 보여주는 필름.
3. **ArgusV2** (페이지) — 입체로 다시 세공한 프리미티브(버튼·카드·배지·필드) 카탈로그.
4. **ArgusWorkspace** (페이지) — 3D 결정 차트 + 크루-소환 패널. DecisionVoyage의 정적 원형.

---

## About the Design Files
`source/` 안의 `*.dc.html` 파일은 **HTML로 만든 디자인 레퍼런스**입니다 — 의도한 모습과
모션을 보여주는 프로토타입이지 그대로 가져다 붙일 프로덕션 코드가 아닙니다.
목표는 **이 모션/레이아웃을 대상 코드베이스의 기존 환경(React 등)에서 그 패턴·라이브러리로
재구현**하는 것입니다. (환경이 없다면 가장 적합한 프레임워크를 골라 구현)

> ⚠️ 파일 형식 주의: `.dc.html`은 사내 디자인-시스템 런타임(`support.js`, `ds-base.js`)에 의존하는
> 포맷입니다. **로직 클래스(`class Component extends DCLogic`)의 타임라인 수학과 카피·색상이
> 곧 사양(spec)** 입니다. 프레임워크에선 `setInterval` 기반 시계 → `requestAnimationFrame` +
> `useState`/signals 로 옮기고, `renderVals()`가 반환하는 스타일 객체를 그대로 인라인 스타일로
> 매핑하면 1:1로 재현됩니다.

## 공통 설계 시스템
- **분위기**: 양피지(parchment) 위 잉크의 "항해 일지(logbook)" 톤.
- **골드 규칙**: 골드(`--accent`)는 **화면당 한 번**, 가장 중요한 순간에만.
- **타입**: 제목/본문 세리프 `--font-display`(Noto Serif KR), 라벨·수치는 모노
  `'JetBrains Mono'`, 한글 가독 `word-break:keep-all`.

## 필름 1 — ArgusHeroDemo (제품 투어)

**용도**: 히어로 상단. 16:10 앱 윈도우 한 장 안에서 한 세션이 흐름.
**구성**: 상단에 *지속되는 타이틀바*(라이브 상태 라벨 + 크루 아바타 스택 + 6개 도트),
그 안에서 6개 장면이 크로스페이드.

**타임라인** (`this.segs`, `this.TOTAL = 17900ms`, 루프):
| # | 장면 | 구간(ms) | 상태 라벨(색) | 핵심 |
|---|---|---|---|---|
| 0 | **Brief(상황 입력)** | 0–3600 | 상황 읽는 중 (gold) | 사용자 문장이 타이핑되며 핵심 구절에 골드 밑줄 캡처 칩 |
| 1 | **Crew Summon(크루 소환)** | 3600–6100 | 크루 소환 (gold) | 황동 나침반 둘레로 4개 크루가 차례로 등장 |
| 2 | **Analysis(해도 분석)** | 6100–9400 | 해도 분석 중 (gold) | 차트지 캔버스 위에 분석 카드들이 그려짐 |
| 3 | **Ask Back(되묻기)** | 9400–11900 | 확인 필요 (`#c9852f`) | Argus가 사용자에게 되묻고 2개 보기 제시 |
| 4 | **Workers(작업)** | 11900–14600 | 크루 작업 중 (gold) | 진행률 0→100% 게이지 |
| 5 | **Draft(초안)** | 14600–17400 | 초안 완성 (`--success`) | 한눈에 보이는 결과 초안 |

**입력 문장(scene 0, 골드 캡처 키워드)**:
> "대표님이 갑자기 신사업 기획안을 2주 안에 만들어오라고 했어. 백엔드 5명인데 기획은 처음이야."
> — 골드 밑줄: **"2주 안에"**, **"기획은 처음"**

**Tweaks(props)**: `speed`(차분히 0.72 / 기본 1 / 빠르게 1.45), `grain`(종이 질감 on/off),
`captionBar`(상단 캡션 on/off).

**핵심 모션 함수**:
- `env(t,a,b)` — 장면 페이드 인/아웃 엔벨로프(fade-in 440ms, fade-out 380ms) → `{o, ty}` 반환.
- `lp(t,i)` — i번째 장면 내 0~1 로컬 진행도.
- `reveal(p,k,step,dur)` — 자식 요소들의 stagger 등장.

## 필름 2 — DecisionVoyage (II. 항적 — 해도 위 의사결정)

**용도**: "II. 항적(The Trail)" 섹션. 5:3 양피지 해도(3D rotateX(20deg)) 무대 위에서
의사결정이 항로로 그려짐. **2개 세션**이 이어짐(`this.ACT = 22000ms`씩, `this.TOTAL = 44000ms`, 루프).

**한 세션의 7단계(phase)** — 하단 진행바 + 단계 라벨로 표기:
1. **질문** (0–3000) — Argus가 묻는다 (선장의 지시 박스, 좌상단)
2. **전제 도출** (3000–6500) — 크루가 캐낸 **숨은 전제**가 화면 중앙에 크게 떴다가
   상단으로 떠오름(중앙 정렬 x=480px). *어두운 잉크 패널 + 골드 점선 테두리* 로 차별화.
3. **갈림길** (6500–10000) — 두 항로(세션1: 예/아니오)·세 항로(세션2)가 **점선**으로 동시 표시.
   각 끝점에 선택지 카드(우측, `left:640px~`).
4. **선택** (10000–13000) — 커서가 선택 카드로 이동·클릭. 고른 항로의 점선이 **실선**으로 이어짐.
5. **전진** (13000–16400) — 깃발 단 배가 선택한 항로를 따라 전진.
6. **현재 방위** (16400–19400) — 하단에 결과 플레이트("전제 교정 — …") 등장.
7. **다음 세션으로** (19400–22000) — 전환 카드("새로운 갈림길 · Session 2/2") 후 2번째 세션 시작.

**세션별 콘텐츠** (`this.D` 배열):

세션 1 — *마케팅 예산 2배 논쟁*
- 선장의 지시: "신규 가입이 3주째 폭증 중. 지금이 절호의 기회처럼 보인다." / **"마케팅 예산을 2배로 태울까?"**
- 숨은 전제: **"지금 몰린 사용자는 그대로 남는다"** — "이 가정부터 따져봐야 한다."
- A (아니오 · 전제가 틀리다): **누수부터 막고 키운다** — 느리지만 안전 · 이탈을 먼저.
- B (예 · 전제가 맞다): **예산 2배 증액** — 빠르지만 위험 · 밑 빠진 독.
- 선택: **A**. 결과 플레이트: "전제 교정 — 누수부터 막고 키운다"

세션 2 — *이탈 방어 지점* (세 갈래)
- 선장의 지시: "잔존을 끌어올리기로 했다. 그런데 팀은 자꾸 새 기능부터 만들자고 한다." / **"이탈, 어디서 막을까?"**
- 숨은 전제: **"기능이 많아질수록 더 머무른다"** — "모두가 당연하게 믿는 가정."
- A (온보딩 재설계): 첫날 이탈부터 잡기 — 효과는 빠르지만 표면적.
- B (핵심 가치를 체감): **"쓰는 이유"를 먼저 경험** — 근본적 · 체감 시 잔존 3배.
- C (기능 더 추가): 요구는 많지만 — 정작 잔존엔 영향이 적다.
- 선택: **B**. 결과 플레이트: "전제 교정 — 기능이 아니라 '쓰는 이유'가 잔존을 만든다"

**크루(에이전트)** — 하단 "쟁점 자동 감지 → 크루 배정" 바: **재무·회계 / 마케팅·그로스 / 전략**
(각 음각 디스크 아이콘 + 한 줄 근거 수치).

**해도 좌표계** (SVG viewBox `0 0 900 460`): 트렁크 `M70,232 → 214,232`에서 분기. 위 항로 끝
`624,112`(예/A), 가운데 `632,222`(세션2 B), 아래 `612,352`(아니오/암초). 선택지 카드는 각 끝점
오른쪽(`left:640/648px`)에 앵커.

**Tweaks(props)**: `speed`(0.5~1.6), `pauseAtArrival`(도착 시 일시정지).

## Interactions & Behavior
- 두 필름 모두 **자동재생 · 무음 · 무한 루프**. 사용자 입력 없음.
- 시계: `setInterval(40ms)` → `t = (elapsed * speed) % TOTAL`. (프레임워크에선 rAF 권장)
- `prefers-reduced-motion: reduce` → 애니메이션 정지, 마지막 결과 비트 표시
  (Hero: `t=15800`, Voyage: `t=18600`).
- 모든 등장은 `opacity`+`translateY` 트랜지션. 커서 이동·클릭(Voyage scene 4)은 위치 보간 + 리플.

## State Management
- 단일 상태 `t`(경과 시간, ms)만으로 전 화면이 파생됨(`renderVals()`가 `t`로 모든 스타일 계산).
- 외부 데이터 페치 없음. 콘텐츠는 컴포넌트 내부 상수(`this.D`, `this.S`, `this.segs`).
- 마운트 시 타이머 시작, 언마운트 시 `clearInterval`.

## Responsive
- 무대는 `width:100%; max-width:980~1000px; aspect-ratio` 고정(Hero 16:10, Voyage 5:3).
- 내부 좌표는 디자인 폭 기준 고정 px. 컨테이너 스케일로 대응(필요 시 `transform:scale`).

## 페이지 3 — ArgusV2 (Component Foundry · 컴포넌트 쇼케이스)

**용도**: Argus 프리미티브(버튼·카드·배지·필드)의 **입체 리빌드** 카탈로그 페이지.
평면이던 컴포넌트를 음영·베벨·종이 질감으로 다시 세공한 결과를 한 페이지에 나열.
**이것은 "디자인 방향 명세"입니다** — 코드베이스의 실제 컴포넌트(Button/Card/Badge/Field)에
이 입체 처리(레이어드 섀도, 헤어라인 보더, 양피지 면, 골드 틴트 칩)를 입히는 가이드로 보세요.

- 레이아웃: `max-width:1140px` 중앙, 섹션 간 `gap:72px`. 커버 헤더(좌: 세리프 H1 "정교하게
  벼려낸 / 항해 도구상자", 우: 떠다니는 황동 나침반 SVG) → 컴포넌트 섹션들.
- 배경: 양피지 `#ece3d0` + 라디얼 하이라이트 2겹 + 미세 가로 스캔라인(`repeating-linear-gradient`).
- 골드 규칙·타입·토큰은 **공통 설계 시스템**과 동일.

## 페이지 4 — ArgusWorkspace (Decision Chart & Crew)

**용도**: DecisionVoyage 필름의 **정적(static) 원형(原型)** 페이지. 두 줄짜리 평면 ForkPath를
**3D 양피지 결정 차트**(rotateX로 기울인 해도 + 함선 마커 + 떠오르는 선택지)와
**황동 크루-소환 패널**로 재세공. 필름이 "움직이는 버전"이라면 이쪽은 "정지 컷 + 컴포넌트 사양".

- 레이아웃: `max-width:1080px` 중앙, 섹션 간 `gap:84px`. 헤더 → `01 · Decision chart`(3D 차트)
  → 크루 소환 패널.
- 차트 좌표·함선·나침반 SVG는 DecisionVoyage와 동일 계열(필름의 정지 프레임으로 상호 참조 가능).
- DecisionVoyage를 구현할 때 **개별 컴포넌트(차트/함선/크루 디스크)의 정적 스펙**을 이 페이지에서
  떼어 보면 편합니다.
