# Argus MCP + 플러그인 — 독립 검증 지시서

**대상 실행자:** Claude 이외의 에이전트(Codex 등) 또는 사람
**목적:** 이 저장소의 MCP 서버와 플러그인이 **실제 사용자 경험 수준에서** 동작하는지를,
이전 작업자의 주장에 의존하지 않고 처음부터 직접 확인한다.

> **왜 이 문서가 존재하는가.** 2026-07-27~28에 창업자가 "확인창에서 Accept를 눌러도
> 기록이 안 된다"를 **세 번** 보고했다. 세 번 다 "고쳤다"는 답을 받았고, 세 번 다 게이트는
> 초록이었다. 첫 번째는 `required` 필드, 두 번째는 `format` 제약이었고 — 둘 다 진짜
> 결함이었지만 — **셋 다 원인이 아니었다.** 진짜 원인은 §3에 있다.
>
> 공통 실패 양상은 하나다: **"게이트가 초록"과 "사용자가 쓸 수 있다"를 같은 말로 취급했다.**
> 그러니 이 문서를 수행할 때, 초록불을 근거로 삼지 말고 **당신이 직접 관찰한 것**만 근거로 삼아라.

---

## 0. 규칙

1. **이전 작업자의 결론을 전제로 삼지 않는다.** 이 문서의 §3(원인 분석)조차 검증 대상이다.
   틀렸다고 판단되면 그렇게 보고하라 — 그게 이 문서의 목적이다.
2. **"통과했다"가 아니라 "무엇을 보았다"로 기록한다.** 명령의 실제 출력을 붙여라.
3. **못 한 것은 못 했다고 적는다.** 빈칸을 추정으로 채우지 않는다.
4. 창업자의 실행 중인 터미널 창에 키 입력을 넣지 않는다. 새 창에서만 조작한다.
5. `claude` 프로세스를 이름으로 죽이지 않는다(`Stop-Process -Name claude` 등 금지).
   다른 워크트리의 세션까지 죽는다. 자신이 띄운 **특정 PID만** 종료한다.

## 2. 기계 검증 — 전 게이트

```bash
node evals/verify-all.mjs
```

이 스위트는 게이트를 돌린 뒤 **자기 자신을 시험한다**: 소스에 회귀를 일부러 심고
게이트가 빨간불이 되는지 확인한 다음 파일을 원래 바이트로 복구한다.

**주의 1 — 중간에 죽이지 마라.** `npm run clean`이 `dist/`를 지운 직후에 중단되면
이후 모든 게이트가 "Connection closed"로 실패한다. 제품 결함이 아니라 빌드 산출물이
없는 것이다. 중단했다면 `npm run build`로 복구하고, 심어둔 회귀가 남지 않았는지
`git status`와 `git diff`로 확인하라. (스위트 끝의 "자기검증 뒷정리" 항목이 파일
복구를 확인해 준다 — 중단하면 그것도 안 돈다.)

**주의 2 — 20분 안팎 걸린다.** 자기검증 19개가 각각 소스를 수정하고 재빌드한다.

**주의 3 — 게이트가 빨간불이라고 곧바로 제품 결함은 아니다.** 두 경우를 구분하라:
- 제품이 실제로 깨졌다 → 고쳐야 한다
- **게이트가 옛 계약을 고정하고 있다** → 게이트를 고쳐야 한다

  2026-07-28에 이 부류가 여러 건 나왔다. 확인창에서 입력칸을 없애자 "입력 칸이 있다",
  "타이핑한 말을 돌려준다" 같은 단언이 전부 빨개졌는데, 화면은 오히려 **좋아진** 것이었다.
  판단 기준: *이 단언이 지키려던 사용자 가치가 무엇인가? 그 가치가 지금도 지켜지는가?*

기대 결과: 전 게이트 통과 + 심은 회귀 전부 적발.

기록할 것:

- [ ] 실패한 게이트가 있으면 그 이름과 note, 그리고 위 세 부류 중 어느 것인지

## 3. 핵심 결함의 재현 — Accept가 먹히지 않던 이유

**이것이 이 문서에서 가장 중요한 절이다.** 아래 주장이 사실인지 직접 확인하라.

### 3.1 주장

Claude Code(v2.1.220)의 elicitation 폼은 이렇게 동작한다:

```js
const hasFields = Object.keys(schema.properties).length > 0
const [selected] = useState(hasFields ? null : "accept")   // 필드가 있으면 Accept 미선택
handleTextInputSubmit = () => move("down")                 // 칸 안에서 Return은 "이동"
if (key === "return" && selected === "accept") { ... 제출 ... }
```

따라서 **입력칸이 하나라도 선언된 픽커는 "읽고 Enter"로 제출되지 않는다.** 커서가 첫 칸에
있고, Enter는 다음 줄로 이동할 뿐이다. 사용자는 아무 일도 안 일어나는 것을 보고, 60초 뒤
SDK 타임아웃이 호스트에서 `cancel`로 보고된다.

### 3.2 근거 직접 확인

Claude Code 바이너리에서 해당 코드를 직접 읽어라. 경로는 설치 방식에 따라 다르다:

```bash
# npm 전역 설치의 경우
ls "$(npm root -g)/@anthropic-ai/claude-code/bin/"
```

바이너리에서 `tengu_mcp_elicitation_response` 문자열 주변을 덤프하면 elicitation 핸들러가,
`requestedSchema`가 포함된 JSX 영역을 덤프하면 폼 컴포넌트가 나온다. 다음을 눈으로 확인하라:

- [ ] `useState(... ? null : "accept")` — 필드가 있으면 Accept가 미선택인가?
- [ ] 텍스트 입력의 submit 핸들러가 `move("down")`인가?
- [ ] 선택형(enum)에서도 `if (key === "return") { move("down") }`인가?

**이 셋 중 하나라도 다르면 §3.1은 틀린 것이다. 그렇게 보고하라.**

### 3.3 기계로 재현

```bash
node evals/claude-code-form.mjs
```

이 게이트는 위 로직을 그대로 구현해서, 서버가 실제로 보내는 모든 픽커를 판정한다.
**판별력 확인이 핵심이다** — 고장난 버전에서 빨간불이 떠야 의미가 있다:


기대: **2.0.2는 빨간불**(F5 위반 다수), 현재 빌드는 초록.

기록할 것:

## 4. 실기기 검증 — 직접 눌러본다

기계 검증은 호스트를 **모델링**한 것이다. 이 절만이 진짜 호스트를 쓴다.

### 4.1 전용 창 준비

기존 세션과 섞이지 않는 새 프로젝트와 창을 만든다.

```bash
mkdir -p /tmp/argus-live && cd /tmp/argus-live
```

`.mcp.json`을 만들어 **로컬 빌드**를 직접 실행하게 한다(npm 배포본이 아니라 지금 고친 코드):

```json
{
  "mcpServers": {
    "argus-decision": {
      "command": "node",
      "args": ["<절대경로>/argus-mcp/dist/index.js"],
      "env": { "ARGUS_DIR": "/tmp/argus-live/.argus" }
    }
  }
}
```

이 디렉터리에서 **새 터미널 창**으로 Claude Code를 띄운다.

**Windows 함정 (실제로 밟았다):** `wt.exe`나 `cmd.exe`를 그냥 실행하면 Windows Terminal이
새 창 대신 **기존 창의 탭**으로 붙인다. 그러면 창업자가 쓰고 있는 세션에 키를 넣게 된다.
확인법:

```powershell
Get-Process -Id <내가 띄운 PID> | Select-Object Id,MainWindowHandle
```

`MainWindowHandle`이 `0`이면 자기 창이 없다 = 남의 창에 들어간 것이다. 즉시 그 PID만
종료하고 다른 방법으로 다시 띄워라(`conhost.exe cmd.exe /k ...`는 자기 창을 갖는다).
`Stop-Process -Name claude` 같은 **이름 기반 종료는 절대 금지** — 다른 워크트리의
세션까지 전부 죽는다.

### 4.2 봉인 확인창 — 한 번의 Enter

세션에서 다음을 호출하게 한다:

```
argus_predict(id:"live-1", predicate:"<아무 문장 8자 이상>",
              check_by:"2026-12-31", predicate_owner:"ai_surfaced", confirm_draft:true)
```

**관찰 항목:**
- [ ] 확인창이 화면에 떴는가?
- [ ] **입력칸이 없고** Accept/Decline만 보이는가?
- [ ] Accept가 처음부터 선택돼 있는가?
- [ ] **Enter를 한 번** 눌렀을 때 즉시 기록되는가? (여러 번 눌러야 하면 실패다)
- [ ] 응답의 `surface`가 "예측을 저장했습니다" 계열인가?

그 다음 되읽어서 **진짜 남았는지** 확인한다:

```
argus_patterns(view:"all")
```

- [ ] `live-1`이 목록에 있는가? (도구가 ok를 반환한 것과 기록이 남은 것은 다른 사실이다)

**호스트 로그로 교차 확인** (이게 결정적이다). Claude Code는 elicitation 요청과 응답을
모두 로그에 남긴다. 화면에서 본 것과 서버가 받은 것이 다를 수 있으므로, 이 대조가
"눌렀는데 안 된다"류의 유일한 객관적 증거다.

```
# Windows
C:\Users\<user>\AppData\Local\claude-cli-nodejs\Cache\<프로젝트 슬러그>\mcp-logs-<서버키>\*.jsonl
# macOS/Linux는 ~/.cache 또는 ~/Library/Caches 아래 같은 구조
```

찾을 줄: `Received elicitation request:` / `Elicitation response:` / `Tool '...' completed in`

- [ ] `Received elicitation request:` 의 `requestedSchema`에 `properties: {}`인가?
- [ ] `Elicitation response:` 가 `{"action":"accept"}`인가?
- [ ] 요청과 응답 사이 시간이 **당신이 누른 시점**과 일치하는가?
      (정확히 60.0초라면 그건 당신이 누른 게 아니라 타임아웃이 cancel로 둔갑한 것이다)

**실기기 조작 요령 (실제로 필요했던 것들):**

- 창이 **선택(mark) 모드**에 걸리면 화면이 얼어붙고 콘솔 읽기가 빈 값을 낸다.
  제목이 `선택 claude`면 그 상태다. 그 창은 버리고 새로 띄우는 게 빠르다.
- 포커스를 뺏어 키를 보내면(SendKeys) **다른 창으로 갈 수 있다.** 안전한 방법은
  그 프로세스의 콘솔 입력 버퍼에 직접 쓰는 것이다(`AttachConsole` + `WriteConsoleInputW`).
  포커스가 필요 없고 대상이 PID로 확정된다.
- `today_override`는 **공개 스키마에 없다**(테스트 전용, `public-tools.ts`가 의도적으로 숨김).
  실기기에서는 실제 날짜로 시나리오를 짜라. 연기(defer) 픽커는 **확인일이 지난 기록**에서만 뜬다.

### 4.3 정산 픽커 — 답을 골라서 넣는다

```
argus_predict(id:"live-2", predicate:"<문장>", check_by:"<어제 날짜>", predicate_owner:"user")
argus_resolve(id:"live-2")
```

- [ ] 어떤 예측에 대한 질문인지 화면에 보이는가?
- [ ] 선택지에 `held`/`avoided` 같은 **내부 값이 그대로 노출되지 않는가?**
- [ ] 화면 안내대로 조작했을 때 실제로 제출되는가?
- [ ] 한국어 세션이면 화면에 영어 단어가 튀지 않는가? (반대도)

### 4.4 오래 생각하기 — 60초 넘겨서 답한다

이건 반드시 확인하라. 이전 실패의 절반이 여기였다.

- [ ] 확인창을 띄우고 **90초 이상 기다린 뒤** Accept를 누른다
- [ ] 기록이 남는가? (남지 않으면 `elicitInput`에 timeout이 안 넘어가는 것이다)

### 4.4b 기록 시각 — 물은 때가 아니라 답한 때인가

이건 실기기에서만 보인다. 화면과 로그와 원장 세 곳의 시각을 대조하라.

```
호스트 로그: Elicitation response: {...}   ← 당신이 답한 순간
원장:        {"ts":"...","event":"seal"}   ← 기록된 시각
```

- [ ] 원장의 `ts`가 호스트 로그의 응답 시각보다 **앞서지 않는가?**
      (앞선다면 핸들러가 호출 시점에 찍고 사람을 기다린 것이다. 2026-07-28에 63초 앞선 사례)

이게 왜 중요한가: 앞선 시각은 아무것도 잃지 않지만, **정직한 기록을 위조된 것처럼 보이게 한다.**
실제로 그날 리뷰 세션이 payload만 보고 "서버가 판단을 지어내 user로 찍었다"고 결론냈다. 아니었다.

### 4.5 영수증 — 사람이 읽을 수 있는가

```

```

- [ ] `data.receipt_text`의 액자(상하 테두리)가 같은 폭으로 닫히는가?
- [ ] 긴 문장·이모지·공백 없는 한국어 문장을 넣어도 액자 밖으로 안 나가는가?
- [ ] 80칸 터미널에 들어오는가?

## 5. 픽커 없는 호스트 (Codex 등)

Codex는 elicitation을 선언하지 않는다. 그 경우 **픽커가 안 뜨는 것이 정상**이고,
설계상 텍스트 경로로 진행돼야 한다(커밋 `d113ef34` 참조).

- [ ] 픽커 없이도 봉인이 진행되는가?
- [ ] 출처가 `ai_surfaced`로 정직하게 남는가? (사용자 것으로 위조하면 실패)
- [ ] 조용히 아무것도 기록 안 하고 끝나지 않는가? (그게 과거의 데이터 유실 버그였다)

### 실기기에서만 나온 것 — 이 방식이 왜 필요한가

위 표의 마지막 두 줄은 **기계 검증 전부가 초록인 상태에서** 나왔다. 하네스는 즉시 답하므로
"화면 안내대로 비워두고 제출"도, "사람이 1분 생각한 뒤의 시각"도 재현하지 않는다.
§4를 건너뛰면 이 부류는 계속 살아남는다.

**이 표의 각 줄도 검증 대상이다.** "게이트가 있다"는 "고쳐졌다"의 증거가 아니다 —
게이트가 고장난 버전에서 실제로 빨간불이 되는지가 증거다(§3.3).

## 부록 B: 이 작업에서 실제로 일어난 실패 양상 (반복하지 말 것)

이 목록은 창피를 위한 게 아니라, 같은 함정을 당신이 다시 밟지 않기 위한 것이다.

1. **"게이트 초록 = 사용자가 쓸 수 있다"로 착각.**
   Accept 결함이 세 번 살아남은 이유. 게이트는 *우리가 검사할 생각을 한 것*만 본다.

2. **검사기가 대상과 같은 자를 사용.**
   이모지 폭 결함이 안 보였던 이유 — 검사 코드가 렌더러 자신의 폭 함수를 import했다.
   검사기는 대상과 **독립된 근거**로 재야 한다(`keepsake-frames.mjs`가 유니코드 속성으로 재는 이유).

3. **한 규칙의 사본이 여러 곳에.**
   `dw`만 고치니 `truncDw`·`breakToken`이 각자 인라인 사본을 갖고 있어, 판정은 새 자로
   자르기는 옛 자로 했다. 한 글자 폭을 정하는 함수는 하나여야 한다.

4. **하네스가 즉시 응답.**
   사람은 즉시 답하지 않는다. 60초 타임아웃 결함이 여기 숨어 있었다
   (`slow-human.mjs`가 일부러 75초 기다리는 이유).

5. **위치 기반 식별.**
   `picker-surfaces.mjs`가 "스크립트의 몇 번째 줄이 마지막에 돌았나"로 픽커를 분류해서,
   타이머로 뜨는 물음이 부하 중에 남의 자리를 차지했다. 게이트가 결함이 아니라
   **기계 부하에** 빨개졌다. 식별은 대상 자신의 모양(스키마)으로.

6. **문구를 고정한 단언.**
   게이트가 `Enter를 두 번`이라는 **특정 표현**을 찾고 있어서, 그 문구를 더 나은 한국어로
   바꾸자 빨개졌다. 단언은 표현이 아니라 **의미**를 검사해야 한다.

7. **도달 불가능해진 보호 코드.**
   봉인에서 필드를 없애자 "타이핑한 말 돌려주기" 보호가 어떤 호스트에서도 실행되지
   않게 됐고, 그 자기검증은 회귀를 심어도 초록이었다 — *게이트가 거짓말을 시작한 순간*.
   `extra-field` 호스트 프로필을 추가해 그 경로를 다시 살아 있게 만들었다.
   **도달할 수 없는 코드는 테스트할 수 없다. 둘 중 하나를 택하라: 살려서 검증하거나, 지우거나.**
