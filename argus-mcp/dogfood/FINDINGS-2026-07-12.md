# 도그푸딩 관찰 기록 — 2026-07-12 밤

창업자 지시로, Argus를 **실제로 써보며**(26개 현실 결정 시나리오를 실
툴 핸들러로 끝에서 끝까지 구동) 나온 관찰. 하네스: `dogfood/run.mjs`.

**정직성 경계**: 여기 발견은 *driver-observed*이지 *human-observed*가
아니다 — 사람의 감정 반응·우선순위는 P5 관찰 세션이 매긴다. 이 기록은
그 전에 "읽으면 명백한" 마찰만 미리 잡은 것이다.

## 방법

`dist`의 실제 툴 핸들러를 MCP SDK와 동일하게 **inputSchema 검증을 먼저
통과**시킨 뒤 호출(초기 하네스는 이 관문을 건너뛰어 500자 예측이 통과했다
— 하네스 자체 수정). 26 시나리오: seal→settle(held/missed/avoided/
partial/still_pending) · amend·dismiss·premises·watch·candidates·recall·
sync · 한글 로케일 · 경계(중복봉인·봉인전정산·재정산·과거확인일·빈예측·
초장문·주입) · 공정 큐 · 갓 설치.

## 창업자 판단이 필요한 것 (수정하지 않고 남김)

- **F1의 더 깊은 질문**: 정산의 "무게"를 어디까지 실을 것인가. 지금은
  사실 명명 + 영수증 손잡이까지만(스파인 안전선). 영수증 절대경로를
  surface에 평문 노출(규칙 18의 "복귀 캡슐 1클릭")까지 갈지, 정산일에
  더 의식(儀式)적인 표면을 줄지는 **제품 의미를 건드리므로 관찰 세션
  피드백으로 결정**해야 한다. (어제 합의: 의미-담지 표면의 "이만하면
  됐다"는 AI가 아니라 창업자가 판단.)
- **F(sync)**: 계정 미연결 시 `NOT_CONNECTED`가 에러 봉투로 온다.
  "로컬만 쓰는 중, 문제 아님" 톤이 나을 수 있으나, 명시적으로 sync를
  부른 사용자에게 "연결 안 됨"을 알리는 것도 정당 — 판단 보류.

## 하네스 자체가 잡은 것 (자기 교정)

- 초기 하네스가 handler를 직접 불러 **SDK 스키마 검증을 건너뜀** → 500자
  예측이 통과. 실서버 충실도를 위해 `inputSchema.safeParse`를 먼저
  통과하도록 수정. (교훈: 검증은 프로토콜 경계에 있고 handler는 그걸
  신뢰한다 — 우회 경로를 만들지 말 것.)
- API 인자 모양이 비직관적인 지점: `settle`은 `outcome_source:
  'user_stated'` 필수, `premises add`는 `premises[]` 배열, locale은
  `init`이 아니라 `config`. 모델이 스키마 설명으로 채우지만(설명은 꼼꼼),
  사람이 직접 호출하면 틀리기 쉽다 — 관찰 참고.
