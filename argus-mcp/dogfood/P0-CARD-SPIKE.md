# P0 · 작업 중 카드 스파이크 (기다림 포착의 땅 확인)

> 목적: "작업 중에 카드 하나 띄우고, 흐름 안 끊고, 사용자 답을 받아 기록까지"가
> 실제 호스트에서 되는가. 이게 기다림-포착 UX 전체가 서는 땅이다.
> 작성 2026-07-13. 상태: **기술 절반 확정(문서 근거), 체감 절반은 실세션 필요.**

## 결론 한 줄

작업 중 비차단 카드는 **된다 — 단, 문서가 그린 배관(훅·elicitation·pending-card
프로토콜)이 아니라, 훨씬 단순한 한 경로로만 된다:**

> **모델이 카드를 자기 출력으로 한 번 찍고 계속 일한다 → 사용자가 답을 타이핑하면
> 다음 턴 입력으로 큐잉된다 → 모델이 자기가 찍은 카드와 그 답을 대조해 기존
> 도구로 기록한다.** MCP 서버는 카드를 그리지 않는다. 새 호스트 기능 0, 새 훅 0.

## 기술 근거 (문서 확인, 추정 아님)

### Claude Code — ✅ 된다 (queued input)
- 스트리밍 입력이 기본. **"Queued Messages: 여러 메시지를 보내면 순차 처리, interrupt
  가능."** 작업 중 타이핑한 답은 큐에 쌓여 **다음 턴에** 처리된다(턴 중간 주입 아님).
  → 카드는 작업 중에 보이고, 모델은 자기 턴이 끝난 뒤 그 답을 받아 기록한다. 포착엔
  이 타이밍으로 충분하다. (근거: agent-sdk/streaming-vs-single-mode)
- `Esc`는 턴을 **끊는다** → 차단이므로 안 쓴다. 큐잉(그냥 타이핑 후 Enter)이 비차단 경로.
- 긴 작업을 백그라운드(Ctrl+B/Bash background)로 돌리면 세션이 계속 응답 가능 → 카드+답이
  더 자연스러움.
- `/btw`는 부적합(도구 없음·기록 안 됨·단발). 설계 문서 판단과 일치.

### Codex — ⚠️ 훅 경로는 죽음, 모델-출력 경로만 살아있음
- 훅: SessionStart·PreToolUse·PostToolUse·UserPromptSubmit·Stop 등. 그러나
  **command-only + 동기, async 미지원, `prompt`/`agent` 핸들러는 건너뜀.**
- **플러그인·MCP는 네이티브 선택 카드 UI를 그릴 수 없다. 턴 중 상호작용 입력 포착 메커니즘
  없음.** (근거: learn.chatgpt.com/docs/hooks)
- 따라서 "훅으로 카드"는 불가. 살아있는 건 CC와 같은 경로 — 모델이 카드를 출력하고,
  사용자 steering 메시지를 다음 입력으로 받는 것. Codex의 steering 수용 타이밍은 실세션
  확인 대상(아래).

### 함의
- **pending-card ↔ answer-routing 프로토콜을 지을 필요가 없다.** 대조는 모델이 자기
  대화 이력(자기 카드 + 사용자 답)을 읽는 것으로 끝난다. 이건 이미 스파인이 유도하는 행동.
- Argus가 추가로 지을 배관: 없음. 필요한 건 (a) 스파인이 "긴 작업 중 값진 빈칸 하나면
  카드 한 장" 유도(대부분 있음), (b) 모델이 다음 턴에 답을 기존 도구로 기록.

## 남은 절반 — 체감 (실세션에서만 정직하게 측정됨)

기술이 된다 ≠ 사용자가 답한다. 헤드리스로는 "됐다"고 거짓 보고하게 되므로 여기서 멈추고,
아래를 **사람이 실제 Claude Code 세션에서** 돌린다.

### 가짜 카드 실행법 (5분, 저장 안 함)
1. 실제로 30초+ 걸리는 코딩 작업을 Claude에게 시킨다(리팩터·테스트 스위트·빌드 등).
2. 세션에 이 지시를 한 번 붙인다(임시, 저장 로직 없음 — 순수 체감 측정용):

   > 이번 세션 동안: 30초+ 걸릴 작업을 시작하면, 작업을 멈추지 말고 아래 카드를
   > **딱 한 번** 출력한 뒤 하던 일을 계속하라. 아무것도 기록하지 마라.
   >
   > ```
   > Argus · 선택(답 안 해도 작업은 계속됩니다)
   > 방금 이 방향을 잡을 때, 깨지면 안 되는 전제는 어느 쪽에 가깝나요?
   >   1. <현재 작업 맥락의 구체 문장 A>
   >   2. <현재 작업 맥락의 구체 문장 B>
   > 번호만 보내거나 한 줄로 고쳐 써도 됩니다.
   > ```
3. 작업이 도는 동안 `1`/`2`/한 줄 수정/무시 중 하나를 해본다.

### 측정 (세션당 기록)
- 카드가 **좋은 순간**(방향이 막 잡힌 직후)에 떴나, 뜬금없었나?
- 답을 **했나**(큐잉이 제대로 됐나), 무시했나?
- 방해감: 흐름이 끊겼나, 곁다리로 느껴졌나?
- 타이밍: 답이 다음 턴에 도착하는 게 어색했나?
- 20회 중 답변율 몇 %?

### Go / No-Go
- **Go**: 방해 0 + 답변율이 쓸 만함 → 스파인에 "긴 작업 중 카드 한 장" 정식 유도 추가.
- **No-Go**: 방해되거나 답 거의 안 함 → 카드는 접고, 같은 질문을 **우리 땅**(봉인 직전·
  세션 종료 직후)으로만 낸다. 어느 쪽이든 포착 자체는 살아있다(연결은 이미 우리 땅에서 작동).

## 한 줄 요약

땅은 있다(큐잉). 배관은 지을 게 없다(모델 출력이면 끝). 남은 건 "사람이 실제로 답하냐" —
그건 위 5분 프로토콜로 실세션에서만 정직하게 나온다.
