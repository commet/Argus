## E5. ★ 그 예측의 첫 실사용 표본이 오늘 나왔고, 빗나가는 쪽을 가리킵니다 `[공개가능]`

이번 세션 시작 시 훅이 실제로 울린 원문입니다.

```
════════════════════════════════════════════════════════════
  하중 가정 위반 — 진행 전에 이것부터 처리한다
════════════════════════════════════════════════════════════
위반 · S2-최신-위에-짓고-있는가
     가정: 현재 브랜치는 원격보다 뒤처지지 않았다.
     검사: branch_synced → 확인 불가 — Command failed: git fetch origin claude/evidence-md-ph
     귀환: fetch·merge 후 시작한다.

위반 · S3-한-PR-한-존인가
     가정: 현재 브랜치의 변경은 한 라이선스 존에만 머문다.
     검사: zone_purity → 한 PR이 두 존을 건드림: MIT + app
     귀환: PR을 존별로 쪼갠다.
```

**둘 다 위양성입니다.** 직접 열어 확인한 원인:

1. `S3` — `zone_purity`는 `git diff --name-only origin/main...HEAD`를 돌리는데
   (`argus-agent.mjs:110-122`), **`origin/main`을 먼저 fetch하지 않습니다.**
   이 컨테이너의 `origin/main`은 `ae5a018`로 낡아 있었고, 그래서 이미 머지된
   커밋 3개의 파일 198개가 "이 PR의 변경"으로 집계됐습니다.
   `git fetch origin main` 한 줄을 돌린 뒤 재검사한 결과:

   ```
   유지 · S3-한-PR-한-존인가
        검사: zone_purity → 존 docs만 · 파일 0건
   ```

   같은 파일 안에서 `branch_synced`는 fetch를 하고 `zone_purity`는 하지 않습니다.

2. `S2` — `branch_synced`의 catch 블록이 **모든 예외를 `holds:false`로**
   돌립니다(`argus-agent.mjs:136-138`). 원격에 아직 없는 새 브랜치는
   `git fetch`가 실패하고, 그래서 "확인 불가"가 "위반"으로 출력됩니다.
   출력 문자열 자체가 "확인 불가"라고 말하는데 판정은 위반입니다.

값어치: E4의 봉인이 요구한 "적중 대 위양성의 비"의 첫 실표본이 **적중 0,
위양성 2**입니다. 발표 시점 기준으로 가장 최신이고, 화면에서 두 줄 명령으로
재현됩니다. 그리고 이 리시트 자신이 미리 적어둔 문장이 그대로 맞았습니다.

> 시끄러운 실패 장치가 시끄럽게 틀리면 사람이 장치를 끈다. 위양성률은 이
> 원형의 생존 조건이지 부수적 품질이 아니다.
