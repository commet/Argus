# storyline.md — 구성안 (Phase 2)

> **정산 기록 (2026-08-22).** 이 문서는 13분 · 13장 · 8비트 기준으로 쓰였다.
> 실제로 배포된 덱은 **15분 · 20장 · 4막**이다. 어긋난 부분과 그 이유를 문서
> 끝의 「6. 구성안과 배포본의 차이」에 적었다. 아래 본문은 **당시 판단의
> 기록으로 남긴다.** 결과를 본 뒤에 원문을 고치면 그게 이 발표가 말하는
> 저자 교체다.

대상 발표: "AI가 아니라 사람을 검증하는 하네스", 13분 + Q&A, 슬라이드와 구두,
라이브 데모 없음. 근거 재료는 [`evidence.md`](./evidence.md)이고 항목 번호는
거기 색인을 따릅니다.

## 0. 축 판정 — 부록 A의 가설을 어떻게 다뤘나

가설 원문은 "신호라고 생각했던 것들이 대부분 내 목소리의 반향이었다. 하네스는
반향과 신호를 구분하는 장치다"였습니다.

**뒷받침하는 증거는 넷입니다.**

| 증거 | 무엇 |
|---|---|
| E6 | 창업자 지시문의 하중 개념구 16개 중 16개가 AI 최초 발화 |
| E7 | 22시간 뒤 회고에서 "우리가 하기로 했던"으로 저자성이 병합 |
| E10 | 페르소나 10명의 예측이 무페르소나 기준선과 사실상 동일 |
| U2 | 자동 브리프가 16일째 전날 브리프를 요약 |

가설은 삽니다. 그런데 발굴의 무게중심은 한 칸 뒤에 있습니다. 반향을 잡으려고
지은 장치들이 **스스로 조용히 틀렸고, 전부 자기 검사를 통과했습니다.**

| 증거 | 무엇 |
|---|---|
| U1 | 전제 센서가 봉인된 날부터 남의 npm 패키지를 보며 "유지"를 냄 |
| E5 | 오늘 훅이 울린 위반 2건이 둘 다 위양성 |
| E22 | 계측기가 자기 맹점의 원인을 정상 동작으로 15바퀴 기록 |
| E25 | 기계가 검사하지 않는 규약의 준수율 90퍼센트, 위반 6건 전부 CI 통과 |
| U3 | 사람이 손으로 돌리던 증거 원장이 3주 만에 멈춤 |

**그래서 축을 이렇게 놓습니다.** 반향은 문제 진술로 앞에 두고, 장치의 실패를
두 번째 반전으로 뒤에 둡니다. 두 층이 한 문장으로 이어집니다.

> 판단을 검증할 장치를 지었더니, 그 장치도 같은 병에 걸려 있었고, 그것을
> 알아낸 것은 장치 밖에서 들여다본 일이었습니다.

이 축이 부록 A보다 나은 이유 셋입니다. 첫째, 증거가 아홉 건으로 두 배입니다.
둘째, 반전이 두 번 생깁니다(부록 C 자기검증 1번의 요구). 셋째, 청중이
AI-native라서 "AI가 내 말을 따라 한다"는 첫 층은 이미 아는 이야기입니다.
두 번째 층이 그들이 모르는 부분입니다.

## 1. 비트 구성

총 13분. 슬라이드 13장. 시간은 목표치이고 합이 12분 40초라 20초 여유를 둡니다.

### 비트 1 · 오프닝 (0:00 – 0:55) · 슬라이드 1

**목적**: 일반론 없이 구체물로 연다. 제목이 약속한 물건을 첫 화면에 올린다.

**증거**: E5 (오늘 세션 시작 시 훅 출력 원문)

**화면**: 훅 배너 전문. 박스 드로잉 문자 그대로.

```
════════════════════════════════════════════════════════════
  하중 가정 위반 — 진행 전에 이것부터 처리한다
════════════════════════════════════════════════════════════
위반 · S2-최신-위에-짓고-있는가
     검사: branch_synced → 확인 불가 — Command failed: git fetch origin …
위반 · S3-한-PR-한-존인가
     검사: zone_purity → 한 PR이 두 존을 건드림: MIT + app
```

**구두 요지**: 오늘 아침 작업을 시작했더니 제가 만든 장치가 저를 멈춰
세웠습니다. 위반 두 건입니다. 그리고 두 건 다 틀렸습니다. 오늘은 이 장치를
왜 만들었는지, 그리고 왜 틀렸는지를 말씀드리려고 합니다.

여기서 좌표를 한 문장으로 정리합니다. 지난 시즌에 나온 하네스는 AI의 완료
주장을 못 믿어서 만든 것이었고, 오늘 것은 검증 대상이 사람 쪽입니다.

**→ 전환 문장**: "이 장치를 만들게 된 자리는 코드가 아니라 제 전 직장이었습니다."

### 비트 2 · 결핍 (0:55 – 2:40) · 슬라이드 2–3

**목적**: 전략기획 출신 배경을 우월감이 아니라 결핍으로 배치한다. 개발자
청중 앞에서 "판단이 결과물인데 채점이 오지 않는 직군"으로 자기를 놓는다.

**증거**: E12, U3

**슬라이드 2** — 증거 원장 화면 캡처. 회사명만 가림. L1~L5 등급, 등급 근거,
후속 검증 큐가 보이게. 캡션 없이 화면만.

**구두 요지**: 코드에는 테스트가 있는데 제가 하던 일에는 없었습니다. 그래서
직접 만들었습니다. 물류 대기업 AX 프로젝트에서 관찰마다 L1에서 L5까지 등급을
매기고, 등급 근거를 적고, 단일 증언은 검증 큐에 넣는 원장입니다. 1,200줄까지
갔습니다.

**슬라이드 3** — 같은 파일의 다음 장면. 두 줄만 크게.

```
## 2026-06 (Month 2)
<!-- 비어 있음 -->

## 2026-07 (Month 3)
<!-- 비어 있음 -->
```

**구두 요지**: 3개월짜리 프로젝트였고, 원장은 3주 채워졌습니다. 검증 큐에
남은 11건은 지금도 미검증입니다. 그중 하나가 이겁니다. 킥오프에서 누가
"내부적으로도 하네스 엔지니어링 진행 중"이라고 했는데, 무슨 뜻인지 몰라서
확인 큐에 넣어뒀고 석 달째 그대로입니다. 오늘 이 자리 제목이 하네스인데,
제 원장에서 그 단어는 아직 근거로 못 쓰는 칸에 앉아 있습니다.

**→ 전환 문장**: "사람이 손으로 돌리는 하네스는 3주를 못 갑니다. 그래서 기계에
넘겼고, 넘기고 나서 먼저 확인한 것은 채점을 AI에게 맡길 수 있느냐였습니다."

### 비트 3 · 첫 번째 반전, 반향의 실측 (2:40 – 5:00) · 슬라이드 4–5

**목적**: "AI에게 채점을 시키면 된다"는 기대를 숫자로 꺾는다. 청중이
예상하는 결론(AI가 내 사고를 도왔다)의 반대편을 실측으로 보여준다.

**증거**: E6, E7, E10

**슬라이드 4** — 계단식 축소 네 줄. 위에서 아래로 애니메이션 없이 한 화면에.

```
통제 전(전체 용어 928개)          AI 최초 681/928  (73.4%)
대화 중 신조어로 좁히면              58/105  (55.2%)
창업자가 2회 이상 반복한 것만          13/47   (27.7%)
손으로 안 고르고 규칙만으로            35/355  ( 9.9%)
────────────────────────────────────────────────
내 지시문의 하중 개념구             16/16   (100.0%)
```

**구두 요지**: 6일치 대화 1,241턴을 재봤습니다. 제 발화 92턴, AI 1,149턴입니다.
처음 숫자는 73퍼센트였는데 교란을 걷어내니 9.9퍼센트까지 내려갔습니다. AI가
말을 12배 많이 하니까 흔한 말은 물량으로 AI가 먼저 합니다. 그런데 제가
지시문에서 실제로 하중을 걸어 쓴 개념구 16개만 따로 세면 16개 전부 AI가 먼저
꺼낸 말이었습니다. 제 지시문 다섯 개는 제 단어가 하나도 없습니다.

**슬라이드 5** — 회고와 원문 대조. 두 줄만.

```
당시 08-10T09:38   "계획도 한번 세워보자. 1,2층위도 아주 좋고…"
회고 08-11T04:08   "우리가 시뮬레이션 돌리기로 했던 층위 1,2,3…"
                                        ↑ 22시간
```

**구두 요지**: "아주 좋고"는 남의 안을 평가하는 말입니다. 22시간 뒤에는 우리가
됩니다. 방향과 내용은 그대로고 저자만 합쳐졌습니다. 같은 로그 다음 날 제가
이렇게 씁니다. "우리가 이 제품에서 테스트해봐야하는 핵심이 그거였나. 조금
당황스러워." 이건 기억이 왜곡된 기록이 아니라, 왜곡을 본인이 발견한 기록입니다.
차이는 하나입니다. 원문이 남아 있었습니다.

**→ 전환 문장**: "채점을 AI에게 맡길 수 없다면 남는 심판은 현실뿐입니다.
그래서 현실이 답할 수 있는 형태로 미리 적어두는 장치를 지었습니다."

### 비트 4 · 지은 것 (5:00 – 7:10) · 슬라이드 6–8

**목적**: 산출물로 회의감을 뚫는다. 프롬프트 한 덩어리가 아니라는 것을
스키마와 종료 코드와 원장으로 보인다.

**증거**: E26, E24, E1, E27

**슬라이드 6** — 봉인 스키마 4필드. 코드 그대로.

```ts
required: ['decision', 'predicate', 'falsified_if', 'check_by_days']
```

옆에 설계 이유 두 줄. 모델은 "오늘 더하기 2주"를 못 믿으므로 날짜 수만 받고
날짜는 호출자가 실제 시계로 만듭니다. predicate와 falsified_if는 내부 이름이고
사용자에게는 "잘 됐다는 신호"로 나갑니다.

**슬라이드 7** — 가정 파일과 종료 코드. 이 슬라이드가 회의감을 뚫는 자리입니다.

```json
"id": "S1-업로드된-정본을-읽었는가",
"why_load_bearing": "틀리면 전 작업이 원본과 어긋난 채 그럴듯하게 완주한다.
                     결과물이 멀쩡해 보이므로 어떤 테스트도 울리지 않는다.",
"check": { "type": "uploads_referenced", … }
```

```js
console.error(`거부: "${a.id}" — 검사 불가능한 가정은 봉인이 아니라 메모다`);
process.exit(2);
```

**구두 요지**: 규칙 하나가 나머지를 다 정했습니다. 가정은 기계가 읽는 술어여야
합니다. 산문 가정은 검사가 안 되고, 검사가 안 되는 가정은 봉인이 아니라
메모입니다. 그래서 check가 없는 가정은 봉인 자체를 거부합니다. 종료 코드 2로
죽습니다.

**슬라이드 8** — 정산 화면 원문. 빗나간 것으로 고릅니다.

```
argus_resolve outcome=missed broken_premise_ref=P1

→ 실제 결과를 기록했습니다: 예측이 빗나갔다. 평가는 없습니다.
  봉인 때 남긴 확신도: '확신함'.
  이 판단을 내린 사람: 나 (모델 아님)
  AI VERDICT ON THIS DECISION ······················  NONE
```

사용자가 창에 직접 타이핑한 규칙 한 줄을 아래에 붙입니다.

> "원인부터 세고 나서 옮긴다. 짜증나는 걸 원인으로 착각했다."

**구두 요지**: 예측 원장은 지금 적중 4, 빗나감 3, 미결 2입니다. 빗나간 것을
안 지우는 게 이 물건의 전부입니다. 그리고 채점 대상은 사람이 아니라 예측입니다.
"당신은 판단력이 B+입니다" 같은 문장은 이 제품에 없습니다.

**→ 전환 문장**: "여기까지가 잘 된 이야기이고, 이제부터가 오늘 진짜 하려던
이야기입니다."

### 비트 5 · 두 번째 반전, 장치들이 조용히 틀렸다 (7:10 – 9:50) · 슬라이드 9–10

**목적**: 발표의 최고점. 검증 장치 셋이 각각 다른 방식으로 틀렸고, 전부
초록이었다는 것을 연속으로 보인다.

**증거**: U1, E22, U2

**슬라이드 9** — U1. 두 명령의 출력을 나란히.

```
$ npm view argus-decision-mcp version        ← 우리가 발행하는 것
2.0.23

$ npm view argus-mcp description             ← 센서가 보고 있던 것
'MCP server for browser automation - gives AI coding agents
 the ability to see and interact with web pages'
  repository: github.com/adesmet/browser-mcp
```

아래에 센서 판독 원문 한 줄.

```
유지 · P1-발행본이-설치-가능하다      npm_version = 1.2.0 ≥ baseline 1.2.0
```

**구두 요지**: 전제를 외부 신호에 묶어두는 센서를 만들었습니다. 첫 전제가
"우리 패키지가 레지스트리에 살아 있다"입니다. 센서는 봉인된 날부터 오늘까지
계속 유지를 냈습니다. 그런데 보고 있던 건 이름이 비슷한 남의 브라우저 자동화
서버였습니다. 우리 패키지가 통째로 내려갔어도 이 센서는 유지라고 말했을
겁니다. 그리고 같은 센서 문서 첫 절에 제가 이렇게 써놨습니다. "조용히 메우는
순간 이 장치는 자신이 감시하려던 실패의 사례가 된다."

**슬라이드 10** — 나머지 둘을 한 화면에 위아래로.

위: 계측기에 시계가 없었다.

```
진단 (11차, 08-15)  "문맥 손잡이는 동사 선택은 못 바꾼다"   ← 모델 탓
사실 (08-18)        확인일이 온 적이 없다                  ← 시계 탓
                    15바퀴 · 부품은 처음부터 서랍에 있었다
```

아래: 자동 브리프.

```
2026-08-21 브리프 전문
  "어제 commit은 자동 생성 brief 파일 1건뿐이며, 콘텐츠 변경 없음.
   해당 brief 내용: '어제 commit은 자동 생성 brief 파일 1건뿐이며…'"
                                              16일 연속
  실제 개발은 07-21에 옆 저장소로 이사. 그 뒤 537 커밋.
```

**구두 요지**: 두 번째는 계측기가 자기 맹점의 원인을 정상 동작으로 기록해둔
경우입니다. 15바퀴 동안 특정 호출이 0회였고 우리는 그걸 모델의 성향으로
적었습니다. 확인일이 온 적이 없어서였습니다. 시간을 옮기는 부품은 처음부터
있었고 그 하네스만 안 썼습니다. 세 번째는 매일 아침 오는 자동 브리프입니다.
16일째 전날 브리프를 요약하고 있습니다. 개발이 한 달 전에 옆 저장소로
옮겨갔는데 브리프 봇은 안 따라갔습니다. 저는 그 브리프를 매일 받았습니다.

**→ 전환 문장**: "셋의 공통점이 하나 있습니다. 전부 자기 검사를 통과했습니다."

## 3. Q&A 예상 질문 다섯

본문에 미리 다 방어해 넣지 않았습니다. 선제 배치한 것은 아래 표시한 둘뿐입니다.

### Q1. 이거 결국 사전등록 아닌가요. 새로운 게 뭡니까

**답변 요지**: 맞습니다. 새로운 건 사전등록이 아니라 **집행 지점**입니다.
사전등록은 사람이 하고, 사람은 3주 만에 멈춥니다(U3, 실측). 여기서 옮긴 건
그 행위를 세션 시작 훅으로 내려서 사람의 성실성에서 떼어낸 것입니다. 그리고
검사 불가능한 가정은 봉인 자체를 거부합니다. 사전등록 문화에는 그 거절이
없습니다.

### Q2. 훅이 위양성을 내면 사람이 끄지 않습니까

**★ 본문에 선제 배치했습니다** (비트 7 규칙 3, 비트 8 봉인문).

**이유**: 이 질문은 반드시 나오고, 방어하지 않고 두면 발표 전체가 순진해
보입니다. 그런데 답이 이미 재료 안에 있습니다. 이 위험은 장치를 만들 때
봉인문으로 미리 적어뒀고, 지금 첫 표본이 그 봉인문이 빗나가는 쪽을 가리킵니다.
방어가 아니라 클로징의 재료가 되므로 본문에 넣는 편이 이득입니다.

### Q3. 표본이 너무 작지 않나요. 사용자 두 명이라면서요

**★ 본문에 선제 배치했습니다** (비트 6 오른쪽 열).

**이유**: 부록 C가 요구한 정직성 기준이고, 5절 채택 기준의 "표본이 적으면
적다고 먼저 말하는 편이 훨씬 강하다"에 정확히 해당합니다. 질문받고 인정하는
것과 먼저 말하는 것은 신뢰에서 차이가 큽니다.

### Q4. 대기업 현장에 실제로 꽂아보니 어땠습니까. FDE 하려면 뭐가 필요한가요

**답변 요지**: 이 방에서 가장 희소한 자산이므로 시간을 써도 됩니다. 구체물로
답합니다. 첫째, 게이트를 사람이 아니라 테스트에 맡겨야 했던 이유. 용어 분열을
전수 조사했더니 같은 제품명이 로마자 105번, 한글 19번이었고 한 카드 안에서
제목과 본문이 갈렸습니다(E13). 사람이 매번 볼 수 없으니 테스트가 지킵니다.
둘째, 인용문은 검사 대상에서 뺐습니다. 사람이 한 말을 문체 교정하면 근거가
아니라 각색이 됩니다. 셋째, 마스킹 대조표를 저장소 밖으로 뺐더니 검사가 못
도는 환경이 생겼고, 그때 통과가 아니라 건너뜀으로 표시하게 만들었습니다(E30).
현장에서 가장 자주 깨지는 건 모델이 아니라 이런 경계입니다.

**주의**: 고객사명, 실명, 실제 제품명은 말하지 않습니다. U9(마스킹 사고)는
답변에도 쓰지 않습니다.

### Q5. AI가 반박을 안 해준다면, 반박하도록 프롬프트를 짜면 되지 않나요

**답변 요지**: 그 시도의 결과가 재료에 있습니다. 결과를 아는 우리 결정 3건을
숨기고 페르소나 10명에게 예측시켰더니 방향 적중이 10/30이었고, 페르소나를
아예 뺀 기준선 15표본이 사실상 같았습니다(E10). 말투 축은 판단을 거의 못
움직입니다. 확신도 분포도 양극단에만 몰려 있고 중간 구간이 0건이었습니다(E11).
프레임 안에서 모델과 토론해서 검증되는 결론은 없다는 게 지금 제 위치이고,
그래서 검증을 정산 시점의 현실로 밀어냈습니다.

## 4. 자기 검증 (부록 C 다섯 문항)

### 1. 예상을 꺾는 지점이 최소 2회 있는가. 각각 몇 분 지점인가

**두 번 있습니다.**

- **첫 번째, 4분 지점** (비트 3). 청중은 "AI가 사고를 도왔다"를 예상합니다.
  숫자는 하중 개념구 16개 전부가 AI 발화였다고 말합니다. 그리고 같은 측정이
  자기 헤드라인을 73퍼센트에서 9.9퍼센트로 깎습니다. 꺾이는 방향이 두 번입니다.
- **두 번째, 7분 10초 지점** (비트 5). 비트 4에서 "잘 지었다"를 6분 넘게 쌓은
  직후에 그 장치들이 조용히 틀렸다는 것으로 들어갑니다. 전환 문장이
  "여기까지가 잘 된 이야기이고"라 예고 없이 방향이 바뀝니다.

보조로 2분 40초 지점(원장이 3주 만에 멈췄다)이 있으나, 이건 반전이라기보다
결핍 배치입니다.

### 2. 가장 평평한 구간은 어디인가. 무엇으로 메울 것인가

**비트 4 후반, 6분에서 7분 사이입니다.** 슬라이드 7과 8이 둘 다 "잘 지은 것"의
전시라 같은 톤이 1분 이상 이어집니다. 청중의 기본 회의감이 가장 살아나는
구간이기도 합니다.

**메우는 방법 둘.**

1. 슬라이드 7에서 종료 코드 2를 말할 때 한 박자 세웁니다. "검사할 수 없는
   가정은 봉인이 아니라 메모다"는 이 발표에서 가장 옮기기 쉬운 문장이고,
   구두로 강조하면 그 자리가 평평하지 않게 됩니다.
2. 슬라이드 8을 적중이 아니라 **빗나간** 정산으로 고정합니다. 이미 그렇게
   잡았습니다. "AI VERDICT ON THIS DECISION ... NONE" 한 줄이 시각적으로
   튀므로 톤이 바뀝니다.

그래도 늘어지면 슬라이드 7을 버리고 6과 8만 갑니다. 45초가 회수됩니다.

### 3. 실물 증거로 뒷받침되지 않는 슬라이드는 어느 것인가

**전부 뒷받침됩니다.** 13장 중 12장이 파일, 커밋, 명령 출력의 원문입니다.
다만 두 가지를 표시합니다.

- **슬라이드 12(오늘 밤 최소 버전)는 원문이 아니라 요약입니다.** 규칙 셋은
  각각 E30, U1, E17에서 나왔지만 이 슬라이드 자체는 제가 만든 정리입니다.
  발표에서 "이건 제가 정리한 겁니다"라고 말하는 편이 낫습니다.
- **슬라이드 5의 "조금 당황스러워" 인용은 측정 파일에 담긴 재인용입니다.**
  원 대화 로그 실물은 이 컨테이너에 없습니다(evidence.md 9.2). 발표 전에
  로컬에서 원문을 확인해 두시는 것을 권합니다. 확인이 안 되면 슬라이드에
  "측정 기록에 인용된 형태"라고 작게 붙입니다.

### 4. 발표 전체를 한 문장으로 옮기면 무엇인가. 제목과 일치하는가

**한 문장**: 판단을 검증하려고 장치를 지었더니 그 장치도 조용히 틀려 있었고,
틀렸다는 사실은 장치 밖에서 들여다봤을 때만 드러났습니다.

**제목과의 일치**: 절반 일치합니다. 제목 "AI가 아니라 사람을 검증하는 하네스"는
검증 대상이 사람이라는 좌표를 잡아주고 비트 1에서 3까지가 그 약속을 지킵니다.
그런데 발표의 무게중심인 비트 5는 검증 대상이 **장치 자신**입니다.

**판단**: 제목은 바꾸지 않습니다. 이미 사전 예고가 나갔고, 제목이 잡아주는
좌표(지난 시즌 하네스와의 구분)가 여전히 필요합니다. 대신 비트 1의 좌표 정리
문장 뒤에 반 문장을 덧붙여 봉합합니다. "사람을 검증하는 장치를 만들었고,
오늘은 그 장치를 검증한 이야기를 하겠습니다." 이러면 제목이 발표의 전반부를
가리키고 후반부가 그것을 한 겹 더 감싼다는 게 처음부터 예고됩니다.

### 5. 청중이 다음 날 기억할 장면 하나를 꼽으면 무엇인가

**두 명령의 출력이 나란히 놓인 슬라이드 9입니다.**

```
$ npm view argus-decision-mcp version     2.0.23
$ npm view argus-mcp description          'MCP server for browser automation…'
```

이유 셋입니다. 첫째, 재현이 가장 쉽습니다. 청중이 자기 자리에서 두 줄 쳐볼 수
있고, 자기 센서도 같은지 확인해보고 싶어집니다. 둘째, 발표자에게 불리합니다.
셋째, 옮길 때 한 문장이 됩니다. "그 사람 3개월 동안 남의 패키지 보고 있었대."

경쟁 후보는 슬라이드 3의 `<!-- 비어 있음 -->` 두 줄인데, 이건 옮길 때
"의지박약" 이야기로 납작해질 위험이 있습니다. 슬라이드 9는 납작해져도 논지가
남습니다.

## 6. 구성안과 배포본의 차이 (2026-08-22 정산)

### 왜 8비트가 4막 20장이 됐나

세 가지가 이 문서 이후에 정해졌다.

1. **분량이 13분에서 15분으로 늘었다.** 사양 v2 기준.
2. **창업자가 이론 배경을 독립 장으로 요구했다.** 원래 비트 4 안에 눌러
   담았던 것을 넷으로 폈다 — 오디세이, 세 학문, 게임이론의 순·역방향,
   그리고 가지 않은 길.
3. **제목 규약이 바뀌었다.** 비트 제목은 발표자의 소회였고
   ("첫 번째 반전", "남는 것"), 배포본은 명사구 주장문이다. 제목만 순서대로
   읽어 논지가 서는지가 유일한 시험이 됐다.

### 비트 → 장 대응

| 이 문서의 비트 | 배포본의 장 | 비고 |
|---|---|---|
| 1 오프닝 | 1 세 문제의 공통 원인 | 앵커 숫자 셋을 표로 명시 |
| 2 결핍 | 2 화물 · 3 채점 원장 · 4 판단 0건 · 5 조용한 중단 | 화물 대비를 셋으로 폄. 4장이 이 덱의 엔진 |
| 3 반향의 실측 | 6 기억의 재구성 · 7 공저자 | 그대로 |
| 4 지은 것 | 8 오디세이 · 9 세 학문 · 10 순·역방향 · 11 봉인 네 칸 · 12 거부 · 13 정산 | 이론 넷이 여기서 갈라져 나왔다 |
| — (없었음) | 14 기각된 대안의 재생 | **신설.** 이 문서에 없던 장 |
| 5 장치들이 조용히 틀렸다 | 15 검사기 자체의 사각지대 | 그대로 |
| 6 남는 것 | 16 남은 한계와 대응 | **성격이 바뀌었다.** 한계가 한 건뿐이던 것을 표로 셋 |
| 7 오늘 밤 최소 버전 | 17 시작에 필요한 세 줄 | 그대로 |
| 8 클로징 | 18 이 발표의 봉인된 예측 | 그대로 |

### 이 문서가 틀렸던 것 하나

**「가지 않은 길」을 다루지 않았다.** 그래서 덱 초안에서 그것을 "채점 불가"
라는 한계로 잘못 배치했다가 창업자 지적으로 되돌렸다. 기각된 대안을 원장에
남기고 분신이 그 경로의 추론을 재생하는 것은 이 시스템의 **능력**이고,
`grade_label: fiction` 은 못 한다는 표시가 아니라 재생을 정직하게 유지하는
장치다. 구성안 단계에서 이 개념을 빠뜨린 것이 배치 오류의 원인이었다.

### 시간 배분 (배포본, 합계 900초)

각 장의 발표자 노트 첫 줄에 박아 두었다.

```
표지 20 · 목차 30
문제  60 · 80 · 40 · 30 · 60
진단  70 · 70
해법  40 · 50 · 50 · 50 · 40 · 50 · 40
한계  40 · 35 · 25 · 20
```

리허설에서 넘치면 **3장(채점 원장)** 을 먼저 접는다. 2장이 이미 화물 쪽 루프를
보여주므로 빼도 4장의 `0건` 대비가 그대로 선다.
