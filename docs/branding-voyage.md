# Argus 브랜딩: Voyage (오디세우스의 항해)

> **이 문서가 단일 소스다.** `branding-orchestra-metaphor.md`, `branding-orchestra-final.md`,
> `branding-metaphor-deep-research.md` 는 모두 폐기. 오케스트라 메타포는 끝났다.
>
> 이전 문서들의 핵심 결함: **스킨이 기능을 가렸다.** 왜 adversarial이 트럼펫인지 아무도 모른다.
> `branding-orchestra-final.md` 자신이 "메타포를 학습해야 제품을 쓸 수 있으면 메타포는 실패한 것"이라고
> 적어놓고는, 악기 매핑(🎺=반론, 🎻=분석)이라는 학습 부담을 강제했다. 자기모순.
>
> **Voyage는 반대다.** 역할이 이름에 그대로 드러난다 — Scout=정찰=리서치, Watch=망루=리스크,
> Cartographer=제도=전략, Navigator=항해장=종합. 학습할 메타포가 없다. 단어가 곧 기능이다.

## 1. 신화적 골격 (하나의 세계)

오케스트라는 골격 밖의 이물질이었다. Voyage는 이미 존재하던 그리스 신화 골격에 합류한다:

| 요소 | 의미 | 제품에서의 위치 |
|---|---|---|
| **Argus** (백 개의 눈) | 모든 것을 보는 감시자 | 제품 이름. 에이전트가 행동하기 전에 "본다" |
| **오디세우스의 항해** | 결정의 여정 | 4R 파이프라인 = 한 번의 항해 |
| **이타카 (Ithaca)** | 목적지 | 내려진 결정 / 제출 가능한 산출물 |
| **세이렌 (Sirens)** | 매혹적이지만 그릇된 노래 | AI의 그럴듯한 한방 답변 |
| **돛대-밧줄 (the mast & rope)** | 듣되 뛰어들지 않는 구조 | **"Decision harness for AI"** — 포지셔닝 그 자체 |

`docs/essay-draft-siren-and-harness.md` 가 이 골격의 서사적 원천이다.

## 2. 역할 매핑 (사람 + 시스템)

| 오케스트라 (폐기) | Voyage (확정) | 영문 | 기능 |
|---|---|---|---|
| 지휘자 Conductor | **선장** | Captain | = 사용자. 직접 노 젓지 않고 항로를 판단·결정 |
| 연주자 Players | **선원** | Crew | = 페르소나 / 에이전트 |
| 악장 Concertmaster | **항해장** | Navigator | 모든 선원의 목소리를 종합해 선장에게. 코칭 = 항로 조언 |
| 앙상블 Ensemble | **선원 편성** | Crew | 결정 복잡도에 맞춘 선원 구성 |

**핵심: `concertmaster` → `navigator` 는 코드 식별자/타입/함수/i18n 키까지 전부 통일.**
voyage-crew.ts 의 종합 division 도, concertmaster.ts 의 코칭 엔진도 모두 Navigator/항해장 하나로.

## 3. 선원 5개 부서 (에이전트 팀 — voyage-crew.ts 확정)

| 부서 | 영문 | 자리 | 기능 |
|---|---|---|---|
| 탐색조 | Scouts | 선수 난간 | 먼저 나가 낯선 해역 정보를 가져온다 (리서치) |
| 제도사 | Cartographers | 해도 테이블 | 해도를 그리고 항로를 정한다 (전략) |
| 장인들 | Artisans | 메인 갑판 | 손기술로 항해의 실물을 만든다 (실무: 카피·재무·마케팅·기술·PM) |
| 망루 | The Watch | 까마귀 둥지 | 수평선 너머 위험을 먼저 본다 (리스크·법무·UX) |
| 항해장 | Navigator | 조타륜 옆 | 모든 목소리를 하나로 묶어 선장에게 (종합) |

## 4. persona_function = 항해 렌즈 (리허설 분류)

리허설 페르소나의 기능적 분류. 악기 스킨(Brass/Strings/...) 폐기. **선원 부서와 같은 archetype 공유** —
세계관이 하나로 닫힌다. 도전하는 페르소나 = 망루처럼 보는 사람.

| persona_function | 항해 렌즈 | 아이콘 | 한 줄 (사용자가 보는 것) |
|---|---|---|---|
| adversarial | **망루** Watch | 🔭 | "위험을 먼저 봅니다 / 반론합니다" |
| analytical | **제도사** Cartographer | 🗺️ | "측정하고 검증합니다" |
| empathetic | **탐색조** Scout | ⛵ | "직접 나가 사람의 관점을 봅니다" |
| integrative | **항해장** Navigator | 🧭 | "전체를 종합해 항로를 정합니다" |

원칙: 같은 function + 같은 세부 역할 → 항상 같은 아이콘 (학습·애착의 일관성).

## 5. 선원 규모 (결정 복잡도 기반)

| 규모 | 인원 | 이름 | 적합한 결정 |
|---|---|---|---|

## 6. 4R = 항해의 단계 (이중 라벨)

4R 스킬 이름(Reframe/Recast/Rehearse/Refine)은 브랜드 자산이므로 유지. 오케스트라 스킨만 항해로 교체.

| 4R | 폐기된 오케스트라 스킨 | Voyage 스킨 | 의미 |
|---|---|---|---|
| Reframe | 악보 해석 | **항로 재설정** | 출항 전 "어디로 가야 하는가"를 다시 묻는다 |
| Recast | 편곡 | **선원 배치** | 누가(AI/사람) 어느 노를 잡는가 |
| Rehearse | 리허설 | **선원 회의** | 출항 전 선원들이 항로의 약점을 친다 (Crew council) |
| Refine | 조율 | **항로 수정** | 반복은 결함이 아니라 숙련 (course correction) |
| Synthesize | — | **이타카** | 종합 — 목적지가 보인다 |

## 7. 비주얼 시스템 (오케스트라 → 항해)

`MusicalElements.tsx` → `VoyageElements.tsx`:

| 오케스트라 (폐기) | 항해 (신규) | 의미 |
|---|---|---|
| 오선지 / 마디선 (staff/barlines) | 해도 격자 / 위도경도선 (graticule) | 배경 텍스처 |
| 페르마타 (fermata, 멈춤) | 닻 (anchor) | "여기서 멈춘다" |
| ConductorBaton | 조타륜 / 나침반 바늘 (helm/needle) | 방향을 잡는 도구 |
| 다이내믹 마크 (mf/ff) | 나침반 방위 / 항해 깃발 | 강조 표시 |
| (장식) | 나침장미, 항로선(dashed), 등대, 돛 | 분위기 |

오디오(`audio.ts`): 연주음 → 최소한의 항해음(ship's bell 단타) 또는 제거. 과한 의식(ceremony) 지양.

## 8. 톤 가이드

### 쓸 것
- "선원을 편성합니다" (페르소나 생성)
- "선원 회의를 시작합니다" (리허설)
- "항로를 수정합니다" (Refine)
- "이 결정에는 소조면 충분합니다" (규모)
- "🔭 망루가 강하게 경고하고 있습니다" (핵심 반론)
- "이타카가 보입니다" (종합 완료)

### 쓰지 않을 것
- 음악 용어 전부 (악장·연주·편곡·조율·오선지·페르마타·앙상블)
- 항해 전문 용어 중 학습이 필요한 것 (현측·아딧줄 등) — 아이콘+한 줄로 자명해야 함
- mixed metaphor (음악 ↔ 항해 혼용)

### 핵심 원칙
> 단어가 곧 기능이어야 한다. 메타포를 학습해야 쓸 수 있으면 메타포는 실패한 것이다.
> Voyage가 오케스트라를 이긴 이유가 바로 이것이다 — 기능을 가리지 않고 드러낸다.
