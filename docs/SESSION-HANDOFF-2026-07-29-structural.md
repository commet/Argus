## 1. 이 트랙의 한 문장

> **이틀치 결함 9건이 종류가 다른 버그가 아니라, 한 가지 구조적 원인이 아홉 번
> 다른 옷을 입은 것이었다 — 두 곳이 같아야 하는데 한 곳만 고쳐졌다.**

| 결함 | 같아야 했던 두 곳 | 어디서 고쳤나 |
|---|---|---|
| 판단 원장 미이관 | 이관 표 목록 ↔ db.ts 동기화 목록 | #317 |
| 익명 "지우기"가 서버 사본 방치 | `useAuth().user` ↔ session | #317 |
| 규칙 crash | TS 타입 ↔ jsonb 현실 | #317 |
| 감시 캐시 오염 | 캐시 키 ↔ 함수의 실제 입력 | #317 |
| 음소거 무시 | 전제 ↔ 미결질문 | #317 |
| `closed_at` 오독 | 의식 스탬프 ↔ 생애주기 | #308 |
| 글씨 역방향 | 기본 크기 ↔ sm 크기 | #317 |
| **공유 18일 사망** | **마이그레이션 파일 ↔ 실DB** | **#327** |
| **커버리지 누락 2표** | **db.ts TableName ↔ schema-drift 목록** | **#327** |

그래서 개별 수리가 아니라 **그 쌍들의 등록부**를 만들었다:
`src/lib/__tests__/agreement-pairs.test.ts` (16쌍). 등록된 쌍은 반드시 가드를 갖고,
가드 파일이 사라지면 CI가 막는다.

**이 등록부가 못 하는 것(정직하게)**: 아직 아무도 이름 붙이지 않은 쌍은 못 잡는다.
값어치는 "발견된 쌍이 다시 조용해지지 않는다"이지 "모든 쌍을 안다"가 아니다.
새 쌍을 발견하면 **거기 한 줄 추가하는 것**이 이 트랙을 잇는 방법이다.

## 2. #327이 담고 있는 것 (머지 대기)

### 2-1. 공유·이메일·텔레그램·팀초대가 18일간 전부 죽어 있었다

`record_share_if_allowed` RPC가 **프로덕션에 없었다.** 마이그레이션 파일
(`20260711230000_atomic_share_rate_limit.sql`)은 리포에 있었고 코드도 테스트도 초록.
`recordAndCheckShare`는 **옳게** fail-closed 해서 4개 표면이 전부 503이었는데
아무 신호가 없었다. → 적용 완료(§5).

교훈: fail-closed 자체는 옳은 설계다. 문제는 **그 상태가 아무에게도 안 보였다**는 것.

### 2-2. 뮤테이션 프로브 — "초록이 뭘 보장하는가"를 숫자로

`scripts/mutation-probe.mjs` (새 의존성 0). `premises-core.ts` 측정:

- 처음 **47%**. 살아남은 것 중 가장 무거운 것:
  `daysBetween(last, today) >= recheckCadenceDays(p)` — 부등호를 뒤집어도 초록.
  이게 뒤집히면 **확인일이 온 전제는 조용해지고 아직 안 온 전제가 매일 운다.**
  제품의 척추가 반대로 도는데 3,893개가 전부 초록이었다.
- 경계 양쪽을 함께 보는 15개 케이스 추가(`premise-due-arithmetic.test.ts`) → **73%**.

> ⚠️ **도구가 두 번 거짓말했다**: (1) 처음 100%가 나왔는데 바이트 패리티 가드
> (`premises-core-drift.test.ts`)가 모든 변형을 죽이고 있었다 — 패리티 가드를 테스트
> 목록에 넣으면 측정이 무의미해진다. (2) 주석 안의 `true`까지 세고 있었다.
> 둘 다 고친 뒤의 숫자가 위 값이다.

### 2-3. E-1 리팩토링 — ProgressiveFlow 4,177 → 3,186줄

표시 전용 조각 18개를 `flow-parts/` 4파일로 **한 글자도 안 바꾸고** 이동
(원본 바디가 새 파일에 그대로 있는지 기계로 대조). 상태 기계 3,017줄은 무접촉.

런타임 import는 `workspace/page.tsx` 한 곳(dynamic)뿐 → 바깥 위험 없음.
기존 경로는 back-compat re-export로 전부 그대로 동작.

> 옮기자 **소스를 문자열로 읽던 가드 2개가 조용히 눈을 감았다**
> (`no-machinery-leak`, `promotion-basics`). 파일 경로가 아니라 **흐름 표면 전체**를
> 읽도록 고쳤다 — 이것도 같은 부류였다.

**E-2(상태 기계 3,017줄 분해)는 하지 않았다.** 창업자 결정: 뮤테이션 측정으로 그
파일의 테스트가 실제로 뭘 잡는지 본 **다음에**.

## 4. 세션에서 내가 틀렸다가 정정한 것 (같은 함정 피하라고)

1. **가드를 일부러 깨서 검증했는데 초록이 나왔다** → 치환이 파일에서 먼저 나오는
   `isMonitored`에 걸렸고 대상 `isReconsiderable`은 멀쩡했다. **초록을 믿었으면
   "가드 없는데 있다"고 보고할 뻔했다.** 치환 검증은 대상 함수 범위를 잘라서 할 것.
2. **`git checkout <파일>`로 실험을 되돌리다 커밋 안 한 작업까지 날렸다** (schema-drift).
   실험 전 커밋하거나 사본을 떠 둘 것.
3. **PR #308이 "아직 열려 있다"고 보고** → 이미 창업자가 머지한 뒤였고 내 로컬 상태가
   낡았던 것. PR 상태는 `gh pr view <n> --json state`로 그때그때 확인할 것.
4. **뮤테이션 프로브 첫 결과 100%** → 도구 결함(§2-2). 숫자가 너무 좋으면 도구를 의심.

공통: **판정 근거가 "읽어온 값"일 때 그 값이 진짜인지 먼저 의심할 것.**
(직전 인계본 §8의 결론과 동일 — 두 세션 연속으로 같은 함정.)

## 6. 창업자 판단 대기 (우선순위 순)

### 6-1. #327 머지

PR 코멘트의 로컬 재현 표를 볼 것.

### 6-2. 팀 마이그레이션 적용 여부
§5 참조. 적용하면 `teams`/`team_members`/`team_invites`/`team_review_inputs`의
정책이 통째로 교체된다.

### 6-3. 익명 데이터 만료 정책 — **내 추천이 답을 기다리는 중**
익명이 초반 95% 이상이라는 전제 위에서 내가 제안한 것:
1. **계속 다 저장한다** (뒤집지 말 것) — 가입 전에 제품이 진짜로 느껴지는 이유이고,
   이제 가입 시 판단 원장까지 따라오니 전환의 가치가 커졌다.
2. **90일 무활동 익명 신원 자동 정리** — 지금 정책이 **없다.** 익명 신원은
   localStorage 토큰에만 묶여 있어 쿠키를 지우면 본인도 못 연다.
   현재 익명 신원 10개 / 그 아래 프로젝트 9개. 파기라서 창업자 결정.
3. **고지는 딱 한 번, 봉인하는 순간에** — 랜딩은 마찰, 봉인은 그 기록이 지킬 가치가
   생기는 순간.
4. **가입 벽은 세우지 말 것.**

창업자 답이 아직 없다. **이 답이 나오기 전엔 익명 데이터를 지우지 말 것.**

### 6-4. 익명 사용자의 봉인 허용 여부
지금 **된다** (seal 라우트가 `is_anonymous`를 구분하지 않는다). 그런데 UI 에러 문구는
"로그인이 필요해요"라고 **다른 말을 한다.** 둘 중 하나로 맞춰야 한다.

### 6-5. `JudgmentGraph`의 8.5px 데이터 라벨
장식이 아니라 읽는 글자. 크기를 바꾸면 레이아웃이 흔들려 손대지 않았다.
