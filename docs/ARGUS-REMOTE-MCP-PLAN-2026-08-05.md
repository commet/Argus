## 0. 한 문단 요약

사람이 ChatGPT·Claude 안에서 결정을 굴리는 그 자리에, URL 하나로 붙는 원격
MCP 서버를 만든다. 서버는 결정을 포착하고 → 실행 계획을 내주고 → 그 계획의
마일스톤 날짜에 **먼저 찾아와** 무슨 일이 있었는지 묻는다. 뇌는 이미 검증된
`method-harness`(79 테스트)이고, 인증·계정은 이미 있는 자산을 재사용한다.
**새로 짓는 것은 전송 계층·서버 원장·계획 도구 셋뿐이다.**

## 1. 이미 있는 것 — 실측 (2026-08-05 코드 확인)

가정하지 않고 확인한 결과, 원격 MCP의 비용 대부분이 이미 지불돼 있다:

| 자산 | 상태 | 위치 |
|---|---|---|

| OAuth **discovery/DCR** | ~~없음~~ → **2026-08-05 구현 완료** (`.well-known/oauth-protected-resource`·`oauth-authorization-server` + 리소스 경로 변형, RFC 7591 동적 등록, 브라우저 authorize·동의·form-encoded token) | `src/app/api/mcp/v2/oauth/**`, `src/lib/mcp-discovery.ts`, 부록 A 5주차 |

| MCP 표면 사양 | 구현 완료 (가장 엄격한 fire-gate, 제안만, 채택 불가) | `method-harness/surfaces/mcp.ts` |

② 서버측 원장 테이블, ③ 계획(plan) 도구.

## 2. 레거시 경계 — 이 기획의 가장 중요한 결정

`argus-decision-mcp@2.0.20`은 **구 제품의 모델** 위에 서 있다. 어휘를 세어보면
`premise` 444회, `seal` 161회, `recheck` 58회 — 전제(premise) 관리와 봉인이
중심이다. 새 방법(v1.0)의 모델은 다르다: 기준선 → 하중 가정 하나 → 카드 채택
→ 실행 계획 → 관찰 우선 귀환.

**두 모델을 한 패키지에 섞으면 둘 다 죽는다.** 그래서:

> **결정: 원격 MCP는 `method-harness`를 뇌로 삼는 새 표면으로 짓는다.
> `argus-decision-mcp`(로컬 stdio, 구 모델)는 건드리지 않고 그대로 둔다.**

- **재사용하는 것:** OAuth 라우트, `plugin_tokens`, 계정 연결 UX 패턴, Vercel.
  이들은 모델 중립적인 배관이다.
- **재사용하지 않는 것:** premise/recheck/seal 도구, `review_receipts` 스키마,
  구 도구의 개념 어휘. 새 표면은 카드·계획·귀환만 안다.
- **구 패키지의 운명:** 이 기획에서 판단하지 않는다. H-B 판정 후 별도 결정
  사안으로 남긴다 (섣부른 폐기도, 억지 통합도 하지 않는다).

## 2.5 선행 관문 — 이것부터 통과하지 않으면 시공 금지

기획서 초안이 놓쳤던 두 개의 실제 차단 요인이다. 코드보다 먼저 처리한다.

### (가) 격리 가드 amendment

`method-harness/__tests__/harness.test.ts`의 `PILOT_CHANNEL`은 `src/`가 하네스를
import할 수 있는 예외를 **`src/app/method-pilot/` 하나로** 못박고 있다. 새
`/api/mcp/v2` 라우트가 하네스를 부르면 **이 테스트가 빨간불이 된다** — 그리고
그것이 정상이다. 가드는 제 일을 하는 것이다.

**처리:** 예외를 하나 더 여는 명시적 amendment를 시공 첫 커밋에서 한다.

```
PILOT_CHANNEL = /src\/app\/(method-pilot|api\/mcp\/v2)\//
```

승인 근거를 테스트 주석과 BLUEPRINT에 함께 남긴다. **암묵적으로 넓히지 않는다** —
가드를 조용히 무력화하는 것이 이 프로젝트가 가장 경계하는 실패 형태다.

### (나) v1.0 §15.6과의 관계 — 명시적 판정

정본은 이렇게 말한다: *"R3 전 신규 공개 flow·schema migration·graph UI·agent
orchestration 금지 **(pilot harness 예외만)**."*

이 기획은 신규 엔드포인트와 신규 테이블 3개를 만든다. 따라서 **pilot harness
예외 안에 있음을 증명하거나, 시공하지 않거나 둘 중 하나다.** §15.5가 정의하는
pilot harness의 조건에 하나씩 대조한다:

| §15.5 조건 | 이 기획의 준수 방식 |
|---|---|
| 초대 전용 | 커스텀 커넥터 URL 배포만. **디렉토리 등재는 H-B 통과 후** (§8에 이미 명시) |
| 비공개 | 공개 랜딩·가입 흐름 없음. URL을 받은 사람만 |
| 폐기 전제 | 종료 시 데이터 반출·삭제. `argus_*` 테이블은 파일럿 전용이며 폐기 가능 |
| canonical schema 불변 | **기존 테이블을 건드리지 않는다.** `argus_*`는 신규 격리 테이블이고, `projects`/`personas` 등 canonical 동기화 스키마는 무변경 |
| 기존 배관·알림 불변 | 기존 크론·알림 경로 무변경. 귀환은 **새 크론 항목**으로 추가 |

**판정: 이 기획은 pilot harness 예외 안에 있다.** 단 위 다섯 조건이
시공 내내 유지되어야 하며, 하나라도 깨지면 그 시점에 §15.6 위반이 된다.
특히 **디렉토리 등재는 이 예외를 벗어나는 행위**이므로 H-B 판정 전에는 금지다.

이 판정은 창업자 승인 사항이다 — 승인 없이 시공하지 않는다.

## 3. 아키텍처

```
ChatGPT / Claude (커넥터에 URL 붙여넣기)
        │  Streamable HTTP + OAuth Bearer
        ▼
POST /api/mcp/v2          ← 신규. Next.js 라우트 하나.
        │
        ├─ 인증: 기존 plugin_tokens 검증 (seal 라우트 패턴 재사용)
        ├─ 뇌:   method-harness (Ledger · validator · returns · influence)
        └─ 저장: Supabase (신규 테이블 3개, §5)
                    │
                    └─ 마일스톤 날짜 → 크론 → 이메일 귀환
```

**핵심 설계 판단 셋:**

1. **서버가 원장의 정본이다.** 로컬 파일이 아니다. 사용자가 ChatGPT에서 결정하고
   Claude에서 돌아봐도 같은 원장이어야 하고, 무엇보다 **귀환이 서버에서
   출발해야** 한다 (클라이언트는 3주 뒤에 켜져 있지 않다).
2. **stateless 요청.** MCP 세션 상태를 서버 메모리에 두지 않는다. 매 호출마다
   토큰 → user_id → 원장 fold. 서버리스에서 유일하게 맞는 형태다.
3. **채택은 MCP에서 불가능하다** (v1.0 §11.2, 하네스가 tombstone으로 강제).
   호스트의 "승인"은 사용자 행위가 아니다. 도구는 후보를 돌려주고, 채택은
   **사용자가 그 턴에서 명시적으로 채택 도구를 부를 때만** 성립한다.

## 4. 도구 표면 (여섯 개, 그 이상 만들지 않는다)

| 도구 | 무엇 | 방법 정본 대응 |
|---|---|---|
| `argus_open` | 결정을 연다. 기준선(현재 기울기·이유)을 **추출**해 함께 기록 | UNDERSTAND, §2.2 |
| `argus_sharpen` | 하중 가정 하나 + 반증 조건. fire-gate가 먼저 돈다 — 평평하면 침묵 | IMPROVE, §4.6 |
| `argus_plan` | **채택된 결정에 대해** 준비·조사·실행 목록 + 순서 + 기한. 마일스톤이 곧 귀환 계약 | MOVE, `process` 추천 |
| `argus_adopt` | 사용자의 명시적 채택 행위. 이것만이 카드를 정본으로 만든다 | §6.6 |
| `argus_return` | 귀환 진행 — 관찰 먼저, 그다음 기억, 그다음 기록 공개 | RETURN, §7.3 |
| `argus_recall` | 지난 결정·계획·정산 결과를 불러온다 (다음 계획의 재료) | 복리 자산 |

**금지 (도구로 만들지 않는다):** 사용자 점수·등급 조회, 계획 자동 실행,
호스트 승인에 의한 채택, 평평한 결정에 대한 계획 생성.

## 5. 데이터 모델 (신규 테이블 3개)

CLAUDE.md Schema Sync 규약을 처음부터 지킨다 — 세 테이블 전부 같은 커밋에서
마이그레이션 + `schema-drift.test.ts` `TABLE_COLUMNS` + `user-data-tables.ts` +
`erasure-coverage.test.ts`에 등록한다.

| 테이블 | 무엇 | 비고 |
|---|---|---|
| `argus_cases` | 결정 하나 = 행 하나. 상태·제목·소유자 | user_id, RLS |
| `argus_events` | **append-only 원장.** 하네스 `LedgerEvent`를 그대로 | 수정·삭제 없음 (§AUTHORITY) |
| `argus_returns` | 귀환 계약. 트리거 날짜·상태·발송 이력 | 크론이 읽는 유일한 테이블 |

`argus_events`가 정본이고 나머지 둘은 그로부터 fold 가능한 캐시다 — 하네스의
이벤트 소싱 구조를 서버에 그대로 옮긴다.

## 6. 귀환 배달 (이 제품의 심장)

계획의 마일스톤 날짜가 오면 **서버가 먼저 움직인다.** 사용자가 기억해서 돌아오길
기대하지 않는다.

- 크론(기존 `health-pulse` 워크플로 옆에 추가) → `argus_returns`에서 만기 조회
- 이메일 발송: "그때 정하신 것에 대해 실제로 무슨 일이 있었나요?" — **기록은
  아직 보여주지 않는다** (§7.3 관찰 우선)
- 링크는 웹 귀환 화면 또는 "쓰던 AI에서 `argus_return` 부르기" 둘 다 지원
- 전역 예산 3건(봉인 계약 §1)이 여기서 강제된다 — 하루에 세 개 넘게 보내지 않는다

## 7. 반증 가능한 가설 (제품 기획안 §6 승계, 새 지표 만들지 않음)

| | 가설 | 이 기획에서 측정되는 지점 |
|---|---|---|
| H-A | 계획이 막막함을 줄인다 | `argus_plan` 호출 후 세션 내 채택률 |
| **H-B** | **기한이 오면 돌아와 결과를 적는다** | **발송된 귀환 대비 `argus_return` 완주율 — 이 사업의 전부** |
| H-C | 두 번째 계획이 첫 번째보다 낫다 | `argus_recall`이 실제로 다음 계획에 인용되는가 |

추가로 이 표면에만 있는 선행 지표: **연결률** (URL을 준 사람 중 실제로 커넥터를
붙인 비율). 여기서 죽으면 나머지는 측정 자체가 안 된다.

## 8. 시공 순서 (6주, 각 주가 독립적으로 검증 가능)

| 주 | 산출물 | 완료 판정 |
|---|---|---|
| **0** | **선행 관문 (§2.5)** — 격리 가드 amendment + §15.6 pilot-harness 판정 창업자 승인 | 가드 테스트가 새 예외로 green, BLUEPRINT에 근거 기록 |
| 1 | 하네스에 계획 단계 (`plan` 스키마 + `process` 추천 + 마일스톤→귀환 자동 연결) | 하네스 테스트 green, 계획 없는 채택도 여전히 동작 |
| 2 | 서버 원장 3테이블 + `/api/mcp/v2` 전송 + 인증 + **discovery/DCR** | curl로 MCP 핸드셰이크·도구 목록 성공, `.well-known` 응답 확인 |
| 3 | 도구 6개 배선 + Claude 커스텀 커넥터로 실연결 | 창업자 계정으로 결정 1건 완주 |
| 4 | 귀환 크론 + 이메일 + 웹 귀환 화면 | 스스로에게 귀환 도착·완주 확인 |

**디렉토리 등재(ChatGPT 앱 심사·Claude 디렉토리)는 H-B 통과 후.** 커스텀 커넥터
URL만으로 5주차 테스트가 가능하므로, 심사 대기가 일정을 막지 않는다.

## 9. 위험과 대응

| 위험 | 대응 |
|---|---|
| 연결 마찰(설정 화면에 URL 붙여넣기)이 예상보다 높다 | 5주차 첫 관찰 항목. 높으면 웹 파일럿을 대체 통로로 유지 |
| 플랫폼이 커넥터 정책을 바꾼다 | 뇌가 하네스에 있으므로 전송 계층만 갈아끼운다 |
| 서버 원장이 생기며 개인정보 부담 증가 | 처음부터 erasure/export 등록 (§5). 파일럿은 폐기 전제 유지 |
| 계획 품질이 범용 AI와 구분되지 않는다 | 이것이 H-C. 구분점은 계획이 아니라 `argus_recall`이 물어오는 과거 정산이다 |
| 구 MCP와 개념이 섞인다 | §2 경계 — 새 표면은 카드·계획·귀환만 안다 |

## 10. 이 기획이 하지 않는 것

로컬 stdio MCP 재작성 · 구 `argus-decision-mcp` 폐기 판단 · 팀 기능 · 그래프
UI · 사용자 점수 · 계획 자동 실행 · **디렉토리 등재(H-B 통과 전)** · canonical
schema 수정 · 기존 크론·알림 경로 변경.

§15.6 관계는 §2.5(나)에서 판정한다 — "유지"가 아니라 "pilot harness 예외 안에
있음을 조건과 함께 증명"이다.

**0주차 실측 결과 (기획서의 최대 미검증 위험이었던 항목):**

- MCP over HTTP가 Next.js 라우트에서 **동작 확인** — 401 + `WWW-Authenticate`,
  JSON-RPC 오류 봉투, GET 405, discovery 문서 응답 전부 curl로 확인.
- **SDK를 쓰지 않기로 결정.** SDK 전송기는 Node req/res를 받는데 App Router는
  Web Request/Response를 준다. 우리 표면은 stateless·서버 무발화·도구 6개로
  좁으므로 JSON-RPC를 직접 구현하고 실제 페이로드로 테스트한다(34 케이스).
  서버가 먼저 말해야 하는 기능이 생기면 SSE와 SDK 전송기를 재검토한다.
- `WWW-Authenticate`가 가리키는 `/.well-known/oauth-protected-resource`(RFC 9728)를
  **같은 커밋에서 실재화** — 가리키는 곳이 404면 그것이 "그럴듯한데 깨진" 상태다.

**교훈:** 초안이 "FINAL CANDIDATE"로 표기됐다는 사실은 검토됐다는 뜻이 아니었다.

**이메일이 맞는 채널인가 (창업자 질문, 2026-08-05).** 아니다 — backstop일 뿐이다.
이메일은 진짜 push지만 받은편지함 → 클릭 → 웹페이지라는 **이동**을 요구하고,
그것은 "사람들이 이미 있는 곳에서 만난다"는 이 기획의 전제와 정면으로 어긋난다.
MCP 서버는 먼저 말을 걸 수 없다는 제약은 사실이지만, 놓친 선택지가 있었다:
**사용자가 다음에 어떤 도구든 부를 때 그 응답에 얹으면 된다.** 채팅 안에서, 이동 0.
이제 성공 응답 끝에 최대 2건까지 붙는다(자제 규칙). 이메일은 채팅으로 다시
돌아오지 않는 사람을 위해 남긴다.

**5주차 실측 (로컬 서버 기동 후 curl — 추측이 아니라 응답 본문):**

| 무엇 | 결과 |
|---|---|
| `/.well-known/oauth-protected-resource` (+ `/api/mcp/v2` 변형) | 200, 같은 문서 |
| `/.well-known/oauth-authorization-server` (+ 변형) | 200, 세 엔드포인트가 실재 경로를 가리킴 |
| `POST /api/mcp/v2` 무인증 | 401 + `WWW-Authenticate: Bearer realm="argus", resource_metadata=…` |
| `GET /api/mcp/v2` | 405 + `Allow: POST` |
| `register` — 평문 http redirect_uri | 400 `invalid_redirect_uri` |
| `register` — `client_secret_post` 요구 | 400 `invalid_client_metadata` (공개 클라이언트만) |
| `token` — form-encoded 파싱 | 사양 형식을 실제로 읽음 (`grant_type` 인식 확인) |
| `token` — PKCE 없는 교환 | 400 `invalid_grant` |
| `authorize` — client_id 없음 / 미등록 | 사람이 읽는 400 / 503 |
| locale 없는 `/connect/mcp?…` | 307, **쿼리 보존 확인** (인가 파라미터가 살아서 동의 화면에 도달) |

**이 실측에서 발견해 고친 것:** 저장소가 죽었을 때 `authorize`가 브라우저에
**빈 500**을 주고 있었다. 사용자는 커넥터 설정 화면에서 "설정 실패"만 보고
무엇이 틀렸는지 영영 모른다 — 이 화면은 사람이 읽는 유일한 지점이므로 삼키면
안 된다. 네 라우트 전부 저장소 장애를 사양 안의 오류(`temporarily_unavailable`)
또는 사람의 문장으로 끝내도록 고쳤다. (`/[locale]` 페이지가 이 환경에서 500인
것은 CLAUDE.md가 적어 둔 키 부재 현상이며 코드 결함이 아니다 — 로그에서
`src/lib/supabase.ts` 모듈 평가 실패로 확인.)
