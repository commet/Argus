## §A. 목표 형상 — 하나의 루프, 세 개의 문 (청중은 열린 질문)

**제품 = 루프**: 알아봄(측정) → 봉인("물어봐 줄까요?") → 귀환("그래서, 어떻게 됐어요?") → 자차표.

| 시계 | 문 | 표면 | 상태 |
|---|---|---|---|
| 주 단위 | 깊은 세션 (무거운 결정) | 웹앱 | **재구축의 중심** — 몰입이 실관찰로 검증된 곳 |
| 시간 단위 | `/argus:helm` (에이전트 계획 승인 전 탐침) | 플러그인 | 루프 부트스트랩 도메인 (§C+ 루프 압축) — P0.B 통과 시 |
| 일 단위 | watch (대화에서 결정 수확) | CLI/훅 | 구축 완료(2026-06-11), 내기 3 정산 대기 |

- **원장은 스키마 규약만 통일한다** (decision 객체의 JSON 모양 공유). 도메인 횡단 자차표·동기화
  배관은 **H5 검증 후** — 두 문을 다 쓰는 사용자가 실존할 때.
- 어느 문이 주력인지는 출시 후 데이터가 정한다. 지금은 셋 다 같은 루프 위에 세운다.

## §B. 갈아엎기의 정의

**부순다 (경험과 엔진):** ① 질문 원천 — AI 의견 단독 → **측정 정박 + 몰입 심화의 적층**(§W2.3,
교체 아님) ② 세션 아크 — 산출물 클라이맥스 → 봉인 종막 ③ reframe 판정형 → 목적-수준 분기 측정
④ 랜딩 3막 → 세이렌 1화면, IA 6진입 → 단일 진입 ⑤ 페르소나 시스템 — XP/언락 게이트 제거,
역할 재배치 (§W1.5).

**남긴다 (배관과 검증된 강점):** 스트리밍 극장, 질문 루프 UI 골격, convergence 게이지(역방향 재활용),
deepening 루프(삭제 금지 — 측정의 그릇이 됨), i18n, Zustand/Supabase 배관, 인증·쿼터(견고 확인),
`DecisionContractCard`, `signal-recorder`, watch CLI, 플러그인 뼈대, **페르소나 자산 17종**.
**새 레포 금지. 구 경로는 flag로 보존** (A/B 기준선 + 회귀 안전망).
