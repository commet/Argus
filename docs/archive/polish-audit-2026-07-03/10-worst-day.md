# 10 — 최악의 날의 품격: 도구의 인격은 실패할 때 드러난다 (2026-07-03)

> 감사 범위: 6가지 최악의 순간 — (a) 오프라인 (b) LLM 죽음(429/529/타임아웃) (c) 데이터 0의 새 계정 (d) 6개월 만의 귀환 (e) 정산일을 한참 넘김 (f) 세션 만료.
> 기준: 02-voice의 Argus 목소리 가이드("도착을 알아본다 · 막힘은 배의 사정 · 사실은 세고 판정하지 않는다"). 모든 인용은 실제 코드를 열어 확인함. 이 감사의 심장: **정산일을 놓친 사용자를 죄인으로 만들지 않는다.**

## 요약 (5줄)

1. **의식(ritual) 화면은 이미 최악의 날을 잘 맞는다.** 정산 모달은 늦게 온 사람에게 늦었다는 말을 한마디도 하지 않고("그래서, 어떻게 됐어요?", 두 번 미루면 "천천히 해도 돼요", `SettlementModal.tsx:200,370`), 귀환 스트립·계약 카드·ETA 배지 모두 날짜만 말하고 지각을 세지 않는다. 이 결이 정답이고, 나머지를 여기에 맞추면 된다.
2. **가장 아픈 구멍은 세션 만료다 (P0).** 세션이 만료되면 ① 클라우드 백업이 소리 없이 멈추는데 배지 자체가 사라져 아무 표시가 없고(`db.ts:218` + `Header.tsx:279`), ② 계정이 있는 사람에게 "무료 체험을 모두 사용했어요"라며 처음 온 손님 취급을 한다(`llm.ts:81`, `workspace/page.tsx:647`).
3. **지각을 세는 라벨이 세 군데 남아 있다**: 검수 대시보드 배지 "확인 지남 (N일)"(`status.ts:106` — 6개월이면 "확인 지남 (183일)"), 가져오기 화면 "기한 지남"·"확인일이 지났습니다"(`import/page.tsx:241,262`). 확인 날짜는 이미 카드에 있으므로, 늦은 날수 집계는 죄책감 숫자일 뿐이다.
4. **웹 봉인 결정의 텔레그램 재알림은 답이 없으면 7일마다 무한 반복**이고(`checkin-due/route.ts:107,132`) 봇에는 "그만 물어봐 주세요" 탈출구가 없다 — 웹 모달엔 있는 절제(2회 미루면 '알 수 없음으로 닫기')가 푸시 채널엔 없다.
5. **6개월 만에 돌아온 사람을 알아보는 문장이 첫 화면에 없다.** 워크스페이스는 "이어서 작업 · 6달 전"만 말하고, 돌아올 결정은 헤더의 작은 숫자 배지뿐. 로그인까지 풀려 있으면 신규자용 카피("로그인하면 저장되고~")가 맞이한다 — 등불이 아니라 안내데스크다.

### (d) 6개월 만에 돌아왔을 때

추적 결과, **긴 부재를 알아보는 코드가 웹앱에 한 줄도 없다** (`오랜만|welcome back|lastSeen` 전수 grep — 히트 0). 지금의 귀환 경험:

1. `/workspace`(기본 착륙지)에 내림 → "이어서 작업" 목록에 "6달 전"이라는 상대시각(`workspace/page.tsx:719,729`). 돌아올 결정(due) 언급은 **이 화면에 없음** — `workspace/page.tsx` 전체에 due가 0회 등장.
2. 헤더 프로젝트 탭에 작은 숫자 배지(`Header.tsx:83-86,199`). 이게 유일한 신호.
3. 배지를 눌러 `/project`에 가면 그제야 모범적인 문장을 만난다: "그래서, 어떻게 됐어요? — 돌아올 결정 N건" (`project/page.tsx:482`).

즉 등불은 있는데 **항구 안쪽에** 걸려 있다. 6개월 만에 온 사람이 첫 화면에서 받는 인상은 "옛 파일 목록"이지 "기다리고 있었어요"가 아니다.

더 나쁜 경우의 수: 6개월이면 브라우저가 localStorage를 비웠을 수 있고(Safari는 미사용 사이트의 스크립트 저장소를 7일 후 정리한다), Supabase 세션도 만료됐을 수 있다. 그러면 이 사람은 **완전한 이방인으로 취급된다** — 빈 워크스페이스 + 데모, /project에선 "프로젝트는 로그인이 필요해요 / 로그인하면 지금까지 작업한 내용이 프로젝트로 저장되고…"(`src/components/layout/AuthGuard.tsx:29-33`). 이 카피는 신규자용이라, 돌아온 사람에게는 "내 기록이 사라졌나?"라는 공포로 읽힌다. 실제로는 로그인만 하면 `loadAndMerge`가 서버에서 전부 복원한다 — **그 사실을 말해주는 문장이 없다.**

한편 텔레그램을 연결해 둔 사람이라면: 웹에서 봉인한 결정에 대해 6개월간 **7일마다 영어 기계문**("Argus check-in / Tap a button…", `src/lib/telegram-settlement.ts:81-89`, 발송 `checkin-due/route.ts:132`)을 최대 26번 받았다. 텔레그램에서 봉인한 결정은 정확히 1회만 묻는다(`cron/telegram-reminders/route.ts:17,55` — `reminded_at` 스탬프). 같은 제품의 두 채널이 절제의 반대편에 서 있다.

**어기는 곳:**

1. **검수 대시보드 배지가 지각을 센다.** `src/lib/review/status.ts:105-106`:
   ```ts
   if (derived === 'due' && days_until !== undefined && days_until < 0) {
     label = `확인 지남 (${-days_until}일)`;
   ```
   이 라벨이 검수 카드 배지에 그대로 앉는다(`ReceiptList.tsx:117`). 6개월 뒤 돌아온 사람의 카드엔 "확인 지남 (183일)" — 출석부다. 확인 날짜 자체는 같은 카드 아래 이미 표시되므로(`ReceiptList.tsx:121` "확인일 2026-01-02"), 늦은 날수를 굳이 세어 보여주는 건 정보가 아니라 판정이다.
2. **가져오기 화면이 "기한"이라는 단어를 쓴다.** `import/page.tsx:241` 배지 "기한 지남", `:262` "확인일이 지났습니다. 실제로 어떻게 됐나요?" — "기한(deadline)"은 사용자가 어긴 마감이라는 틀. Argus의 확인일은 마감이 아니라 약속한 재회다.
3. **텔레그램 재알림이 무한 반복 + 탈출구 없음.** 웹 봉인 계약은 due인 동안 7일마다 재발송(`checkin-due/route.ts:107,132` — `RESEND_DUP_WINDOW_MS`), "Still pending"을 눌러도 1주 뒤로 미뤄질 뿐 또 온다(`telegram-settlement.ts:122-130` → `amendCheckIn '1w'`). 웹 모달이 가진 "알 수 없는 걸로 닫기" 탈출구가 봇엔 없다. 답하지 않는 것도 답인데, 그 답을 받아줄 버튼이 없다.
4. **플러그인 스테이터스라인 빨간 `OVERDUE`** (`argus-plugin-v2/statusline/index.js:315-319`, "never decays, beats everything"). 02-voice와 동일 결론: 개발자 대상 + 의도된 정직한 신호(:322-323 주석에 "check_by ≤ today means 'settle now', not 'you are late'"라는 설계 흔적)이므로 **유지**. 다만 이 어휘를 웹앱 사용자 표면으로 수입하지 않는 것이 규칙이다.

### (f) 로그인 세션이 만료됐을 때

세션 만료를 다루는 코드가 없다 — `onAuthStateChange`는 SIGNED_IN만 특별 취급하고(`src/lib/auth.tsx:79-97`), 만료로 user가 null이 되는 순간을 아무도 알리지 않는다. 그 결과 세 겹의 침묵:

1. **백업이 소리 없이 멈춘다.** 모든 Supabase 쓰기가 `if (!userId) return;`으로 조용히 무시되고(`src/lib/db.ts:218` upsert, `:245` softDelete, `:268` delete), 하필 그 순간 상태를 말해줄 SyncStatus 배지는 로그인 게이트 뒤라 **화면에서 사라진다**(`Header.tsx:279-281`). 사용자가 받는 유일한 신호는 헤더 구석의 아바타→로그인 버튼 교체뿐.
2. **회원을 뜨내기로 부른다.** LLM 호출은 bearer 없이 나가고(`llm.ts:465-471` — 4초 타임아웃 시 토큰 없이 진행), 서버는 익명 쿼터로 취급, 소진되면 429+needsLogin(`src/app/api/llm/route.ts:133`) → 클라이언트 문장은 "무료 체험을 모두 사용했습니다. 로그인하면 하루 N회…"(`llm.ts:81`) → 워크스페이스 카드도 "무료 체험을 모두 사용했어요"(`workspace/page.tsx:647`). 계정을 만들고 결정을 봉인해 온 사람에게 "체험"이라니 — 알아봐주는 목소리의 정반대다. (`user` 변수가 같은 스코프 663줄에서 이미 쓰이고 있어 분기 비용은 한 줄이다.)
3. **돌아갈 문의 카피가 신규자용이다.** /project의 AuthGuard: "로그인하면 지금까지 작업한 내용이 프로젝트로 저장되고, 다음 번에 이어서 작업할 수 있어요"(`AuthGuard.tsx:31`) — 이미 저장해 둔 사람에게는 "저장되고"가 미래형이라 불안을 만든다. 공용 사전도 "인증에 실패했습니다. 다시 로그인해주세요."(`ko.ts:170`) — 실패한 건 사용자가 아니라 세션이다.

## 스파인 충돌 검토

1. **지각 라벨 제거(S2)는 사실 은폐가 아니다.** 확인 날짜라는 사실은 카드에 그대로 남는다(`ReceiptList.tsx:121`) — 빠지는 것은 "당신이 며칠 늦었다"는 파생 집계, 즉 사용자에 대한 판정뿐. 규칙 2(평결 금지)의 직접 적용이다.
2. **재알림 상한(S3)은 거울 조항의 직접 적용.** "개입할지 말지를 사용자 대신 판단하지 않는다" — 26번 조르는 것이야말로 개입 과잉이었다. 탈출구 버튼은 friction escape 추가이므로 규칙 1의 방향과 일치. 리마인더를 멈춰도 웹 due 표면은 유지하므로 고리 자체를 몰래 닫아버리지 않는다(정직).
3. **귀환 인사(S4)의 과개입 점검**: due 0건이면 렌더 0 — 부재 길이("오랜만이에요")를 세지 않는 이유도 같다: 부재 집계는 온기로 포장한 출석부다. 기다리던 결정이 있을 때만, 그 결정이 말하게 한다.
4. **세션 만료 문안(S1)은 약속만큼만 말한다.** "기록은 계정에 그대로 있어요"는 `loadAndMerge`가 실제로 하는 일(`db.ts:56` 주석)이고, "이 기기에 계속 저장되고 있어요"는 localStorage-first라 참말이다. 다만 (b)의 "이 기기에만 저장 중" 배지가 전제하는 것: 만료 상태의 쓰기가 정말 로컬에는 남는다는 것 — 스토어들이 setStorage를 먼저 부르는 구조이므로 성립하나, 구현 시 한 번 실주행으로 확인할 것(Persistence 원칙 3: "행수도 본다").
5. **칭찬·평결 미포함 전수 확인**: 모든 제안 문안은 상태 서술("풀렸어요", "기다려요", "그대로 있어요")과 질문("어떻게 됐어요?")까지만 — 점수·등급·잘잘못 어휘 0. "다시 오셨네요"는 도착의 알아봄이지 평가가 아니다(02-voice 원칙 1).
