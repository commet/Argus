# 오케스트레이션 B+ → A 격차 메우기 (계획)

**작성: 2026-06-24** · 트리거: 배포 전 에이전트팀 감사(40-에이전트 워크플로우 + 2건 보수적 재검증).
**상태: 계획만 — 코드 작업 전. 우선순위·범위 합의용.**

## 한 줄 진단
스파인 설계·LLM 트랜스포트(`llm.ts`)·스파인 eval은 진짜 A급. 그러나 **"결과가 좋은지"를 보장·관측·진단하는 3개 기둥**이 비어 있어, 전체로는 "스파인의 메달을 단 B+/A−". 아래를 채우면 A 주장이 방어 가능해진다. **어느 것도 배포 차단 사유는 아니다** — 배포 후 순차 작업.

---

## P1 — 신뢰성 (배포 직후 착수 권장)

### 1. 런타임 출력 품질 eval (가장 중요)
- **문제:** `argus-plugin-v2/evals/`는 *스파인 tilt만*, 그것도 *플러그인 마크다운만* 채점한다. 사용자가 실제 쓰는 **웹앱 런타임(`progressive-engine` + `progressive-prompts`)의 Mix/합성 출력은 generate-and-judge 대상이 아니다.** → 공허하지만 규칙 준수하는 답이 전 게이트 통과 가능.
- **할 일:** 웹앱 런타임 경로에 골든셋(10~20 결정 시나리오) + 페어와이즈/루브릭 LLM 심사(유용성·정확성·갈림질문 품질)를 붙이고 `npm run eval`에 회귀 게이트 추가.
- **완료 기준:** "이 PR이 출력 품질을 떨어뜨렸나"를 CI가 잡는다.
- **노력:** 중(2~3일).

### 2. 검증 실패 워커가 합성으로 새는 것 차단
- **문제:** 점수<70 워커 결과가 `passed=false`인 채 그대로 Mix/lead-synthesis로 흘러든다. 유일한 완화는 UI 배지(`worker-engine.ts` MAX_RETRIES=1, 재라우팅 미발화).
- **할 일:** 합성 입력에서 실패 워커 제외 또는 명시적 `[저신뢰]` 격리; 1회 재시도 후에도 실패면 다른 에이전트로 재라우팅(`worker_rerouted` 이벤트는 이미 정의됨, 발화만 안 됨).
- **노력:** 소~중(1~2일).

### 3. 계기판 — 워커별 비용/토큰/지연 관측
- **문제:** 토큰은 `userId+path`로만 찍혀 세션/워커에 연결 안 됨. 이상하거나 비싼 배포를 사후에 "왜"로 못 파고든다(transcript에 토큰·모델·지연·프롬프트 없음, localStorage 20세션 FIFO).
- **할 일:** 실행 transcript에 워커별 {모델, 토큰 in/out, 지연, 프레임워크, 컨텍스트 전략} 기록 + 세션 단위 비용 합계. 가능하면 서버측 영속.
- **노력:** 중(2~3일).

## P2 — 효과/효율 (그다음)

### 4. 모델 티어 살리기
- **문제:** `"strong"`/Opus 티어가 죽은 별칭(→Sonnet). critical 합성·debate조차 Sonnet. 깊은 추론 티어 부재.
- **할 일:** stakes=critical의 합성/debate를 강한 티어로 라우팅(비용은 P1-3 계기판으로 관측하며 조정). "전부 강티어"는 금지 — stakes 기반 escalation만.
- **노력:** 소(0.5일) + 비용 모니터링.

### 5. 라우팅이 신규 입력에 조용히 무너지는 것 방지
- **문제:** 도메인 감지가 substring 키워드 매칭(`orchestrator-classify.ts`). 못 잡으면 `domains=[]` → lead synthesis가 조용히 누락(신호 0). 신규 용어·비목록 도메인에 취약.
- **할 일:** domains 비었을 때 (a) 사용자/로그에 "일반 모드로 진행" 신호, (b) LLM 백업 분류 1회. 침묵 다운그레이드 금지.
- **노력:** 소~중(1~2일).

### 6. 컨텍스트 절단·토큰 예산
- **문제:** 고정 슬라이스 절단(`slice(0,1500/1000/800/300)`), 관련도 선택·dedup 없음; 토큰 추정이 `text.length`(영어 4배 오차), 예산 미강제.
- **할 일:** 토큰 추정 교체(tokenizer) + 워커당 입력 예산 캡 + 길이 대신 관련도 기반 패킹(최소: 중요 섹션 우선).
- **노력:** 중(2일).

### 7. 콜드스타트 자기개선
- **문제:** 경험 보정 ≥5, 컨텍스트 자기튜닝 ≥10 데이터포인트 필요 → 신규/경량 사용자에겐 사실상 비활성. "쓸수록 정확" 약속이 거의 미발동.
- **할 일:** 데이터 부족 시 합리적 사전분포(prior) 또는 전역 집계 보정으로 폴백.
- **노력:** 중.
