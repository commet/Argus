# 라운드 12–24 종합 — 플러그인·웹앱 두뇌 하드닝 + 드리프트 닫기

> Date: 2026-06-18
> R1~11이 *엔진 설계*(추상)와 *재설계(subtractive)*를 검증했다면, R12~24는 **실제 shipped 두뇌**(플러그인 SKILL.md + 웹앱 프롬프트)를 부딪혀 고쳤다. 사용자 지시: 자기강화 금지, 근본 원인, 창의적, 표면/프롬프트 남발 금지, R24까지.

## 1. 호(arc)
- **R12~18 — 플러그인 하드닝.** clarify(첫 대화) literal 두뇌를 부딪힘 → tilt가 modal·위기 규칙 부재 발견. R13 프롬프트 패치는 *self-play로 11→4처럼 보였으나* R14 blind A/B가 그게 가짜임을 폭로(규칙 추가는 tilt 무력). **R16: 형식(C+ = 핵심을 양-비용 대칭으로 + 두 선택지는 사용자 위임)이 미는 힘을 8/10→1/10로** (가치↑). settle(R17)·log(R18)는 R9 우려보다 견고(9/10, 8/8) — R9 발견이 과대평가.
- **R19~23 — 웹앱 드리프트 발견·닫기.** 웹앱 엔진은 절제 장치 *전무* → 28/30 harm(플러그인 11보다 나쁨), 대신판단 17. STEP 0 분류 게이트 포팅(R20) → 13. 저항 분기 + OPEN 대칭(R22) → **7/30**(플러그인보다 낮음). **두 표면 정렬 = 드리프트 닫힘.**

## 2. 숫자
| 표면 | 시작 | 끝 | 핵심 수정 |
|---|---|---|---|
| 플러그인 clarify(tilt) | 미는힘 8/10 | **1/10** | C+ 형식(대칭 crux + 사용자 위임) |
| 플러그인 clarify(over-fire/위기) | — | 닫힘 | step-0 게이트 + 위기 스크린 |
| 플러그인 settle/log | — | 견고(9/10·8/8) | 운/실력 basis만 보강 |
| 웹앱 엔진 | **28/30** | **7/30** | STEP 0 + C+ + 저항 + 대칭 포팅 |

## 3. 핵심 발견 (근본)
1. **프롬프트 규칙 추가는 tilt를 못 고친다(R14 blind 확증).** "기울지 마"를 SKILL에 쌓아도 자유산문이 매체라 샌다 — 사용자 경고가 데이터로 입증.
2. **형식이 답이다(R16).** 핵심 질문을 *양-비용 대칭*으로 짜고 두 선택지를 *사용자가 쓰게* 위임 → tilt의 매체(엔진 산문)를 구조적으로 제거. 미는 힘 8→1, 가치 유지.
3. **분류 게이트(step-0)가 over-fire/대신판단의 대량 원천.** 웹앱 대신판단 17→0, 사소한 over-fire 5→0. "모든 입력에 풀 기계"를 "먼저 분류 후 절제"로.
4. **발견 라운드(R9)는 과대평가했다.** "track-record 가짜 통계 priority 10"은 *웹앱 코드 버그*(이미 고침)였지 두뇌 문제 아님 — settle/log 두뇌는 견고. *자기강화 경고는 발견 단계 자체에도 적용된다*(상상 harm은 부풀려진다; 실제 부딪힘이 교정).

## 4. 환원 불가 잔여 (없애지 말고 *밝힐* 것)
- **value ∝ tilt 바닥(~7/30).** 무거운 가치판단 결정(열쇠·폭로·동업자)에선 *가장 유용한 핵심을 짚는 행위 자체*가 옅게 방향을 가리킨다. 형식(C+)으로 최소화했으나 0 불가. **제품-수준 1회 고지로:** "Argus는 결정이 도는 한 질문을 짚고, 드물게 옅은 치우침이 남을 수 있으며, 그건 출력마다 면책하지 않고 한계로 밝힌다." (출력마다 tilt-태깅은 R7에서 *더* 나빴음 — 금지.)
- 두 표면 다 같은 바닥 = 더 낮출 길은 프롬프트가 아니라 산출물 *구조*(웹앱의 5단계 카드 등) 재설계 또는 실사용 데이터.

## 5. 미완 (정직하게)
1. **코드 게이트 단일원천화 미완.** 지금은 *프롬프트* 정렬(plugin SKILL ↔ webapp prompt)이라 또 드리프트 가능. 판정 가능한 부분(분류·평탄·위기)을 `data/`+코드(webapp `judgment-gates.ts`/`crisis-gate.ts` + 플러그인 참조)로 단일원천화 + parity 테스트 = "한 번 고치면 둘 다"(명심2의 1).
2. **웹앱 다른 프롬프트 미수정:** `buildDeepeningPrompt`/`buildOverreachPrompt`(성공-환상 부풀리기)도 같은 절제·비-verdict로.
3. **settle `basis`(운/실력) webapp 정렬:** plugin ledger에 넣었으니 webapp GradeSummary/Predicate에도.
4. **전부 시뮬레이션이다.** plugin·webapp·persona·채점이 같은 모델군(self-play). blind A/B로 "수정 봐주기"는 제거했으나 최종 검증은 **실사용자**. (memory finishline-probe: 진짜 막힌 건 가입/로그인 문 — 두뇌가 아니라 *도착*.)
5. **미탐색 영역(R9 백로그):** persona 날조, patterns 자기실현 정체성, 가치 단일문화, 프롬프트 인젝션, 의존, cold-start — 다음 캠페인.
