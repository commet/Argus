# R29–R30 — Prose-only deviation rate across model tiers, and the vent-template fix

> 2026-06-19. R29 stopped self-scored sims and MEASURED the real deviation rate of
> the markdown plugin across model tiers (haiku / sonnet / opus), because the
> plugin runs on whatever model the user's Claude Code has and a markdown surface
> has no runtime to enforce its prose rules. R30 shipped the one spec-defect R29
> found and re-measured to prove it. Method: a producer agent (run ON each tier,
> with NO banned-pattern coaching) reads the REAL clarify SKILL.md and produces
> the actual user-facing output; an independent strict opus judge scores each
> output against the spine. ~217 agents (R29) + ~190 (R30).

## R29 — the measurement

**Headline: prose-only enforcement does NOT hold — haiku 44% / sonnet 44% / opus
25% deviation, and it is NOT monotonic with model strength (bimodal).** Two
signals diverge:
- **Route-classification accuracy IS monotonic** (route_errors 10 / 7 / 1) — picking
  the right route degrades cleanly with model weakness.
- **Banned-pattern leakage within a route is bimodal** — opus 25% vs haiku == sonnet
  44%. Sonnet buys the user almost nothing over haiku on spine-fidelity; only opus
  roughly thirds it. **A plugin cannot assume opus; the median (sonnet/haiku) user
  sees ~44% deviation.**

### The biggest number was a SPEC DEFECT, not model deviation

vent deviated **6/6 on every tier (100%)** — but the models were faithfully
COMPLYING with a defective template. The canonical vent on-ramp in clarify
SKILL.md (`결정으로 바꿔서 같이 볼까요? 아니면 그냥 들을게요`) is itself a banned
two-pole fork whose second pole (`그냥 들을게요`) is an availability hook — and it
self-contradicted the Forbidden-patterns no-hook rule. **Same defect class as
R28's C1** (route copy contradicting the forbidden list). Fixable in prose, today.

### The genuinely model-dependent leaks (NOT prose-fixable)

- **flat `decided_for_user` (high severity) — worst on SONNET (6/6), haiku 5/6,
  opus 2/6.** Sonnet's "be helpful, give an answer" bias makes it decide FOR the
  user on a flat tie (a mirror-clause spine violation) MORE than haiku does — and
  sonnet is the webapp's default tier. The M-flat prose gate already exists; weak/
  mid models ignore it. Per R28, more prose only fakes confidence → needs a runtime.
- **crisis_miss (highest harm) — sonnet 2, haiku 1, opus 0, all high.** Weak/mid
  models miss a veiled-SI / ruin signal and skip M-crisis. Deterministic on a
  markdown surface = impossible (the C5 ceiling). NOTE: the **webapp already wired
  `classifyCrisis` in front of the LLM (R27)** — so the webapp is protected for the
  regex-detectable cases; the plugin is not.

### Regression of R28's C1–C3 (held)

- **C1 (no contract_seed on validation): held** — residual 2, one on opus (rare
  drift, not weak-model collapse); the ban is intact.
- **C2 (decline verdict both directions, no normalizing premise): held well** —
  validation became one of the cleanest routes (haiku 2/9, sonnet 0/9, opus 1/9).
  The only residual is the **rhetorical-question form** of the lean (`주변이
  반대한다고 그 이유가 바뀌나요?`) — C2 closed the front door; the lean leaked through
  a side window.
- **C3 (bounded affect-ack): over-corrected exactly as predicted (the C3/C5
  knife-edge), but all LOW severity and — the surprise — concentrated on OPUS**
  (vent_overwarm opus-only 2/2; opus "performs" empathy hardest and blows past the
  one-clause bound), and it surfaced on the VENT route, not C3's refuse-to-own slot.
  Absorbed by the vent rewrite (which carries the one-clause bound).
- **anti-Barnum / self_profiling: held 0/3 on EVERY tier incl. haiku** — the one
  differentiated edge survives weak models because it is a product-STATED decline,
  not a capability-dependent inference. (n was thin → widened in R30.)

## R30 — the fix + the proof

### Shipped (prose, both surfaces where applicable)

- **Vent template rewrite (plugin-only — the webapp vent branch already reflects
  one line and stops).** Dropped the two-pole fork + `그냥 들을게요` hook → ONE
  honest reflective clause + a SINGLE *stated* handle (`필요하면 이걸 결정으로 같이
  정리할 수도 있어요`, stated not asked) + stop. Reconciled the Forbidden-patterns
  vent line to ban the two-pole on-ramp (sole source of truth). Subtractive.
- **Validation rhetorical-lean residual (both surfaces).** C2 now also names the
  rhetorical/leading-question form of the normalizing lean as the same banned
  disclaimed verdict; the check must be stated neutrally, never as a leading question.

### Re-measured (same harness, CORRECTED judge separating spec_defect from
model_deviation; partial run — see caveat)

| Metric | R29 | R30 |
|---|---|---|
| **vent spine-deviation** | **100%** (6/6 every tier) | **17%** (4/23); haiku 0/8, sonnet 3/8, opus 1/7 |
| **spec_defect deviations** | (conflated, large) | **0 / 76** |
| model_deviation deviations | — | 26 / 76 |
| self_profiling (widened n) | 0/9 | **0/12** |
| flat control (judged) | sonnet 6/6 | still deviating (haiku 2/2, sonnet 3/3) |

**The vent fix is proven.** Same inputs, 100% → 17%, and critically **0
spec_defect across all 76 judged outputs** — the spec no longer sanctions any
banned pattern, so R29's scariest aggregate was spec-induced and is now closed.
The 17% residual is pure model drift (haiku, the weak tier, is now a perfect 0/8).

**The method correction works.** Separating "does the output violate the spine"
from "did the spec sanction it" cleanly attributed every remaining deviation to
model_deviation (26) vs spec_defect (0) — so a template defect can never again be
misread as a model-fidelity ceiling.

**Controls held** — flat still deviates (not prose-fixable, confirmed) and
validation's residual is now all model_deviation (contract_seed/hook still drifts
on weak/mid models even though C1/C2 closed the spec door). Both confirm the next
frontier is the **webapp runtime**, where enforcement is model-independent.

**self_profiling held 0/12** with widened n — the sole differentiated edge is
robust on weak models. Do not touch it.

## Carried forward → R31 (implementable by hand, no agents)

The webapp HAS a runtime; the model-dependent residuals (flat `decided_for_user`,
validation contract_seed/hook drift) are exactly the "encode the rule as runnable
data on the surface that has a runtime" move. R31 (no measurement workflow needed):
1. Surface `request_type` + `frame_status` in the webapp's `InitialAnalysisResponse`
   so the runtime KNOWS the route (today it does not — `progressive-engine.ts:52`).
2. Add a deterministic post-LLM lint: on `frame_status == flat`, strip a directive
   verdict / manufactured fork; on `validation`, strip an appended contract_seed /
   re-engagement hook. Model-independent enforcement the markdown plugin cannot have.
3. Keep the plugin as prose-gate + product-level tier disclosure (it runs on the
   user's model; fidelity is tier-dependent — honest provenance extends to that).
4. When the spend limit lifts: re-run the multi-tier harness head-to-head
   (plugin-prose vs webapp-runtime) to quantify how much the runtime closes the gap.
