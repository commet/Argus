# Argus 코드 지도 — 무엇이 살아 있고 무엇이 죽었나 (2026-08-19)

> 창업자 지시: *"전체 코드를 빨리 읽고 장악하자. 지우거나 치워버릴 것들 정리하고
> 교통 정리부터 제대로 하자."* → *"진짜 잘 만들었고 지켜야 되는 것 외에 쓸데없는
> 구식은 다 아카이빙하든 정리를 좀 하자. 명료하게 짓자고. 너무 커 지금."*

**38만 줄이다. 눈으로 읽을 수 없다.** 그래서 이 문서의 모든 숫자는 기계가 냈다 —
import 그래프를 만들어 각 존의 진짜 진입점에서 도달성을 계산했다. 인상이 아니다.

분석기: `scripts/check-reachability.mjs` · `scripts/check-cycles.mjs` (둘 다 CI 에 걸린다).

> **코어가 무엇인지**는 이 문서가 아니라 [`ARGUS-CORE.md`](./ARGUS-CORE.md) 가 답한다.
> 이 문서는 *무엇이 있나*, 그 문서는 *무엇이 중심인가*.

> **이 청소는 PR 둘로 나뉜다.** `zone-purity` 가드(*한 PR 한 존*, 라이선스 경계)가
> 실재하고 옳으므로 따랐다. 앱 존 청소는 이 PR, MIT 존(`argus-mcp/src/v4` 삭제 ·
> `loop:demo` · 실주행 하루 정정)은 `claude/argus-mit-loop-demo` 다. 아래 숫자는
> **두 PR 을 합친 결과**이고, 각 항목이 어느 쪽인지는 그 자리에 적었다.

## 0. 이 문서를 만들다가 내가 아홉 번 틀렸다 — 그걸 먼저 적는다

`CLAUDE.md`의 *"결함이라 부르기 전에 값을 끝까지 따라간다"* 가 여기서 **아홉 번**
필요했다 — 1차 감사에서 넷, 2차 전수에서 다섯. 아래는 1차의 넷이고, 2차 것까지
합친 전체 목록은 [`ARGUS-CORE.md`](./ARGUS-CORE.md) §6.2 에 아홉 줄 표로 있다.

| 내가 "죽었다"고 판정한 것 | 실제 | 왜 틀렸나 |
|---|---|---|
| `src/app/opengraph-image.tsx` | **살아 있음** | Next 규약 파일인데 내 루트 정규식이 `app/` 최상위를 안 봤다 |
| `argus-mcp/src/v3/` (1,600줄) | **살아 있음** | 앱이 `src/lib/decision-kernel.ts:14`에서 `argus-mcp/dist/v3/reducer.js`를 쓴다. 내 MCP 분석기는 MCP 서버 진입점만 루트로 잡아 **존 경계를 넘는 소비를 못 봤다** |
| `VoyagePhases.tsx` 를 "아무도 언급 안 함"으로 분류 | **가드 테스트가 읽고 있었다** | 그 테스트가 `'../../landing/voyage/VoyagePhases.tsx'` 라는 **상대 경로 문자열**로 읽는다. 절대 경로만 찾던 검사기가 놓쳤고, 지운 뒤 스위트가 빨개져서 잡혔다 |
| `*.d.ts` | **살아 있음** | 앰비언트 타입 선언은 import 되지 않는다 — tsconfig 의 include 가 집는다. 도달성으로 재면 언제나 죽은 것으로 보인다 |

**넷의 공통점 하나: 전부 "참조 0" 을 곧바로 "죽었다"로 읽어서 생겼다.** 참조가
0인 이유는 최소 넷이다 — 규약으로 진입하거나 · 다른 존이 쓰거나 · 문자열로
읽히거나 · 애초에 import 되지 않는 종류이거나.

세 번째는 게이트가 아니라 **테스트 스위트**가 잡았다. 그게 정상이다 — import
그래프는 `readFileSync('...tsx')` 를 볼 수 없고 볼 필요도 없다. 청소의 안전망은
분석기 하나가 아니라 *분석기 + 전체 스위트*이고, 그래서 매 단계마다 양존
스위트를 돌렸다.

두 번째가 특히 위험했다 — v3 를 지웠으면 웹 앱이 빌드에서 죽는다.
(`package.json`의 `prebuild`·`predev`·`pretest`가 전부 `kernel:build`를 먼저 도는
이유가 이것이다.) **그래서 최종 분석기는 존을 가로지르는 import 도 루트로 넣는다.**

## 7. 2차 전수 — 1차가 못 본 것 (같은 날, 창업자 "어떤 것도 놓치지 말자")

1차 감사는 **한 차원(파일 import 도달성) · 두 존(`src/`·`argus-mcp/src/`)**만
봤다. 나머지를 전부 쟀다. 자세한 판정은 [`ARGUS-CORE.md`](./ARGUS-CORE.md) §6.

### 7.1 처음 잰 존 넷

| 존 | 비테스트 | 미도달 | 미도달 줄 | 판정 |
|---|---:|---:|---:|---|
| `argus-plugin-v2/` | 42 | 12 | 4,401 | 대부분 **스킬 마크다운이 셸로 부른다** — `decision-ledger.js` 1,757줄이 그렇다. 살아 있다 |
| `scripts/` | 62 | 34 | 5,711 | 사람이 직접 도는 CLI(`sim/`·`uiux-loop/`). package.json 에 없을 뿐 |
| `argus-mcp/evals/` | 34 | 19 | 3,364 | `gate-coverage.mjs` 가 분류로 관리한다 (이미 있는 게이트) |
| `method-harness/` · `antefact/` · `tools/` | 21 | 6 | 1,190 | 독립 CLI·픽스처 |

**넷 다 "죽은 코드"가 아니다.** import 그래프가 못 보는 호출 방식이었다.

### 7.2 라우트 — 1차 감사의 최대 맹점

`check-reachability.mjs` 는 `page.tsx`·`route.ts` **97개를 전부 진입점으로 둔다.**
그래서 아무도 못 가는 페이지와 아무도 안 부르는 API 가 "살아 있음"으로 보였다.
따로 링크 그래프로 쟀다.

| | 전체 | 열리지 않는 문 | 판정 |
|---|---:|---:|---|
| 페이지 | 31 | 3 | `/design/foundry`·`/design/workspace`(스스로 *"디자인 방향 레퍼런스"*라 선언) · `/admin/utm-builder`. 의도된 내부 도구 |
| API | 66 | 1 | `/api/epistemic/commands` — 파생 기억 제어면의 HTTP 문인데 저장소 안에서 아무도 안 연다. **(a) 미배선** |

나머지는 외부 호출자(텔레그램·Slack·이메일 웹훅 · MCP OAuth 클라이언트)이거나
cron 등록분이다 — 내부 호출처 0이 **정상**이다.

### 7.3 순환 import — 19가 아니라 3이다

처음 세었을 때 19개였다. 그런데 그중 16개는 `import type` 이고 **컴파일에서
지워진다** — 런타임 고리가 아니다. 둘을 합쳐 보고하면 숫자가 6배로 부풀고,
과장된 경보는 꺼진 경보와 같다.

진짜 런타임 순환 셋 중 하나만 중요하다:

```
lib/persona-prompt → lib/context-builder → lib/epistemic/control-plane
                   → lib/epistemic/prompt-renderer → lib/persona-prompt
```

`control-plane` 은 `CLAUDE.md` 가 *"파생 기억의 유일한 권위"* 라 부른 파일인데
프롬프트 조립기와 서로를 부른다. **권위가 고리 안에 있으면 누가 먼저인지 읽어서
알 수 없다.** → `scripts/check-cycles.mjs` 래칫으로 잠갔다 (늘지 않는다).

### 7.4 깨끗했던 것

- **안 쓰는 npm 의존성 0** (앱 36개 · MCP 10개 전부 사용)
- **없는 파일을 가리키는 npm 스크립트 0**
- 플러그인 매니페스트가 둘인 것은 **의도된 이중 스펙**이다 — 루트 것은 host-중립
  `agent-plugins.org` 용이고 전용 적합성 테스트가 읽는다 (그래서 `npx` 실행,
  Claude Code 쪽은 `${CLAUDE_PLUGIN_ROOT}`). 결함으로 적었다가 확인 후 철회.

### 7.5 이번 전수의 결론 — "참조 0" 은 아홉 가지 이유로 생긴다

2차 전수에서 **다섯 번 더 틀렸다**(1차의 넷에 이어). 전부 같은 실수였다:
참조 0을 곧바로 "죽었다"로 읽은 것. 아홉 가지 전체 목록은
[`ARGUS-CORE.md`](./ARGUS-CORE.md) §6.2 에 표로 있고, 그게 이번 감사의 가장
쓸모 있는 산출물이다.

## 8. 재발 방지

이 청소가 필요했던 이유는 **도달 불가를 아무도 안 재고 있었기 때문**이다.
6개월 뒤 같은 문서를 또 쓰지 않으려면 기계가 재야 한다.

→ **`scripts/check-reachability.mjs`** + CI. 새 도달 불가 파일이 생기면 막는다.
→ **`scripts/check-cycles.mjs`** + CI. 런타임 순환 import 가 늘면 막는다
  (타입 순환은 세지 않는다 — §7.3).

기준선은 오늘의 목록이고, 그 목록은 줄기만 하고 늘지 않는다. 둘 다 주입으로
빨간불을 확인했다.

**이것이 없으면 이 문서는 6개월 뒤 또 하나의 낡은 문서가 된다.**
