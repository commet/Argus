## 0. 재검증으로 바뀐 핵심 5가지 (v1 → v2)

1. **P0-1 부여된 진행 = 전면 재설계.** v1의 "idle에서 항해 레일 18% 미리 채우기"는 **가짜 신호**다.
   BindCard 불변식(line 29~34: *"On skip we fake nothing"*)을 위반한다. 아직 밧줄을 안 묶었는데
   "이미 시작함"을 꾸미는 것 = over-fire 거울절(CLAUDE.md). Nunes의 부여된-진행은 *가짜*가 아니라
   **사용자가 방금 만든 진짜 sunk cost**를 비추는 것. → 진짜 레버는 **봉인 순간 + 기록 루프 + 항해
   사다리 미리보기(모양 제시, 진행 아님)**. (부록 A 상세)
2. **P0-2 nav = 컴포넌트 DRY가 아니라 IA 분리.** Header=전역 진입(3개), Sidebar=문맥 도구(전역 항목 제거).
3. **P0-2c 카드 2종 = 스타일 통일이 아니라 레거시 코드 삭제** (먼저 레거시 모드 프로젝트 잔존 여부 grep).
4. **P0-3 Von Restorff = "골드 빼기"가 아니라 위계 규칙** (CTA골드 / 메타데이터 조용한accent / 상태 중립).
   필수 예외(돌아올 배지·로고 브랜드·포커스 링)는 유지.
5. **P1-5 Fitt = 일률 확대 금지.** 빈도×밀도로 차등(자주+밀집한 것만 ≥40px; 헤더는 36px 유지).

라인번호 정정: Sidebar utilityItems **line 20~27**(v1 21~28 오류), 카드 그리드 **550~732**(개별 카드 버튼 579~728),
Button.tsx엔 "gold" 변형 **없음**(변형은 `primary/secondary/ghost/danger/accent`; 골드는 `accent`가
`--gradient-gold`로 씀). 골드 *배지* 변형은 Badge.tsx:14에 **있음**(확인됨).

## P0-3. Von Restorff Effect — 골드 위계 규칙 (선행)

### 진단(확인됨)
`--accent`(골드 #96782e, globals.css:13)가 코드 전반에서 텍스트·밑줄·호버·상태에 과용 = token 과부하.
강조색이 사방이면 아무것도 강조 안 됨.

### 규칙 (이게 핵심 산출물 — 이후 모든 강조 작업의 기준)
- **골드 CTA(채움)**: 화면당 "단 하나의 다음 행동"만. 예) BindCard "이대로 묶기", FinalCard 봉인.
- **조용한 accent 텍스트**: CTA 아닌 메타데이터(역할 라벨, 배정 사유, 레벨)만, ≤12px 소형 문맥에서만.
- **중립 상태표시**: 진행 바·토글·완료 체크는 `--primary`/`--text-secondary`로. (골드 금지)
- **필수 예외(유지)**: 돌아올-결정 배지(Header:148~156, due의 유일 어포던스), 로고 그라디언트(브랜드),
  포커스 링(globals.css:194, 접근성). 이 셋은 골드 유지.

### 변경 대상(확인된 과용처)
- VoyagePhaseRail active 세그먼트 `--gradient-gold`(line 215) → 진행은 중립/primary로.
- Badge `gold` 변형(Badge.tsx:14) 사용처 점검 → "정보/상태"면 default/checkpoint로.
- TeamDeployBanner 레벨/메타 텍스트 accent → tertiary.
- BindCard 인터벌 칩은 active에 `--primary` 사용 중(line 161~169) = **이미 올바름**(예시로 보존).
- **검증 룰**: 주요 화면 스크린샷에서 "골드 채움 CTA가 2개 이상 동시"면 실패.
- **규모 주의**: 이건 토글이 아니라 리팩터. accent 사용처 전수(grep `var(--accent)`) 후 위 규칙으로 분류.

## P0-1. 부여된 진행 효과 — 재설계본 (봉인 보류, 가짜 채움 폐기)

### 진단
Argus엔 인위적 진행 신호가 없다(정확). 그러나 **idle 가짜 채움은 스파인 위반**(위 §0-1).
Nunes 부여된-진행의 원리: *사용자가 방금 만든 진짜 sunk cost*가 완주를 끈다 — 가짜 선반영이 아님.

### 변경 A — 항해 사다리 "모양" 미리보기 (진행 아님)
- **파일**: `VoyagePhaseRail.tsx`
- **현황**: 미래 단계가 faint로 시작(line 273). 사용자가 항해 전체 모양을 못 봄.
- **변경안**: idle/bind에서 **세 단계(묶기→듣기→닿기)를 또렷한 사다리로** 미리 보여주기
  (채움=0 유지, 그러나 "오를 계단의 형태"는 제시). 이건 진행을 거짓말하지 않으면서 방향감을 줌.
- **스파인**: 채움(진행)과 사다리(구조)를 분리. 행동 없으면 진행 0.

### 변경 B — 봉인 순간 = 진짜 부여된-진행 모먼트 (신규, 핵심)
- **파일**: SealMoment / DecisionContract 카드 + 정산(Settlement) 흐름 (구현 전 위치 확정)
- **논거**: 사용자가 밧줄(lean+확인일)을 묶고 봉인하는 순간 = 실제 sunk cost 잠김.
  *여기서* "이 항해를 정산까지 완주하고 싶다"가 생긴다. → 봉인 직후 "닻 내림 1/3 — 확인일에 다시 만나요"
  같은 **실제-행동 기반 진행**을 보여줌(닿기 단계가 실제로 열렸음).
- **스파인**: 전부 실제 행동 반영. 점수/등급 금지.

### 변경 C — 대시보드 기록 루프 (조건부, 정직)
- **파일**: `project/page.tsx` ("나의 기록" line ~454; loops>0일 때만)
- **변경안**: loops==0 + 프로젝트≥1이면 "결정 적기 ✓ → 봉인 → 확인" 3칸 미니맵을 **실제 한 단계만**
  채워 표시(결정을 실제로 적었으므로 첫 칸은 정직). 0개 신규는 빈 상태 CTA 유지 + 같은 맵 프리뷰.
- **스파인**: brand-new 프로젝트(아무것도 안 함)는 점등 금지.

### 변경 D(보류) — 회원가입 단계표시
- 가능하나 압박 위험. **봉인-모먼트(B) 검증 후 재평가**. 한다면 얇은 바 1개로 극절제.

### ⚠ 법칙 상호작용 가드 (P0-1 ↔ P2-8)
"이미 출발했다"(P0-1)와 "아직 안 끝났다"(P2-8 미완 항해)는 **충돌 신호**. 둘이 같은 화면에 동시에
뜨면 안 됨. 진행 신호는 *현재 항해 안*에서만, 미완 신호는 *프로젝트 카드 문맥*에서만 (부록 B 매트릭스).

## 부록 A. 누락된 횡단 카테고리 (9법칙 밖, 그러나 load-bearing)

각 PR에 아래를 **체크리스트로 강제**:

1. **접근성(WCAG AA)**: 포커스 가시·키보드 내비 테스트, **색만으로 의미 전달 금지**(골드=CTA·amber=경고는
