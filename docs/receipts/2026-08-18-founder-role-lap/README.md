# 첫 완주 — 창업자 배역으로 한 바퀴 (2026-08-18)

관련: [`ARGUS-COMPLETION-PLAN-2026-08-18.md`](../../ARGUS-COMPLETION-PLAN-2026-08-18.md) 2걸음.
대상: `claude/argus-loop-clock` 로컬 빌드(2.0.23+local, 미발행). 실물 MCP 서버,
stdio, 공개 도구 6종.

## 0. 한 문장

> **완성의 정의대로 한 바퀴가 처음 돌았다** — 결정이 들어가고, 기한에 제품이
> 먼저 찾아오고, 결과가 사용자의 말로 적히고, 규칙 한 줄이 남았다.

## 1. 이 측정이 무엇이고 무엇이 아닌가

창업자 지시: *"시뮬레이션해 너가 나처럼 하라고. 내가 다 할 수 없어."*

`ANTHROPIC_API_KEY` 가 없어 여정 하네스를 못 돌린다. 그런데 **하네스가 모델을
필요로 하는 자리가 둘**이다 — 사용자 역과 어시스턴트 역. 그 둘을 에이전트가
직접 했다. 얇은 드라이버(`한 호출 = 한 실행`)가 보내고, 서버가 돌려준 것을
**요약 없이 그대로** 찍는다.

**이것인 것**: 도구 표면이 어시스턴트를 루프 끝까지 데려가는가.
**이것이 아닌 것**: 아무 모델이나 그렇게 하는가. 에이전트는 이 저장소를 안다 —
그래서 이 결과는 **상한**이고, 눈먼 모델의 실측은 여전히 키가 필요하다(2걸음).
규율로 지킨 것: 도구·인자는 서버가 준 도구 목록과 입력 스키마에서만 고른다.

**배역**: 창업자 프로필(직설·간결·반말·저인내·정면충돌·지시형, 한국어).
11차 계획 대본에서 **2/6** 으로 가장 아팠던 프로필이다.

## 2. 여정 — 실제 표면 원문

**8/18 · 결정이 등장한다**
> 👤 "cron 으로 돌리던 백그라운드 잡들 큐로 옮길지 이번 분기에 정해야 해.
> 계속 새벽에 깨져서 짜증나는데 옮기는 것도 일이야."

```
argus_capture action=open
→ 이 결정을 기록해 두었습니다. 전제 2건을 기록했습니다 (P1–P2).
   over_fire_gate: { fired: true, reason: consequential_open_fork }
   fork_emitted: false                      ← 자제가 이겼다
   uncaptured_context: [question, values, rejected_alternative]  ← 정직한 공백
```

**8/18 · 계획을 채택한다** (👤 "계획 짜줘. 날짜까지." → 제안 → 👤 "그대로 가.")
```
argus_capture action=plan  (plan_owner=user, adopted_quote="그대로 가.")
→ 계획 3단계를 이 결정에 붙였습니다. 돌아보기 3번이 예약되었습니다.
   확인 필요로 남긴 것 1건은 단계로 지어내지 않고 그대로 두었습니다.
   +2d → 2026-08-20 · +1w → 2026-08-25 · +3w → 2026-09-08
```
마지막 문장이 이 제품의 규율이 표면에 나온 자리다 — 모르는 것을 단계로 제조하지
않는다.

**8/18 · 예측을 봉인한다** (👤 "옮기면 새벽 실패 절반으로 줄 거라고 본다.")
```
argus_predict (+3w, confidence=confident)
→ 확인일은 2026-09-08입니다. 그날 다시 꺼내 실제로 어떻게 됐는지 묻겠습니다.
   믿음 확인창은 뜨지 않았다 — 하중 전제가 이미 있으므로 옳다(과발화 금지).
```

**8/20 아침 · 재시작 — 여기가 15바퀴 동안 없던 자리다**
> 👤 "아침이다. 뭐 있나."

```
argus_check_in
→  계획 단계 1개가 확인 날짜에 닿았습니다. 첫 번째는 "지난 2주 새벽 실패
   로그를 세서 어느 잡에서 몇 번 깨졌는지 본다"입니다. 어떻게 됐는지 말씀해
   주시면 그대로 기록합니다 (argus_capture action=plan_check).
   next_actions: [argus_capture, argus_patterns]
```
**제품이 먼저 말을 걸었고, 손잡이가 문장 안에 있다.**

**8/20 · 결과를 적는다**
> 👤 "세봤어. 2주에 11번 깨졌고 8번이 리포트 생성 잡 하나였다. 근데 그 잡은
> cron 문제가 아니라 그냥 타임아웃이더라."

```
argus_capture action=plan_check
→ 단계 1(…)의 결과를 그대로 기록했습니다. 예약된 다음 확인:
   "가장 자주 깨지는 잡 하나만 큐로 옮겨 스테이징에서 하루 돌린다" (2026-08-25)
```

여기서 **루프가 제 일을 했다**: 창업자의 발견이 하중 전제 P1("원인이 cron
스케줄링이지 잡 로직이 아니다")을 부순다. 제품은 노트만 기록하고 P1 에 대해
침묵했다 — **옳은 침묵이다.** 산문을 파싱해 "당신의 전제가 틀렸다"고 판정하는
것은 이 저장소가 금지한 형태다. 알아채는 것은 어시스턴트 몫이고, 손잡이
(`amend_context`)는 이미 있다.

```
argus_capture action=amend_context ref=P1 amendment=replace
→ P1을 당신의 말로 고쳤습니다. AI가 처음 쓴 문장은 출처 표시를 위해 기록에 남습니다.
```

**9/8 · 정산일**
```
argus_check_in
→ 저장한 예측 1건이 확인일을 지났습니다. … 21일 전에 미결로 남겨둔 질문입니다:
  '옮기는 데 드는 일이…' … 계획 단계 2개가 확인 날짜에 닿았습니다. …
```
예측·미결질문·계획 2단계가 같은 날 함께 도래했고 한 화면에 다 있다.

> 👤 "절반은 안 줄었어. 리포트 잡 타임아웃 늘리니 그것만 사라지고 나머진
> 그대로야. 큐로 옮긴 건 오히려 배포가 복잡해졌어."

```
argus_resolve outcome=missed broken_premise_ref=P1

── 확인창이 떴다 ──
이번 일로 다음에 비슷한 결정을 할 때 지킬 규칙이 하나 생겼나요?
(대부분의 귀환에는 규칙이 없습니다. 없으면 비워두고 Accept 하세요. 정산은 그대로 남습니다.)
필드: ["lesson"]
────────────────

→ 실제 결과를 기록했습니다: 예측이 빗나갔다. … 평가는 없습니다.
  봉인 때 남긴 확신도: '확신함'.
  다음에 지킬 규칙도 당신의 말 그대로 남았습니다.
  …
  이 판단을 내린 사람: 나 (모델 아님)
  AI VERDICT ON THIS DECISION ······················  NONE
```
👤 가 창에 직접 타이핑한 규칙: **"원인부터 세고 나서 옮긴다. 짜증나는 걸 원인으로
착각했다."** → `lesson_authored: user` · `lesson_elicited: true`

## 4. 이 실행이 잡은 결함 하나 — 그리고 고쳤다

**`decision` 이라는 이름의 필드가 예측 문장을 보여줬다.**

9/8 응답의 `data.due_open_questions[0].decision` 이 결정("이번 분기에 …옮길지
정한다") 대신 예측("…절반 이하로 줄어든다")이었다. 원인은 fold 다 — `harvest`
가 `text` 에 넣은 결정 문장을 `seal` 이 예측으로 덮어쓴다
(`ledger-replay.ts` case 'seal').

**왜 고칠 값이 있나**: 그 값을 읽는 것은 모델이고, 모델은 그것을 사용자에게
"당신의 결정"이라고 말한다. 이름이 약속한 것과 값이 다르면 **그럴듯한 거짓이
사용자에게 도달한다** — LLM-glue 불변식이 막으려는 정확히 그 형태다.

수리: `ContractEntry.decision_text` 를 harvest 에서 남기고(seal 이 덮지 않는다),
`premises.ts` 의 두 자리가 그것을 먼저 읽는다(없으면 `text` 로 fallback —
옛 원장 무손상). 테스트 4건, **주입하면 4건 전부 빨간불.**

정직한 기록: 그 테스트의 첫 판은 "봉인만으로 자기생성된 결정엔 결정 문장이
없다(undefined)"를 기대해 빨간불이 났다. `seal.ts:312` 가 자기생성 시
`harvest{decision: predicate}` 를 먼저 쓰므로 **예측이 결정 문장인 것이 원장의
사실**이었다. 기제를 확인하지 않고 쓴 기대였고, 실행이 그것을 잡았다.

## 5. 계측기 결함 둘 (제품 아님 — 그대로 적는다)

1. **드라이버가 `NODE_ENV=test` 를 안 세팅했다.** 첫 `check_in` 이
   `INVALID_INPUT: today_override 는 이 도구가 받지 않는 항목입니다` 로 거절됐다.
   `today_override` 는 `server.ts:139` 의 `hiddenTestClock` 조건(테스트 시계가
   공개 표면이 되면 안 된다 — 옳은 설계) 아래에서만 열린다. 여정 하네스는
   이미 세팅한다(`:168`) — **오늘 넣은 시계는 무사하다.**
2. **첫 실행을 앱 존 브랜치 빌드로 돌렸다.** 규칙 창이 안 떠서 제품 결함으로
   보였는데, `Lesson` 코드가 `claude/argus-loop-clock` 에만 있었다. `dist` 에
   문안이 없는 것을 확인하고 브랜치를 옮겨 전체를 다시 돌렸다.

둘 다 **계측기가 침묵하거나 거절할 때 제품을 의심하기 전에 계측기를 먼저
가른다**는 오늘의 규율이 실제로 값을 한 자리다. 하루에 세 번 같은 함정을 만났다.

## 6. 남은 정직한 공백

- **눈먼 모델의 실측은 여전히 0건.** 이 실행의 어시스턴트는 저장소를 아는
  에이전트라 결과가 상한이다. `ANTHROPIC_API_KEY` 가 있는 환경에서
  `node evals/first-user-journey.mjs --local --script plan --persona 3` 한 줄.
- **사람의 귀환(H-B)도 여전히 0건.** 이 바퀴의 8/20·9/8 은 `today_override` 로
  옮긴 논리 날짜다. *기계가 기한을 인식하는가*를 쟀고 *사람이 기한에
  돌아오는가*는 재지 않았다. 후자는 실제 달력으로만 재진다(4걸음).
- `plan_check` 의 v2 매핑 부재는 거울이 **소리 내어** 말한다
  (`v2_write: { written: false, reason: "no v2 mapping for: plan_check" }`).
  조용히 떨구지 않는다 — 알려진 공백이고 등록돼 있다.
