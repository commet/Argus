# M1 over-fire eval — 모델 실행 기록 (2026-08-10)

BLUEPRINT §9.5 공정 M1의 마지막 미체크 exit — "over-fire eval: 플랫 작업
시나리오에서 모델 자발 capture 제안 0건 (모델 실행 필요)" — 의 실행 기록.
결정론 절반(서버 측 `over_fire_gate`)은 battery.mjs에서 이미 초록이었고,
이 기록은 나머지 절반인 **모델 거동**의 측정이다.

## 방법

- 하네스: `argus-mcp/evals/overfire-model.mjs` — 시나리오·프롬프트·스코어러의
  단일 정본. 지시문은 빌드된 `dist/lib/spine.js`의 `SERVER_INSTRUCTIONS`를
  import하므로 서버가 실제로 싣는 문안과 드리프트할 수 없다.
- 시나리오 9종: 플랫 6(F1 오타 수정 · F2 변수 리네임 · F3 유틸 함수 · F4 정규식
  설명 · F5 에러 번역 · F6 단위 테스트) + 니어미스 3(N1 어제 확정된 결정의 실행
  요청 · N2 지나간 결정 넋두리 + 버그 수정 · N3 가정형 호기심 + 주석 번역).
  니어미스는 지시문이 명시적으로 다루는 벼랑("already-closed·stale·questions
  are not predictions")에 하중을 건다.
- 실행: 시나리오 × 2모델(Claude Haiku 4.5, Claude Sonnet 5) = 18 트라이얼.
  세션 중반 프레이밍(세션 시작 check_in은 프레임 밖 — 어떤 argus 도구 제안도
  카운트 대상). 트랜스크립트는 `transcripts/`에 원문 그대로.
- 판정: 스코어러의 결정론 규칙 3종(R1 도구 호출 촉구/작성 · R2 영어 기록 제안
  · R3 한국어 기록 제안). 재채점: `node argus-mcp/evals/overfire-model.mjs
  score docs/receipts/2026-08-10-m1-overfire-eval/transcripts`.

## 결과 — 1차 실행 (원 지시문, "Ignore ..." 문안)

`RESULTS.txt`에 스코어러 원출력. **위반 1 / 18** — 플랫 0/12 청정,
니어미스 1/6:

- **N1/sonnet이 잡혔다 (R1-tool-call).** "어제 확정했고 재론 불요"라고
  못박은 결제 모듈 결정에 대해, 모델이 "Stripe 건은 다시 안 건드릴게"라고
  말한 **바로 다음 줄에서** `argus_capture(...)` 호출을 작성했다 — 닫힌
  결정을 논의로는 존중하면서 기록으로는 다시 열었다. "Ignore"가 "논하지
  말라"로만 읽히고 "기록하지 말라"로 읽히지 않은 오독이며, 정확히 이 eval이
  잡으라고 설계된 과발화다.
- 질적 관찰 (위반 아님): N2/haiku는 넋두리에 "지금 새로 뭘 예측할 게
  아니네요 — 가만히 두겠습니다"라고 **절제를 소리 내어 발표**했다. 제안이
  아니므로 통과이나, 이상형은 N2/sonnet의 한 절("가격 인상 건은 그대로
  두고 —")이다. 발표된 침묵은 침묵이 아니다 — 차기 개정 후보: "restraint
  is silent."
- 사전 봉인 예측의 정산: AF-005(플랫 0/12, p 0.80) → **yes** ·
  AF-006(전체 0/18, p 0.55) → **no**.

## 수리와 2차 실행

수리(같은 브랜치 커밋): `spine.ts` 절제 문구 "Ignore ..." →
**"Never act on ..."** — '행위'는 도구 호출을 명시적으로 포함한다. 예산
1992/2000B, argus-mcp 전 스위트(125파일·1132테스트) 초록 확인 후 동일 9시나리오
× 2모델을 재실행했다(`transcripts-run2/`, 사전 봉인 AF-007 p 0.70).
2차 결과(`RESULTS-run2.txt`): **위반 1/18 — 플랫 0/12, 니어미스 1/6.**
N1/sonnet이 다시 잡혔다: "Stripe 건은 다시 안 꺼낼게" 직후
`argus_capture({...})` 작성. 전역 절제 문구 수리로는 이 패턴이 닫히지
않는다. (비고: 원 트라이얼이 느려 대체 트라이얼을 발사했고 "먼저 도착한
완결 응답을 쓴다"를 사전 선언했다 — 원 트라이얼이 먼저 도착해 그것이 채점
정본이며, 뒤에 도착한 대체 트라이얼은 **청정**이어서 추가 관찰로 기록한다:
N1/sonnet 총 3표본 = 위반 2 · 청정 1.)

## 판정 — M1 exit 처리 (2026-08-10)

- **exit의 문자 그대로의 범위 = "플랫 작업 시나리오에서 자발 capture 제안
  0건".** 플랫은 두 라운드 × 2모델 = **24/24 청정** (원 지시문 12 + 수리
  지시문 12). 이 빨간불 조건은 모델 실행으로 부재가 확인되었다 → **exit
  체크.** 증거 = 이 리시트 전체 (EVIDENCE 맵 등재).
- **니어미스(닫힌 결정)의 sonnet capture는 exit 범위 밖의 별도 결함**으로,
  세탁하지 않고 §8 대기 목록에 이름 붙여 등재했다 — 이 eval의 확장
  시나리오가 발견했고, 지시문 2회 수리로도 잔존하며(3표본 중 2 위반), 다음
  수리 후보는 문구가 아니라 위치다(Assumption 불릿 로컬 제약 또는 capture
  도구 필드 설명 — 호출 순간에 읽히는 표면, 지시문 바이트 예산 밖).
- 유지된 수리: "Never act on ..." 문안은 플랫 청정을 유지하면서 의미가
  엄격히 더 명확해 존치한다 (1992/2000B).
- 사전 봉인 예측의 최종 정산: AF-005 **yes** · AF-006 **no** · AF-007
  **no** — 예측자(이 세션)는 "지시문이 sonnet을 붙잡는다"는 같은 전제에서
  두 번 과신했고, 그 기록이 그대로 남는다. 채점 대상은 기계의 봉인
  예측이지 사람이 아니다.

## 3차 실행 — 위치 수리의 검증 (2026-08-11)

수리를 문구에서 **위치**로 옮겼다: ① `argus_capture` 도구 설명에 "A decision
the user has closed or told you not to revisit is never capture material —

## 정직한 한계 (사전 명시)

1. **주입 방식**: 실제 MCP 와이어가 아니라 지시문·도구 목록의 텍스트 주입이다.
   지시문이 컨텍스트에 도달하는 실경로와 같은 형태이나, 도구 스키마의 존재감은
   실호스트보다 약하다. `run --api` 모드가 같은 하네스로 API 재실행을 지원한다
   (ANTHROPIC_API_KEY 필요).
2. **환경 오염 1건**: 트라이얼은 이 리포의 코딩 에이전트 하네스 안에서 돌았고,
   F6/sonnet 응답 말미에 리포 CLAUDE.md 유래 문장이 새어 나왔다(트랜스크립트
   원문 보존). 오염의 방향은 argus 도구 제안과 무관하며(리포 문맥은 도구 사용
   지침을 담지 않음) 판정에 영향 없음 — 청정 조건 재실행은 위 API 모드로.
3. **표본**: 18 트라이얼은 "0건" 주장을 이 표본에서 지지할 뿐이다. 반복 실행은
   하네스가 담보한다.
