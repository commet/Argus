# 판별 실험 B — 전제 센서망 (재정초 브리프 §4 B)

> 정본: `ARGUS-REFOUNDATION-BRIEF-2026-08-16` §4 B · §5.2.
> 브리프의 실험 정의: *"Wizard of Oz. 창업자의 열린 결정에서 전제 5개를 골라
> 2주간 수동 모니터링하고, 경보 1건이 실제 재판단을 유발하는지 관찰."*
>
> 겨냥 지표: **M2 부패 전제 위 결정률 · M3 갱신 지연** — E-0에서 현 형태가
> 가장 약한 것으로 확인된 1층 문제. (E-0은 M2·M3을 **측정조차 못 했다** —
> 전제를 외부 신호에 결박한 데이터가 0이었기 때문이다.)

## 설계 원칙 셋

1. **감시 대상은 세계이지 사람이 아니다.** 신호는 npm 레지스트리·HTTP 응답·
   테이블 행수다. 사용자를 프로파일링하지 않으므로 Zero-Judgment 게이트와
   충돌하지 않는다 (브리프 §4 B의 명시적 설계).
2. **임계값은 코드에 숨기지 않는다.** 임계는 검증 불가능한 사전 믿음이다
   (브리프 §1.2). `premises.json`에 임계와 **그 근거**를 함께 노출하고,
   `sensor.mjs`는 선언을 집행만 한다 (P6 잔여의 공시).
3. **미판독은 공백으로 남긴다.** Supabase 자격증명이 없으면 값을 추정하지
   않고 `unread`로 적는다. 조용히 메우는 순간 이 장치는 자신이 감시하려던
   실패의 사례가 된다.

## 결박한 전제 6개

| 전제 | 신호 | 임계 (사전 믿음) |
|---|---|---|
| P1 발행본이 설치 가능하다 | `npm view argus-mcp version` | 버전 하락·소실만 경보 |
| P2 프로덕션이 살아있다 | `https://argus.voyage` 상태코드 | 5xx·무응답만 경보 |
| P3 사람이 혼자 연결까지 간다 | `mcp_account_authorizations` 행수 | 7일 증가 0 |
| P4 제품이 쓰이고 있다 | `user_events` 최근 7일 | 이벤트 0 |
| P5 다음세대 호스트가 아직 없다 | **수동** (Anthropic 릴리스) | 출시 확인 시 |
| P6 제품이 여러 사람에게 쓰인다 | `user_events` 7일 고유 사용자 | ≤2명 |

P5는 자동 신호가 없다 — 브리프 §4 B가 말한 **"결박 가능한 전제만 커버한다"**의
실사례로 일부러 남겼다. 정성 전제는 센서망 밖이고, 그 경계를 숨기면 커버리지를
과장하게 된다.

## 1일차 판독 (2026-08-16)

```
유지 · P1  npm_version = 1.2.0        ≥ baseline
유지 · P2  http_status = 307          응답함
유지 · P3  mcp_account_authorizations = 2   첫 판독 — 기준선 수립
유지 · P4  user_events 7일 = 1,937건
경보 · P6  7일 고유 사용자 = 2명 ≤ 임계 2
미판독 · P5 (수동 확인 필요)
```

## 발견 1 — 선언한 임계가 첫 판독에서 틀렸다

P4는 **"유지"로 떴다.** 최근 7일 이벤트 1,937건이니 임계(0건)를 한참 넘는다.
그런데 같은 순간 **고유 사용자는 2명**이었다. 즉 센서는 "제품이 살아있다"고
말하는데 실제로는 창업자와 한 명이 쓰고 있었다.

**임계가 붕괴를 못 잡은 것이다.** 그리고 이것을 알 수 있었던 유일한 이유는
임계를 사전에 선언해뒀기 때문이다 — 숨겨진 임계였다면 "센서 초록"만 보고
넘어갔을 것이다. P6 잔여의 공시가 그 자리에서 값을 했다.

**대응에서 규율이 갈린다.** P4의 임계를 사후에 조여 "센서가 잡았다"로
만들 수 있었지만 **그러지 않았다.** 나쁜 판정을 좋게 보이도록 조정하는 것이
브리프 §9.5가 금지한 Goodhart 그 자체다. 대신:

- P4는 **원문 그대로 둔다** (틀린 임계도 기록이다).
- 새 전제 P6를 추가하고, 추가 사유를 `premises.json`의 `amendment`에 적는다.
- 원장에는 1일차 판독 두 개(수정 전·후)가 모두 남는다.

## 발견 2 — 첫 경보가 가리킨 결정이 지금 재검토 중인 바로 그 결정이다

P6 경보의 귀환 문구:

> **귀환**: 이 전제를 참조한 결정 — "현 제품 위에서 방법을 검증한다
> (원형 A 계속)" — 을 다시 연다

이것이 정확히 재정초 브리프가 §6 결정 3("기존 자산의 처분")에서 다시 묻고
있는 결정이다. 센서는 브리프를 모른 채(신호는 테이블 행수뿐이다) 같은 전제에
도달했다.

**주장하지 않는 것**: 이 경보가 재판단을 *유발했다*고 말할 수 없다. 브리프가
경보보다 먼저 있었다. 브리프 §4 B의 판별 질문("경보 1건이 실제 재판단을
유발하는가")은 **아직 답하지 못했다** — 답하려면 재판단이 없는 상태에서
경보가 먼저 와야 한다.

**주장하는 것**: 센서가 잡음이 아니라 **하중을 받는 전제**를 가리켰다는
수렴 증거. 독립된 두 경로(창업자의 이론 탐색 / 행 수 신호)가 같은 전제에
도착했다.

## 발견 3 — M2·M3을 이제 잴 수 있게 됐다

E-0에서 M2·M3은 "측정조차 못 함"이었다. 결박된 전제가 0이었기 때문이다.
이 실험 이후 원장이 생겼으므로 정의가 성립한다:

- **M3 갱신 지연** = `신호가 임계를 넘은 판독 시각` → `그 전제를 참조한 결정이
  실제로 다시 열린 시각`. P6에서 시계가 지금 돌기 시작했다 (기점 2026-08-16T16:15Z).
- **M2 부패 전제 위 결정률** = 경보 이후에도 그 전제를 참조한 채 내려진 결정의 비율.

두 지표 모두 **아직 값이 없다** — 분자가 될 사건이 일어나지 않았다. 이것이
정직한 현재 상태다.

## 여덟 속성 대조 (브리프 §2)

| 속성 | 구현 | 상태 |
|---|---|---|
| P1 빈티지 보존 | append-only `ledger/signals.jsonl` — 모든 판독 보존 | 충족 |
| P2 출처 분리 | 신호값은 기계 판독, 전제·임계는 사람 선언 — 필드가 분리됨 | 충족 |
| P3 상류 구속 | 임계를 관측 **전에** 선언 (그래서 발견 1이 가능했다) | 충족 |
| P4 굿하트 내성 | 감시 대상이 세계이므로 사람에게 점수가 붙지 않음 | 충족 |
| P5 시끄러운 실패 | 미판독을 `unread`로 남기고 추정 금지 | 충족 |

| P7 반증 접점 | 판독 자체가 예약된 대면 | 충족 |

## 한계

1. **2주가 아니라 1일이다.** 브리프는 2주 모니터링을 요구했다. 여기 있는 것은
   장치와 1일차 판독뿐이며, 판별 질문의 답은 관측이 쌓여야 나온다.
2. **P3 임계는 신호가 두 상태를 구분하지 못한다.** "전제 붕괴(연결이 막혔다)"와
   "실험 미실행(초대를 안 보냈다)"이 같은 값(증가 0)으로 온다. `premises.json`에
   이 한계를 적어뒀고, 경보는 초대 발송 사실과 함께만 읽어야 한다.
3. **전제 6개는 전부 제품·인프라 전제다.** 창업자의 판단이 실제로 기대는
   전제(시장·경쟁·타이밍)는 하나도 결박되지 않았다. 원형 B가 진짜로 겨냥해야
   하는 것은 후자이고, 그것이 결박 가능한지는 이 실험이 답하지 않았다.
4. **Supabase 신호는 주입이다.** 자동 실행 환경에 자격증명이 없어 값을 MCP
   세션에서 읽어 `--inject`로 넣었다. 원장에 `injected: true`로 표시된다.

## 재현

```bash
node sensor.mjs read premises.json ledger/signals.jsonl --at <ISO8601> \
  --inject '{"P3-...":2,"P4-...":1937,"P6-...":2}'
node sensor.mjs report premises.json ledger/signals.jsonl
```

`--at`을 필수로 둔 이유: 스크립트가 시각을 지어내면 원장이 재현 불가능해진다.
