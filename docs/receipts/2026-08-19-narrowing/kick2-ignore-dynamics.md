# 킥2 — 무시의 역학 (판정: 기각 안 됨 · 설계 원칙 확보 · 후보 1개 정정)

> 기각 조건: 무시→죄책감→이탈 나선을 막는 영수증 있는 설계를 못 찾으면 구현하지 않는다.
> **판정: 찾았다.** 후보 (a)(b)(c) 지지, (d)는 문구 정정 후 지지.

## 조사가 확정한 것

1. **나선은 실재** — 습관 트래커 30일 내 43%·60일 내 92% 중단. 기제는
   what-the-hell effect (한 번 어기면 전면 포기). 그런데 실측의 반전:
   **하루 놓침은 습관 형성에 유의미한 영향이 없다** (Lally 2010) —
   **죄책감은 사실이 아니라 UI가 만든 해석이다.** 빨간 연체 배지가 병인.
2. **용서는 유한해야 작동** — Duolingo 600+ 실험: freeze 2개>1개, 3개는 2개보다
   낫지 않음(무한 용서는 의미 파괴), 복구는 행동으로 되사기(earn-back).
   장기 잔존 +10%, 위험군 이탈 −21% 실측.
3. **부채를 누적 숫자로 절대 안 보임** — Sunsama(연체 빨강 없음, 오늘 것만)가
   이 원칙으로 생존 중인 유료 제품.
4. **반복 무시는 더 큰 알림이 아니라 분류 신호** — MS Research 4만 명: 미루는
   의도는 거의 항상 "돌아올 것"(16%는 매일 미룸). CRM 표준: 30일 무활동 딜
   자동 종결+사유 수집.
5. **자동 정리는 조용히·판정 없이·가역으로, 본인 소유물에만** — Sunsama 자동
   보관(기본 4일, 조정 가능) 선례. 반례가 경계: GitHub stale bot 반발은
   '타인 제출물 + 공개 판정' 맥락 — 1인 도구엔 이식 안 됨.
6. **파산 한 타는 제품화된 관행** — Superhuman "Get Me To Zero" (일괄 보관
   226만 건 사례), Lessig 이메일 파산.

## 후보 (d)의 정정 — 이 조사의 최대 수확

원안 "3회 무시된 결정은 '중요하지 않게 됐다'로 기록 제안"은 **오판정 위험**:
무시자의 의도는 거의 항상 복귀였다(MSR). 제품이 단정하면 stale bot 꼴이 되고
PRODUCT.md 제약("추론 저장 금지")에도 걸린다. **정정판: 휴면 순간에 선택지 제시**
("중요도가 내려갔다 / 시간이 없었다 / 사실상 이미 정산됐다 / 그냥 재워라") —
사용자가 고른 것만 관찰로 저장. 무시=정산의 한 형태라는 프레임은 유지하되
저자는 언제나 사용자.

## 축의 분리 (주 세션 종합과 합치)

**사용자에게는 전부 용서 (유한 용서 + 오늘만 표시 + 파산 + 선택지 휴면),
에이전트에게는 무관용 (결정 위반은 기계가 막음).** 죄책감 축과 구속력 축을
섞으면 죽고 가르면 산다.

## 가장 불리한 발견 (설계 전제로 등재)

용서 장치의 정량 영수증은 전부 **지킬 자산이 이미 있는 사용자**에게서 나왔다 —
예방이지 치료가 아니며, 초기 사용자가 "지키고 싶은 기록"을 갖기 전에는 효과
보장이 없다. **따라서 첫 2주의 잔존은 용서 장치가 아니라 매일의 주입 가치가
든다** — 아침 주입이 정산과 독립적으로 유용해야 한다는 아키텍처 결론.
그리고 (b)와 "정산=우편함" 당김은 직접 실험 수치가 없는 유추 — 자체 계측 없이
성공 주장 금지.
