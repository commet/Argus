# 킥3 — 백지 설계 대조 (판정: 애착 절반 인정 · 개념은 수렴, 기판은 분기)

> 기각 조건: 백지 설계가 "몇백 줄이면 충분"이라 답하면 우리 기계 재사용 서사는
> 애착이다. **결과: 백지는 코어 ~900줄(+MCP ~1,200줄)이라 답했다 — 도구 사용
> 0회의 완전 무오염 설계. 판정: 절반 기각 — 개념은 살고 코드 무게는 애착이었다.**

## 백지가 독립 재발명한 것 (설계의 수렴 검증)

후보함(inbox)과 승격의 분리 · 세션 시작 주입 · 확인일 질문(세션당 3건 상한) ·
점수·등급의 전면 부재 · 승계 링크(superseded:) · "git이 동기화다" ·
Cursor 규칙 파일로 컴파일. — 우리가 상처로 배운 설계를 명세만 보고 다시 그렸다.

## 백지가 우리보다 잘 그린 것

1. **채택의 기계적 강제**: `adopt`는 TTY 대화형 y/n 필수 → 훅·에이전트는
   물리적으로 못 누른다. 저자성을 스키마 필드가 아니라 **입력 장치**로 지킨다
   (우리의 세탁 공격 이력에 대한 더 강한 해답).
2. **결정 1건 = 마크다운 1파일** (YAML 머리 + why + log) — 사람이 에디터로 읽고,
   git이 역사·동기화·병합을 공짜로 주고, 다중 세션 동시 쓰기 충돌이 파일 단위로
   격리된다 (우리 단일 JSONL의 락 문제가 구조적으로 소멸).
3. **check: 필드** — 기계 검증 가능한 결정만 한 줄 명령을 갖는다 (2a의
   "결정론 등록" 발견과 정확히 합치).
4. **인프라가 필요해지는 조건의 명시**: 선별이 필요한 규모 / 둘째 사람 /
   훅 없는 표면 — 셋 중 하나가 오기 전의 인프라는 전부 낭비.

## 백지가 놓친 것 (우리 상처 목록과의 대조)

- 프롬프트 주입 세탁(sanitize) — 우리는 sanitizeForPrompt 를 상처로 배웠다.
- YAML 손편집 파손의 복구 경로.
- "과거 다듬기" 방어를 git 역사에 전적으로 위임 — rebase/amend 로 뚫린다
  (단 1인 로컬에선 위협 모델이 약하고, 커밋 훅으로 보강 가능 — 열린 설계 문제).

## 판정 — 사전 등록과의 대조

주 세션 사전 예상(300~500줄, JSONL)과 백지(~900줄, 파일-퍼-결정)는 규모에서
같은 자릿수, 기판에서 분기했다. **백지의 기판(파일+git)이 새 과녁의 사용자
(다중 세션·에디터 생활자)에게 더 맞다는 쪽으로 기운다.** 결론:

- **개념 이관**: 채택·저자성·만기/재확인·정산·후보/승격·발화 자제 — 전부 생존
  (그리고 백지가 독립 재발명함으로써 검증됨).
- **코드 이관**: 최소 — 커널 28모듈·MCP 도구 6종·이벤트 재생은 새 과녁의 1차
  제품에는 과체중. 기존 코드는 박물관(동결)이 기본값, 증명된 부품(락 교훈·
  sanitize·상태 의미론)만 참조 이식.
- **"기계 전부 재사용, 겨냥만 바꾼다"는 서사는 애착이었다** — 정직하게 철회.
  재사용되는 것은 기계가 아니라 **배운 것**이다.

백지 설계 원문(dec CLI, 스키마 예시, 주차별 순서, 안 짓는 것 목록)은 에이전트
보고 그대로 보존 — v3 계획의 시공 절이 이것을 기초로 삼는다.
