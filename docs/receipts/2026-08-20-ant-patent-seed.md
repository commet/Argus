# 씨앗 — 1624년 독점법과 결정 장부: 창업자 졸업논문이 v3에 주는 것 (2026-08-20 아침)

> **왜 이 문서가 있나.** v3 서명 검토 중에 창업자가 자신의 학부 졸업논문을
> 세션에 올렸다 — 이예찬(2020), 「17-18세기 영국 특허 제도는 유명무실했는가?:
> 연구사(史)와 행위자-네트워크 이론(Actor-Network Theory)의 적용」, 서울대
> 경제학부. 전문을 읽었고, 우연한 연상이 아니라 **v3의 역사적 원형과 경고를
> 담은 문서**로 판정했다. 나중에 독립된 글의 뼈대가 될 수 있어 씨앗으로 남긴다.

## 논문 요지 (한 단락)

1624년 독점법(Statute of Monopolies) 제정 후 1852년 1차 개정까지 약 2세기의
'공백기'는 특허 제도가 유명무실했던 시기가 아니라, **왕실 중심 '특허장(letters
patent)' 네트워크가 의회·법원 중심 '특허법' 네트워크로 교체되며 동맹을
넓혀가던 느린 과정**이었다. 낙관/비관·수요/공급의 이분법으로는 안 보이고,
법·문서·기술 같은 비인간까지 행위자로 놓는 ANT(행위자-네트워크 이론)로 봐야
보인다.

## 경고 하나 — 논문이 v3에게 하는 말

**법의 제정은 동맹으로 반드시 이어지지 않는다.** 1624년에 법은 서명됐지만
판례가 쌓이고(신뢰), 명세서가 정착하고(형식), 대리인이 나타나기(접근성)까지
100년 넘게 발명가들은 그 법을 쓰지 않았다 — 그것이 공백기의 정체라는 게
논문의 논증이다. 옮기면: **`adopted` 서명은 1624년의 순간이지 네트워크의
완성이 아니다.** 관문 0~2와 기각 조건 §9-1(2주 미이행 = 확정 취소)은 "우리의
공백기를 2세기가 아니라 2주로 압축해 판정하겠다"는 장치다.

**진단 지침 (씨앗 B):** 관문 미달 시 "수요 없음"이라는 이분법 판정 전에 —
논문이 선행연구를 비판한 바로 그 지점 — **어느 동맹이 안 맺어졌나**를 먼저
가른다: ① 신뢰(집행 실적이 안 보였나 = 판례 부재) ② 접근성(수집·서명 마찰
= 대리인 부재) ③ 형식(그 사용자의 결정들이 검색키에 안 잡히는 유형 = 명세서
부적합). 셋 다 아니면 그때 수요 문제다. §9를 읽는 해석 지침.

## 기획에 주는 씨앗 셋 (제안 — v3 반영은 창업자 판단)

1. **판례란 (씨앗 A — 가장 반짝임).** 신뢰는 서명 수가 아니라 **집행 사례의
   축적**에서 왔다(판례 축적 전의 법원은 신뢰받지 못했다). 제품화: 결정 파일
   말미에 집행 사건이 덧붙는다 — 언제 위반을 잡았나, 언제 물어왔나, 언제
   정산됐나 (추가 전용, 기계가 기록). 효과 셋: ① 결정마다 자기 실적("이 법이
   3번 막았다")이 보여 제도 신뢰가 자람 ② 90일간 한 번도 안 발화한 결정은
   은퇴 후보(만기 재확인의 데이터 기반) ③ 교환식이 추상 아닌 결정별 영수증이
   됨. **경계**: 결정(정책)의 실적이지 사람 점수가 아니다 — 집계·리더보드
   금지(타락형 2 방어 그대로).
2. **동맹 3분해 진단 지침 (씨앗 B).** 위 경고 절 — §9 미달 판정의 해석 규칙
   한 줄.
3. **주권자의 거부권 계산 (씨앗 C).** 제임스 1세가 거부권을 안 쓴 것은 새
   법이 자기 문제(애매한 독점 남발)를 풀어줬기 때문이다. 옮기면: 벤더가 우리를
   용인·채택할 이유를 설계에 명시한다 — 장부는 벤더의 "규칙 무시" 이슈
   트래커를 줄여주고 에이전트 성능을 올린다(주입받는 에이전트가 더 잘 일함).
   유통·표준 경로(agents.md)의 프레임: **새 법은 옛 주권자의 문제를 풀어줄 때
   통과된다.**

## 2차 씨앗 (같은 날 아침 — 창업자 1차 판정 반영)

**창업자 판정 (2026-08-20):** 집행 기록(구 '판례란') **채택** — 단 '판례'라는
표시 이름은 쓰지 않을 수 있음 / 동맹 3분해 **기각** / 거부권 계산 **기각**(자명)
/ 신규 3종은: 시운전 **강채택**("이거 만드는데 모든 토큰 다 바칠 수 있어") ·
인용 **채택**(과하지 않게 — 체계 필요) · 열린 결정 **채택**.

### 시운전의 실현 가능성 (창업자 질문 — 정직한 답)

- **된다.** 엔진: 2a 백테스트가 같은 코퍼스에서 같은 일을 수동으로 이미 했다
  (검색키·금지값 소급 대조 — 정밀도 67%·recall 100%·실모순 1건 발견). 데이터:
  Claude Code 세션 전사 로컬 JSONL(기본 보존 30일) + git 이력.
- 한계 셋 (표기 규율): ① **"발화했을 것"까지만** — "막았을 것"은 반사실
  단정이라 금지 ② 검색키가 나쁘면 시운전도 나쁘다 — 역으로 시운전이 검색키
  튜닝 루프가 된다 (오탐 다발 = 서명 전에 키를 고치라는 신호) ③ 로그 밖
  위반(다른 기계·지워진 세션)은 못 본다.

### 신규 4 (제안 — 판정 대기)

1. **역이식 온보딩** — `dec init`이 기존 CLAUDE.md·AGENTS.md·.cursorrules를
   후보로 역이식하고 즉시 시운전: "너의 규칙 47개 중 4개가 지난주 실제로
   어겨졌다." 설치 60초 안에 보상 도착(1b 생존 조건). 문장: **"너는 이미 법을
   쓰고 있었다 — 집행이 없었을 뿐."**
2. **법→훅 컴파일** — 금지값 있는 서명 결정을 벤더의 PreToolUse deny 규칙로
   컴파일. 벤더 문서 스스로 "차단은 훅으로"라 안내 — 그들의 집행 원시가 우리의
   컴파일 타깃. 조언(주입)·경고(대조) 위의 물리력 층. 이 저장소의 "pkill claude
   금지" 훅이 원형. → "CLAUDE.md는 컴파일 산출물"이 4갈래가 됨: 주입 텍스트 ·
   grep 감시 · 훅 차단 · Cursor 규칙.
3. **왜의 역참조 (`dec why`)** — 코드·행동의 "왜"를 물으면 장부를 인용하거나
   "기록된 결정 없음"이라 정직하게 답함 (그럴듯한 이유 조작 금지 — LLM-glue
   불변식의 기능화). '없음'이 그 자리에서 후보 생성 입구가 된다.
4. **세션 부검 (`dec autopsy`)** — 산으로 간 세션을 장부에 대조 재생, "법 없이
   지나간 갈림길"을 보여주고 막을 법을 후보로 제안. ASRS 구조 — 사고가 징벌
   없이 입법으로. 화나는 순간 = 입법의 순간.

### 빠른 셋

- **전례 소환**: 새 후보가 은퇴·기존 결정과 유사하면 서명 창에 전례 표시
  ("이 결정, 처음이 아니다 — 06-13 은퇴, 사유 X"). 여섯 번째 어휘 사건의 직접
  해독제.
- **위반이 재확인을 앞당긴다**: 사용자가 같은 법을 N회 무시·우회하면 만기
  전이라도 "이 법 아직 유효한가?" — 신선도를 달력이 아니라 마찰로.
- **빈티지 고정 정산**: 정산 화면은 서명 당시의 원문·출처 인용만 보여줌 —
  사후확신·기억 다시쓰기(E-0 M1 실측 병리)의 기계적 방지.

## 3차 — 창업자 2차 판정 + 설계 답 셋 (같은 날)

**판정:** 역이식 온보딩 **확정** ("설치 첫 60초에 모든 걸 보여줘야 돼 — 이미
쓰던 규칙을 잘 이해하고, 시운전 돌려서 보여주고") · 세션 부검 **확정** ("사고가
징벌 없이 입법이 된다") · 법→훅 컴파일 = 재설명 후 판정 대기 · UI 낱말
**"발화" 기각** — 낱말 대신 순간 자체를 보여준다 ("이 법과 부딪힌 순간 3번"
+ 앞뒤 장면). 집행 기록은 날짜·발화 나열로는 부족 — 앞뒤 맥락 동반 요구.

### 설계 답 1 — 감지기는 키워드 검색이 아니다 (3채널 컴파일러)

- 위반의 대부분은 말이 아니라 **행동**이고, 행동(도구 호출·git diff)은
  구조화된 데이터라 정밀하게 잡힌다. 채널 우선순위: ① 도구 호출(파일 경로·
  명령 패턴 매칭 — 고정밀) ② git diff(닿은 파일·추가된 패턴) ③ 대화
  텍스트(보조 — 유일하게 grep인 채널).
- LLM의 자리는 **컴파일 타임뿐**: 서명 순간에 결정 문장을 {행동 규칙 · 텍스트
  키 · 예외 필터 · 범위}로 컴파일해 **사람에게 보여주고 확인받는다.** 런타임
  판정은 결정론 유지 (불변식 6 그대로 — 유행 기법·임베딩·그래프로 런타임을
  흐리지 않는다).
- **시운전 = 깎는 자리.** 컴파일 → 시운전 → 오탐을 보며 조정 → 서명. 검색키
  품질 게이트가 서명 관문 안에 내장된다 — "잘 깎아야 한다"의 자리가 제품
  안에 있다.

### 설계 답 2 — 맥락은 복사하지 않고 가리킨다 (저장 부담 질문의 답)

- 집행 기록 한 줄 = 요약 1줄 + **포인터**(세션 id·위치·해시, 또는 커밋 SHA).
  열람할 때 포인터를 따라가 원본 로그의 앞뒤 장면을 그 자리에서 펼친다
  (재수화). 평시 저장 부담 0.
- 원본 로그 보존기한(기본 30일)을 넘겨 남길 가치가 **증명된** 순간(정산·
  재확인·분쟁에 실제 쓰인 사건)에만 발췌를 장부로 **승격 저장** — 중요해진
  것만 비용을 낸다. git에 앵커된 사건(커밋 SHA)은 영구 무료.

### 설계 답 3 — 크로스툴 시야 (창업자 요구: codex·claude·cursor 공통)

- 도구별 세션 로그(Claude Code JSONL · Codex 세션 · Cursor 기록)를 공통 사건
  흐름 {말 · 행동 · 변경}으로 정규화하는 **어댑터 층** — 4층 스택의 '어댑터'가
  정확히 이 자리다. 감지기·시운전은 공통 흐름 위에서 한 번만 돈다.
- 어댑터가 아직 없는 도구도 첫날부터 커버되는 공통분모 = **git** (모든 도구가
  결국 커밋으로 수렴 — diff 감시는 도구 무관).

### 훅 컴파일 — 쉬운 판 (재설명)

- 훅 = 에이전트가 행동하기 **직전에 끼어드는 문지기 프로그램.** 에이전트가
  뭐라 판단하든 문지기가 거부하면 실행 자체가 안 된다.
- 3단 비유: **주입 = 벽에 붙인 안내문** (읽고 안 지킬 수 있음) / **대조 =
  경보기** (어기면 울림) / **훅 = 잠긴 문** (아예 못 함).
- 실물이 이 저장소에 이미 있다: "claude 프로세스 죽이지 마라"는 CLAUDE.md에
  글로도 있고(안내문) 훅으로도 걸려 있다(잠긴 문 — `pkill claude`를 치는 순간
  거부됨). "법→훅 컴파일" = 서명하면 그 잠긴 문이 **자동으로 만들어져
  걸리는** 것. 지금은 자물쇠를 짤 줄 아는 사람이 손으로 만들어야 한다.
