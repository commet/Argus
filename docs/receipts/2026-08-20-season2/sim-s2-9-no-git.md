# 시즌2-9 — git 이 없는 기술직 (제품 경계의 시험) · 경계 시뮬

> **이 시뮬이 기각하면 무엇이 무너지나**: §4 305행의 *"어댑터가 없는 도구도
> 첫날부터 커버되는 공통분모 = **git** (코딩 작업은 결국 커밋으로 수렴)"* —
> 그리고 그 위에 선 것 셋: 시운전의 재료 · 집행 기록의 영구 앵커(391행) ·
> 자격 판정의 문구(380행).

**배역**: 윤가람 · 데이터 분석가 겸 SRE. 하루의 대부분을 Jupyter 노트북 ·
SQL 콘솔 · 운영 대시보드 · 온콜 런북에서 보낸다. 코딩 에이전트를 매일 쓰고,
커밋은 주 1~2회이며, 중요한 판단의 대부분은 git 에 흔적을 남기지 않는다.

**규율**: 주장마다 절 번호, 부재는 grep 출력. 결함이라 부르기 전에 생산·저장·
소비·표면 네 자리를 확인한다(CLAUDE.md 2026-08-19 규율). 못 본 자리는
"확인 필요"로 남긴다.

## 1. 확인 1 — 사다리 붕괴 전수

| 층 | 이 사용자에게 | 근거 | 무엇이 사라지나 |
|---|---|---|---|
| **L1 주입** | **남는다.** 단 커버리지 = *에이전트 세션 안에서 보낸 시간* | §4 322행(사다리표) · 313-316행(도구 등급) | 노트북·SQL 콘솔·대시보드·런북에 L1 은 **도달하지 않는다**. 그리고 v4 는 그 비율을 **어디서도 계측하지 않는다** — 관문 1 계측 항목 전수(783행)에 없다 |
| **L2 ① 도구 호출** | **남는다 — 이 사용자의 최우선 채널** | §4 294행("어느 파일을 고쳤나·무슨 명령을 쳤나") | 에이전트를 거친 노트북 편집·쿼리 실행은 파일·명령이라 구조 매칭 대상이다. 그가 직접 친 것은 0 |
| **L2 ② git diff** | **주 1~2건으로 붕괴** | §4 295행 · 시운전 창 146행("건별 서명은 지난 14일") | 건별 시운전 창 14일에 커밋 ≈3건. **아래 결정 5건 중 ②가 유일 근거인 것: 0건** |
| **L2 ③ 대화 텍스트** | 남는다. **단 "실증"이 이 사람에게 전이되지 않는다** | §4 300-302행·323행·747행 vs track2a:20,23,29 | 아래 **발견 2** |
| **L3 훅 차단** | **남는다 — ①과 같은 정의역** | §4 324행 · §4-d ⓕ 702행 | SRE 의 가장 위험한 행위는 명령이라 L3 적합도는 오히려 높다. 단 **그의 터미널·콘솔 UI 에는 안 걸린다** |
| **L4 CI 차단** | **붕괴** | §4 325행 · §6 관문 4 786행(분모 = 결정×PR 쌍) | PR 이 주 1~2건이고 중요한 판단이 그 안에 없다. 분자·분모 둘 다 0 근처 |
| **L5 정산** | **남는다 — v4 에서 유일하게 git 무관한 층** | §4 326행 · 217행 · §12 1163행 | 정산 자체는 무사하다. 무너지는 것은 **정산의 증거 영속성** — 아래 **발견 6** |

**3채널 중 살아남는 것: ①·③ 둘. ②만 붕괴한다.**
프롬프트 가설("텍스트 채널만 남는다")은 **부분 반증**된다 — 붕괴하는 것은
git 채널 하나이고, 구조 채널(①)은 그의 노트북·명령이 **파일과 명령**이라는
이유로 정상 작동한다.

### 발견 1 — §4 305행은 이 사용자에게 **거꾸로** 참이다

*"어댑터가 없는 도구도 첫날부터 커버되는 공통분모 = git"* — 그는 **어댑터가
있는 도구(Claude Code)를 매일 쓰고 git 이 얇다.** §7 872행이 "Codex·Cursor
세션 어댑터"를 관문 1 뒤로 미루며 *"(git 공통분모는 1주차부터 됨)"* 이라
적었는데, 이 사용자의 1주차 커버리지는 git 이 아니라 **Claude Code 세션
기록**이고 **그건 이미 1주차에 있다**(시운전 136행이 "지난 30일의 세션
기록과 git 이력"을 읽는다).

즉 **수리가 필요 없고 문장만 틀렸다.** 공통분모는 도구별로 다르고, v4 는
그중 하나를 보편으로 적었다.

### 발견 2 — v4 가 "텍스트 채널 실증"이라 부른 것의 코퍼스는 **커밋**이다

네 자리 확인:

| 자리 | 무엇 |
|---|---|
| **생산** | track2a 가 "최근 커밋 20개 소급 적용"으로 측정 (track2a:17) |
| **저장** | `track2a-contradiction-backtest.md:20` — D3, 정밀도 67%·recall 100%, 오탐 1~2건/**20커밋** · `:29` 소표본 = **키 1개·커밋 20개·감사 1회** |
| **소비** | v4 300-302행 *"2a가 실증한 것은 **③ 텍스트 채널**이다"* · 323행 사다리표 L2 칸 · 747행 §5 증거 지도 |
| **표면** | §4 사다리표에 "텍스트 채널 **실증**" — 사용자향 표면은 아직 없음(문서 단계) |

track2a 의 **종합 판정** 원문은 되는 영역을 *"(ii) **이후 커밋의 금지값
grep**"* 이라 적었다. 엔진(검색키+금지값 결정론 grep)은 같고 **입력이 커밋된
문서 diff** 였다.

→ 정확한 문장은 "채널을 잘못 표기했다"가 아니라 **"같은 엔진을 다른 코퍼스에
돌린 것을 같은 채널로 표기했다"** 이다. 이 사용자에게 미치는 결과는 구체적:
**②가 붕괴하면 그 위에서 얻은 실증도 같이 붕괴한다.** 그가 받는 ③(세션
기록 grep)은 v4 표에서 유일하게 "실증"이라 적힌 칸인데, **그 코퍼스에서는
미실증**이다.

정직 표기: 300-302행은 이미 "표본 소형"을 적었고 ①②를 "미실증"이라 밝혔다.
이 발견은 그 정직의 **강화**이지 반전이 아니다.

## 2. 확인 2 — 자격 판정이 이 경우를 가르는가

**판정 기준 원문 (§4 처방 7, 378-381행):**

> `init`이 **규칙 파일 0 + git 0 + 세션 기록 0**을 만나면 지어내지 않고
> 돌려보낸다: "이 도구가 읽을 과거와 말 걸 표면이 당신 환경에 없다 — 지금은
> **코딩 에이전트와 git이 있는 사람용이다**." 거절도 설계돼야 거절이다(P5).
> **관문 계측의 오염도 막는다.**

그대로 적용:

| 조건 | 윤가람 | 판정 |
|---|---|---|
| 규칙 파일 0 | 아니오(팀 repo 에 CLAUDE.md 존재 가정) | 미충족 |
| git 0 | **아니오** — 주 1~2 커밋 | 미충족 |
| 세션 기록 0 | 아니오 — 매일 | 미충족 |
| 거절 문구의 자격("코딩 에이전트와 git 이 있는") | **둘 다 있다** | **자격 있음** |

→ **자격 판정은 그를 통과시킨다.** 그리고 통과가 **문자 그대로 옳다** —
그는 정말로 코딩 에이전트와 git 을 둘 다 갖고 있다.

**그런데 §6 관문 2 는 그를 뽑지 않는다** (784행):

> **대상 정직화(시뮬 P2)**: Claude Code 주 사용 + **개인 repo** — **저밀도**·
> 타 도구 혼용 사용자는 아직 우리 시장이 아니라고 기록하고 뽑지 않는다

그는 개인 repo 가 아니고(회사 인프라 repo), 커밋 저밀도다.

### 발견 5 — 두 필터가 다른 축을 쓰고, 이 사용자가 정확히 그 사이에 있다

- **입구(자격 판정)** = **존재 판정**(0 인가 아닌가) — 통과
- **계측(관문 2 모집)** = **밀도 판정**(저밀도인가) — 제외
- 그런데 자격 판정의 **명시 목적**이 *"관문 계측의 오염도 막는다"*(381행)다.
  두 필터가 다른 기준을 쓰면 그 목적이 달성되지 않는다.
- 그리고 그의 판정을 가르는 **유일한 낱말 `저밀도`는 전 문서 1회 등장이고
  정의가 0**이다 (grep 위). **무엇의** 밀도인가 — 커밋? 서명? 세션 시간? —
  가 명세에 없다.

**연속량 위에 이분 게이트를 세우면, 그 게이트는 실망시킬 사용자를 정확히
통과시킨다.** 회색지대가 아니라 **설계된 회색지대**다. 이것이 이 배역의
확인 2 산출이다.

### 제품이 이 사용자에게 정직하게 말해야 하는 문장

§4 313-316행이 이미 그 규율의 전례다 — *"방출된 법은 읽히는 법이지 감시되는
법이 아니다"*. 그 문장의 환경 판이 필요하다. `init` 이 자격을 판정하는 자리
(1주차, 822행)에서:

> 당신 환경을 읽었습니다: 세션 기록 30일 · 커밋 30일에 6건 · 규칙 파일 1개.
> 이 장부는 당신에게 **주입(L1)·세션 안 대조(L2)·훅 차단(L3)·정산(L5)** 로
> 섭니다. **git 사후 감시(L2 diff)와 CI 차단(L4)은 당신 작업에 거의 닿지
> 않습니다** — 당신의 중요한 판단이 커밋에 수렴하지 않기 때문입니다.
> 그리고 하루의 대부분을 보내는 노트북·콘솔·대시보드에는 **이 도구가 아예
> 없습니다.** 거기서 내리는 결정은 당신이 `dec check` 로 물어올 때만 닿습니다.

세 문장이 전부 **거절이 아니라 등급 표기**다. 거절 문구를 바꾸는 것보다
값싸고, 380행의 "거절도 설계돼야 거절이다"의 연장선이다.

## 3. 확인 3 — 주입-전용 법만 남는 제품은 벤더 무료층과 무엇이 다른가

**먼저 전제를 정정한다.** 확인 1 이 보였듯 이 사용자에게 남는 것은
L1+L5 만이 아니라 **L1 · L2①③ · L3 · L5** 다. §9 표에서 벤더가 채운 칸은
**수집** 하나뿐이고, 주입조차 벤더는 "서명·만기·구속·정산 없이" 한다(§2
112-114행). 그러므로 "벤더가 공짜로 주는 층과 같아진다"는 **이 사용자에게는
성립하지 않는다** — 성립하는 것은 더 좁은 문장이다:

> **그의 하루 대부분(에이전트 밖)에는 어느 층도 서지 않는다. 벤더도, 우리도.**

이것은 경쟁 판정이 아니라 **도달 판정**이고, 두 회사가 같은 자리에서 같이
부재한다.

### git 없이 정산이 가능한가 — 재료를 하나씩

정산의 재료(§4 기록 절 386-397행)를 전수:

| 재료 | git 의존 | 이 사용자의 대체물 | 판정 |
|---|---|---|---|
| **만기(달력)** | 없음 | 그대로 | **작동** — 우편함(§12 1163행)의 정의가 "만기 도착 알림"이다 |
| **`check`(검증 명령, 선택 필드 §12 1138행)** | 없음 | `psql -c …` · 사후분석 목록 확인 | **작동 — 단 명세 미결**(아래) |
| **발원 장면 승격**(392-395행, *조건 없이 모든 서명에서 즉시*) | **없음** | 그대로 | **전량 생존.** S2-1·S2-3 이 "의존 1위·복리의 원료"라 부른 그것이 **git 없이 온전하다** |
| **집행 기록 요약 1줄**(386-387행, 파일 말미에 추가 전용) | 없음 | 그대로 | 작동 |
| **집행 기록 포인터**(387-388행: 세션 id·위치·해시 **또는 커밋 SHA**) | 부분 | 세션 id | 30일 보존기한(389행)에 걸린다 |
| **커밋 앵커 = 영구 공짜**(390-391행) | **전면** | **없음** | **붕괴** |
| **교환식 분자**(§12 1160행 + §3 186-188행 + §4-b ⓔ) | 없음 | 사용자가 정산에서 직접 표시 | **작동** — 기계가 추정하지 않으므로 채널 유무와 무관 |

### 발견 6 — 이 배역의 최대 산출: **git 앵커는 보조금이고, 이 사용자는 정가를 낸다**

390-391행 원문: *"…만 발췌를 장부로 승격 저장하고, **커밋에 앵커된 사건은
영구 공짜다**."*

- 커밋이 많은 사용자: 집행 장면이 **git 안에** 영구히 있으므로 승격 비용 0.
- 이 사용자: 앵커가 거의 없으므로 **30일 뒤 남는 것은 요약 1줄뿐**이고,
  장면을 남기려면 **바이트를 직접 사야 한다**.

### (b) 의 반전 — 이 사용자는 첫 영토의 중심인가

§4-b 539행 원문: *"**첫 영토**(정산 경제학 — 최약 고리 응답): 결과가 **CI·
지표·만기일**에 **자동으로 떨어지는** 결정부터."*

**찬성 쪽 — 낱말은 이미 그를 가리킨다.** "지표"가 목록에 있고, 그의 결정
5건 중 결과가 지표(D-9002)와 만기일(D-9002·D-9005)에서 오는 것이 2건이다.

**반대 쪽 — 기제가 없다.** grep 으로 `지표` 13건 전수 확인: 326·424·438·539·
711·745·786·889·892·894·897·973·1039. **539행 하나만이 "결과의 출처"로서의
지표이고, 나머지 12건은 전부 관문 지표·벤더 지표·금지 조항이다.** 정산을

정의된다. 지표를 읽어 들이는 자리는 문서 전체에 0이다.

**판정 — 반전은 참이고, 이유가 v4 의 문장보다 강하다.**

"자동으로 떨어진다"는 **제품이 자동화한다는 뜻이 아니라, 사용자가 결과를
찾으러 가지 않아도 결과가 도착한다는 뜻**이다. 그리고 이 사용자에게는
**그 자동화가 이미 그의 환경에 있다** — 대시보드가 그리고, 경보가 깨우고,
사후분석이 문서화한다. 제품이 할 일은 **제때 묻는 것**(만기)과 **한 줄
받는 것**(영수증)뿐이고, **그 둘은 v4 가 §7 금지선으로 지킨 최소형 정산
그대로다**(815행: *"대조 경보(L2)와 정산 최소형(우편함+영수증)은 자르지
않는다"*).

대조하면: 창업자의 "포지셔닝 결정"은 결과가 **어디에도 자동으로 떨어지지
않는다.** 그러므로 **PRODUCT.md 13행의 1차 쐐기(창업자·제품 책임자의
제품·시장 결정)보다 이 SRE 가 §4-b 첫 영토의 중심에 가깝다.**

**그리고 반전을 밀면 안 되는 이유가 하나 있다 — 우리 자신의 금지 조항.**
정산이 지표를 직접 읽으면 *"이 결정 뒤 p99 가 좋아졌다"* 를 말하고 싶어지고,
그것은 §3 184-188행의 반사실 경계와 §8 974행 **R5**(*반사실 효과 주장
"장애 N건 예방" — 영업 문구로도 금지*)의 정면이다. **지표를 읽지 않고
만기에 묻고 사람이 답하는 현재 설계가, 이 사용자에게 맞으면서 동시에
R5 를 지키는 유일한 형태다.** 즉 **반전은 새 기제를 요구하지 않는다.**

**결과**: v4 가 서명되면 `PRODUCT.md:13` 이 조용히 거짓이 된다. CLAUDE.md 는
*"PRODUCT.md의 제약은 코드 규율보다 위다"* 라 못박았고, v4 자신이 §4-d 에서
잡은 병이 *"자기 자신에게 규율을 반쪽만 적용"* 이었다. **정본 하나를 소리
없이 무효화하는 서명은 같은 병의 세 번째 얼굴이다.**

### 창업자 판정 후보 — 갈래 셋과 각각 무너지는 것 (결정하지 않는다)

**갈래 A — 받는다** (원1 을 "코딩 에이전트를 쓰는 기술직"으로 넓힌다)
- 무너지는 것: 관문 2 모집 기준(784행)이 다시 열려 5명 표본이 이질해진다 →
  관문 2 미달 시 §6 미달 진단 넷(신뢰·접근성·형식·대체재)으로 판정 불능이
  되고 **다섯째(모집단 이질)** 를 붙여야 한다. 그리고 PRODUCT.md·METHOD
  **둘 다 개정 필요**(별도 승인 2건).

**갈래 B — 안 받는다, 그리고 명시적으로 적는다** (784행 대상 정직화의 확장)
- 무너지는 것: §4-b 539행에서 **"지표"를 빼야 한다.** 결과가 지표로
  떨어지는 결정을 내리는 사람을 안 받으면서 지표를 첫 영토에 적어 두는 것은
  §4-d 3 이 방금 고친 병(*읽는 자리 없는 조건*)과 같은 형태다. 그리고 자격
  거절 문구(380행)를 *"코딩 에이전트와 git 이 있는"* → *"…와 **커밋으로
  수렴하는 작업**을 하는"* 으로 좁혀야 한다 — 안 좁히면 그는 계속 통과한다.

**갈래 C — 받되 등급을 표기한다** (도구 등급 정직 표기 313-316행의 환경 판)
- 무너지는 것: 관문 1·2 계측의 분모가 **환경별로 달라져** 5명 평균이 의미를
  잃는다 → 관문 2 통과 기준을 환경 등급별로 쪼개야 하고 값이 싸지 않다.
  그리고 §4-d ⓘ 의 "주입-전용 법 비율"이 **엔진 신호와 환경 신호로 뒤섞여**
  비율 상승의 해석이 불가능해진다(§6 783행이 그 비율을 "대조 엔진이 실제로
  못 잡는 영역이 커지는 신호"로 읽기로 사전등록했는데, 환경 이질이 섞이면
  그 독법이 깨진다).

**어디에 적는가**: 이 판정은 계측 기준(§6)이 아니라 **정본 문제**다 —
PRODUCT.md·METHOD 개정이 걸려 있으므로 §11 창업자 판정 사항(현재 6건)의
**일곱째**로 올린다. §6 관문 2 가 대상 정직화를 §6 안에서 처리한 전례가
있지만, 그때는 정본 개정이 안 걸렸다.

## 6. BLUE — 이 사용자가 남는다면 그 이유

형식: *"그날 그 화면이 없었으면 나는 X 를 했다"* + 참이어야 했던 조건 전부에
실현 가능성 판정.

### BLUE 1 — 온콜 인수인계, 화요일 09:00

> 그날 그 화면이 없었으면 나는 **`cache_hit_rate` 94% 를 근거로 "캐시 계층은
> 건강하다"고 인수인계했다.** 인수받은 사람은 그 숫자로 3일을 갔을 것이다.

있었던 것: 인수인계 직전 `dec brief` 가 지형을 내며 D-9004(ban, 그 패널
불신)를 **`open` 다음 자리**에 놓았다(§4-c 2 562-564행: *"읽기 순서를 자산
순으로 뒤집는다"*).

| 참이어야 했던 조건 | 판정 |
|---|---|
| 1. D-9004 가 8/13 에 실제로 서명돼 있었을 것 | **가능** — 확실 후보 2.3건/일 실측(track2b)이 그날 발화를 잡는다. 단 표본은 **창업자 1인 6일** |
| 2. `dec brief` 가 그날 존재할 것 | **그 시점엔 불가** — 878행: `dec brief` 는 **관문 2 전**에 들어간다. 이 장면은 관문 1 뒤에만 성립 |
| 3. 인수인계가 이 도구가 닿는 표면에서 일어날 것 | **불확실 — 확인 필요.** 그의 인수인계는 런북·슬랙일 가능성이 높고, `런북` grep = **0건**, 방출 대상에 없다 |

**판정: 조건 3 중 1 만 지금 참.** 이 BLUE 는 관문 1 뒤 + 표면 하나 추가가
전제다. 프롬프트가 후보로 지목했지만 **가장 약한 BLUE 다.**

### BLUE 2 — 6개월 뒤 같은 장애, 새벽 02:50

> 그날 그 파일이 없었으면 나는 **p99 임계를 다시 500 으로 내렸다.** 6개월 전
> 800 으로 올린 이유가 *배포창 오탐 억제이지 SLO 완화가 아니었다*는 것을
> 잊었으므로. 그 이유는 슬랙 스크롤 밖이고 세션 기록 보존기한 밖이다.

있었던 것: D-9002 의 `source` 에 **서명 순간 승격된 3줄** + `decision` 본문의
*"이유는 오탐 억제이지 SLO 완화가 아니다"*.

| 참이어야 했던 조건 | 판정 |
|---|---|
| 1. 발원 장면 승격이 **조건 없이 모든 서명에** 걸릴 것 | **참.** 392-395행(시즌2 개정)이 이미 그렇게 만들었고 §7 864행 금지선에 들어가 있다. **git 무관** |
| 2. 그것을 읽는 동사가 있을 것 | **동사는 없고 파일은 열린다.** `dec why` 는 관문 1 뒤(872행). 그 전까지는 **불변식 ①(도구 없이 읽히는 평문)이 값을 낸다** — 이것이 ①의 이 사용자용 현금화 |
| 3. 6개월 뒤 그 결정이 아직 읽히는 자리에 있을 것 | **확인 필요.** D-9002 는 9/20 만기이고 정산 뒤 은퇴하면 파일은 남지만 활성이 아니다. **은퇴한 결정의 열람 규칙이 명세에 없다** — grep `은퇴` 9건 중 열람 규칙 0건(전례 소환 245-246행이 유일한 근접물이고 그것도 관문 1 뒤) |

**판정: 핵심 조건(1)이 이미 참이고 git 을 요구하지 않는다.** 그리고 이 자리는
**S2-4 의 BLUE 와 정확히 같은 자리**다(README-round2 §3: *"새벽 02:50, 벤더
콘솔엔 결정과 날짜는 있는데 왜가 없다"*). **다른 배역이 다른 위협에서 도착한
같은 자리이고, 그 자리에는 git 이 필요 없다.** 이것이 이 사용자가 남는
가장 단단한 이유다.

### BLUE 3 — 내가 찾은 셋째 (프롬프트가 주지 않은 것)

> 그날 그 주입이 없었으면 나는 **에이전트가 "PagerDuty 라우팅에 붙였습니다"라고
> 한 것을 그냥 승인했다** — 그리고 **정책이 스키마를 따라가는 순서**가 됐다.

D-9005(`open`)가 주입돼 있어 에이전트가 확정으로 취급하지 않고 되물었다.
이것은 S2-1 이 §4-c 1 로 만든 장면(*"내가 아직 안 정한 것을 남이 정하고
있다"*)의 **1인 판**이다 — 남의 PR 이 아니라 자기 에이전트에서.

| 참이어야 했던 조건 | 판정 |
|---|---|
| 1. `open` 이 1주차에 있을 것 | **참**(827-828행, 1주차로 당겨짐) |
| 2. 에이전트가 주입된 `open` 을 읽고 실제로 abstain 할 것 | **미실증 — 이 계획 전체에서 가장 빈 자리.** `abstain` grep = 2건, 둘 다 §4-d 4 / §12 의 **명세 문장**이고 구현 0. round2 자기 표기 그대로: *"명세를 공격했고 명세에는 구현이 없다 — 그 공백을 채우는 것은 LLM 이다"* |

**판정: 조건 1 은 참, 조건 2 는 이 문서가 가진 가장 큰 미지수.** 그리고
`open` 은 **이 사용자에게 git 을 전혀 요구하지 않는 유일한 완결 기능**이다.

### 1. 주입-전용 법에 달력 만기 강제 — **A · 1줄**

수리 문장: *"컴파일 결과가 주입-전용이면 그 법은 사건형 재확인을 고를 수
없다 — 감지가 0 인 법에 사건은 오지 않으므로 달력 만기를 요구한다."*
(처방 6(d) 490-491행의 **출생 판**.)

**반영하지 말아야 할 이유 (자기반론)**: 408행이 *"달력 심문으로 영구 규칙을
괴롭히는 것"* 을 시뮬 P1·P2 가 잡은 자기모순이라 불렀다. 이 수리가 **그 병을
되살린다** — D-9003 같은 영구 규율("롤백 먼저")에 90일마다 만기를 물리는
것이 정확히 그것이다. 대안(주입 N회마다 재확인)은 **새 문법**이라 값이 싸지
않다. 그리고 **이 사용자를 안 받기로 하면(갈래 B) 주입-전용 비율이 낮게
유지되어 코너 케이스로 남는다** — 사전등록 예측 2 가 그 갈림길의 시험이다.
**즉 이 제안은 예측 2 의 결과를 기다릴 수 있다.**

### 2. §11 ⑤에 Users 복원 — **A · 2낱말**

**반영하지 말아야 할 이유**: 37행이 *"서명이 비준하는 것은 이 계획의 채택
뿐"* 이라 명시했고 6묶음은 각각 별도 승인이므로, 목록에 넣어도 승인은 따로다
→ 실질 변화 없음. **반박**: 목록이 곧 의제다 — 목록에 없으면 승인 요청이
발생하지 않는다. **그러나 진짜 반론은 다른 것이다**: track4 개정-5 가
살아 있는 리시트이므로 v4 를 안 고쳐도 그 묶음은 보관돼 있다. **v4 본문
무게를 늘리지 않는 쪽을 택할 수 있고, 그 선택도 방어 가능하다.**

### 3. `dec check` 의 주어 확장 — **A · 1낱말**

§12 1279행 원문: *"**에이전트가** 작업 직전에 '이 계획에 걸리는 법이 있나'를
**묻는** 동사"*. 이 사용자에게 필요한 것은 **사람이 아무 표면에서나 묻는
것** — 대시보드에서 임계값을 바꾸기 직전에 터미널에서
`dec check "결제 p99 임계 800 으로"`. **그것이 그의 하루 대부분(에이전트
밖)에 사다리가 닿는 유일한 경로이고, 이미 1주차에 있다**(825행).

**반영하지 말아야 할 이유**: 사람이 부르는 pull 은 **사람이 기억해야 부른다** —
무덤 부검(track1b)의 α(기록 비용)가 정확히 거기서 죽었다. 사람 pull 을
주 동선으로 만들면 *"성실한 사용자만 값을 받는"* 제품이 되고, v4 가 §3 에서
공들여 만든 "마찰 0 수확"의 반대다. 그리고 **두 용도(에이전트 abstain 채널 /
사람 사전 조회)가 한 동사에 얹히면 §6 계측 항목도 섞인다.**
→ **그래서 제안을 "주어를 넓힌다"까지만 하고 "주 동선으로 만든다"는 하지
않는다.**

### 4. 코퍼스 표기 — **B · 2줄**

**반영하지 말아야 할 이유**: 300-302행이 이미 "표본 소형"과 "①②는 미실증"을
정직하게 적었으므로 과잉 진단일 수 있다. 더 무거운 반론: 이 정정이 §5 증거
지도의 **유일한 "실증됨" 행**을 약화시키는데, 그 행은 §10-8(감지기 오탐
축소 조건)의 근거이기도 하다. **근거만 약화시키고 축소 조건을 그대로 두면
문서가 더 흔들린다** — 정정하려면 §10-8 도 같이 봐야 하고, 그러면 값이
싸지 않다.

### 5. 보조금 표기 — **B · 1줄**

**반영하지 말아야 할 이유**: 이건 수리가 아니라 표기이고, 표기만 늘리면
문서 무게만 는다. 그리고 **§4-d ⓘ 의 "주입-전용 법 비율" 계측이 이미
비슷한 신호를 잡는다** — 새 문장 없이 관문 1 계측이 드러낼 수 있다.

### 6. `저밀도` 정의 — **B · 낱말 몇 개**

**숫자를 박지 않는다.** 나는 표본 0 이고 "주 커밋 5건" 같은 숫자를 넣으면
v4 가 §5 에서 지킨 규율(*"작은 표본의 숫자는 방향의 증거이지 크기의 증거가
아니다"*)을 어긴다. **무엇의 밀도인지만 적는다** — 커밋인가, 서명인가,
에이전트 세션 시간인가.

**반영하지 말아야 할 이유**: 셋 중 무엇을 고르든 그것이 **모집 기준이자
사실상의 시장 정의**가 되는데, 그 판정은 §11 로 올라가야 할 종류다(위 확인
5). §6 에서 낱말로 처리하면 정본 개정 없이 시장이 정해진다 — **이 배역이
발견 8 에서 비판한 바로 그 형태다.**

## 8. 사전등록 예측 (확인·반증 가능 · 숫자 포함)

**예측 1 — 관문 2 (5명 × 2주).** 784행 기준으로 뽑은 5명에 대해 (주 서명 수,
주 커밋 수) 5쌍을 기록했을 때, **둘의 순위 상관은 |ρ| < 0.5** 일 것이다.
- 참이면: git 밀도는 자격 변수가 아니고 갈래 A·C 가 열린다.
- 반증되면(ρ ≥ 0.5): git 밀도가 실제 자격 변수이고 **갈래 B 의 근거**가 된다.
- 계측 비용: 이미 1인당 지표를 받으므로 **열 하나 추가.**

**예측 2 — 관문 1 (창업자 4주 창).** 서명된 법 중 **주입-전용 비율(§6 783행
계측 항목)이 30% 이상**일 것이다.
- 근거: 190-192행이 예로 든 *"결함이라 부르기 전에 네 자리 확인"* 이 이
  저장소 CLAUDE.md 의 실물이고, 그 문서의 규율 다수가 같은 종류다.
- 30% 이상이면 **발견 3 은 주류**이고 제안 1 이 관문 1 전에 필요하다.
- 30% 미만이면 발견 3 을 코너 케이스로 강등하고 제안 1 을 보류한다.

**예측 3 — 관문 2 종료 시.** 5명이 쓴 `check` 필드 전수를 "그대로 실행
가능한 명령인가"로 이분할 때, **문장(비명령)이 최소 1명·최소 2건** 나올
것이다.
- 근거: **v4 자신의 머리 블록 19행이 이미 문장이다**(*"…원자료가 실재하는가"*)
  — 저자가 그렇게 쓴 필드는 사용자도 그렇게 쓴다.
- 2명 이상이면 §12 1138행의 `check`(**검증 명령**) 정의가 실사용과 어긋나는
  것이고, 첫 영토의 *"자동으로 떨어진다"* 는 **사람 확인으로 물러난다** —
  그것이 위 반전(§4)의 기제 쪽 확인이다.
- 계측 비용: 관문 2 종료 시 `check` 필드 전수 1회 분류.

## 9. 내가 확인하지 않은 것

1. **윤가람의 환경 자체.** 그의 노트북이 파일 시스템의 `.ipynb` 인지, 임계값이
   yaml 인지 대시보드 UI 인지, 에이전트가 Claude Code 인지 — **전부 배역
   설정에서 온 가정이다.** D-9002 의 컴파일 가능 여부가 통째로 여기 걸려 있고,
   나는 그것을 "환경 의존"이라 적었지 판정하지 않았다.
2. **`.ipynb` 의 diff 성질.** "노트북은 git diff 로 안 읽힌다"는 통념을
   검증하지 않았다 — `find . -name "*.ipynb"` = **0건**이라 이 저장소에서는
   확인 불가.
3. **대화 인용이 집행 기록으로 남는지** (발견 4 의 강도가 여기 걸려 있다).
   포인터에 "세션 id"가 있어 여지는 있으나 205행의 대화 인용이 기록되는지는
   명세에 없다. **의문으로 남기고 수리를 쌓지 않았다.**
4. **은퇴한 결정의 열람 규칙** (BLUE 2 의 조건 3). grep `은퇴` 9건 중 열람
   규칙 0건.
5. **`check` 필드의 정본 의미론.** §12 는 "검증 명령", 머리 19행은 문장.
   어느 쪽이 정본인지 확인하지 못했다 — 예측 3 이 이것의 시험이다.
6. **관문 1 계측에 "에이전트 세션 안에서 보낸 시간"이 없다는 것의 의미.**
   783행 전수를 읽었고 없는 것은 확인했으나, 그것이 결함인지(L1 커버리지
   미계측) 의도인지(창업자 1인은 항상 세션 안에 있으므로 무의미) 가르지
   못했다.
7. **구현.** 이 저장소에 v4 의 코드는 0줄이다. 지난 라운드의 한계(*"명세를
   공격했고 명세에는 구현이 없다"*)를 나도 완전히는 벗어나지 못했다.
   **좁힌 것**: grep 으로 결정 가능한 것 — 발견 1·2·3·5·8 과 결정 5건의
   채널 배치. **못 좁힌 것**: 컴파일러가 실제로 무엇을 잡는가 — 발견 4·6 의
   강도, BLUE 3 의 조건 2.

## 10. 한 줄 판정

> **이 사용자는 "우리 시장이 아니다"가 아니라 "우리 문서 넷이 서로 다른
> 답을 주는 자리"다.** git 이 없어서 무너지는 것은 사다리 다섯 층이 아니라
> **한 채널(②)과 한 층(L4), 그리고 집행 증거의 해상도**이고, 남는 것 —
> `open` · 발원 장면 · 만기 · 사람이 답하는 정산 — 은 **v4 가 벤더에게 없다고
> 적은 것 전부**다. 경계는 제품이 그를 못 도와서가 아니라, **그의 하루
> 대부분에 어느 도구도 서지 않기 때문에** 그어진다.
