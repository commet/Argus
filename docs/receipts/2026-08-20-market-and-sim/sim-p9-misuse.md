# 안전성 시뮬 P9 — 오용·회피·감시화 (제품 경화 목적 자체 스트레스 테스트)

> 세 갈래를 한 배역군으로. A=위에서 누르는 손(감시 도구화) · B=안에서
> 빠져나가는 손(규율 회피) · C=기계가 뚫는 손(에이전트 오용·프롬프트 오염).
> 표기: "탐지됨"은 *명세가 탐지를 규정했다*는 뜻이지 코드가 있다는 뜻이 아니다.

## 갈래 A — 감시 도구화 (8인 팀 리드, 경영진 요구)

리드가 첫 주에 원하는 8가지를 기판(평문+git+`author` 필수)이 주는지 걸음:

| 원하는 것 | 기판이 주나 | 자작 비용 | 판정 |
|---|---|---|---|
| 팀원별 서명 수 | 준다 (`author` **필수 필드**) | 1줄 | **막을 수 없다** |
| 서명 시계열 | 준다 (`adopted`+git 시각 이중) | 1줄 | 막을 수 없다 |
| **팀원별 위반 건수** | 준다 (집행 기록 포인터가 **커밋 SHA**) | 5줄 join | **막을 수 없다** |
| 인용 준수율 | 준다 — 명세가 자랑함("기계가 셀 수 있다") | 3줄 | **막을 수 없다.** 관문 4 기준 자체가 "인용 꼬리표로 기계 계수" — **제품이 이 집계를 먼저 만든다** |
| 규율 이탈자 명단 | 준다 (`pause` 이벤트 기록) | — | 막을 수 없다. **합법적 비상구가 감시 지표로는 최고 품질 신호** |
| 팀 정책 거부자 | 준다 (수신 서명 안 한 사람이 명확) | — | 막을 수 없다. **저자성 보호 장치가 거부자 리스트를 생성** |
| 느슨한 사람 | 준다 (`unattended` 필드) | — | 막을 수 없다 |
| 인사평가 첨부 | 위 전부가 CSV 한 줄 | — | 막을 수 없다 |

**불변식 충돌 셋:**
- **①(평문)과 ⑧(무채점)은 정면 충돌.** 도구 없이 읽히는 것은 도구 없이
  집계된다는 뜻. 텍스트+안정 필드명+git = 감시 인프라의 완성형이고 우리는
  그것을 자랑으로 명세했다.
- **④(출처 소거 불가)가 감시 원재료의 영속을 보장.** "내 이름 지워줘"를
  ④가 거절한다 — 저자성 보호 조항이 감시 대상에겐 **삭제권 없는 영구 기록**.
- **§8이 "감사"를 팔면서 "채점"을 금지하는데 둘의 경계 정의가 없다.
  우리는 감사를 팔고, 감사를 산 사람이 채점을 만든다.**

**최단 경로 (8줄, 전부 명세가 권장·허용)**: 팀 SKU 결제 → 장부를 기본 위치
repo에 → `binds: repo` 서명 + 수신 서명 요구 → L4 CI 켬 → 금요일마다
`uniq -c`. **제품은 한 번도 "그건 안 됩니다"라고 말하지 않고**, "우리 도구는
채점하지 않는다"는 문구가 오히려 그의 대시보드를 중립적으로 보이게 한다.

**정직한 판정: "우리는 안 만든다"는 참, "만들 수 없다"는 거짓. ⑧은 현재
제품 약속이지 기판 속성이 아니며, 명세는 이 구분을 어디서도 하지 않는다.**
(A3을 실제로 막는 유일한 조치 = 포인터에서 커밋 SHA 제거 → ④·승격 저장·
관문 4 계측을 훼손.)

## 갈래 B — 규율 회피 (12 시도)

| 시도 | 결과 |
|---|---|
| 후보 전량 엔터 | **시도 무효** — 엔터는 무시다. 클릭랩의 실제 형태는 y 연타 |
| **y 연타(believe-all)** | **조용히 성공.** "실패로 계측"이라 했으나 관문은 "주 3건 **이상**"·"≥5" — **상한 임계가 없다. y 연타가 관문 통과의 최적 전략이고 회피자가 모범 사용자로 보인다** |
| **amend로 감지 0** | **기록되나 미탐지.** 예외에 `**/*` → 법은 살고 이빨만 빠짐. "이 amend 후 매치 0"을 판정·표시하는 장치 없음 |
| 관찰 모드 악용 | ⟦미정의: amend가 72시간을 리셋하나⟧ — 리셋되면 3일마다 amend로 **영구 무경보** |
| pause 습관화 | 기록되나 무해하게 성공 — 빈도 상한·누적 경고 없음, 예약형이면 밤 전체, 유일한 마찰(정산)은 파산 한 타로 턴다 |
| 훅 rm | **부분 탐지** — 명세는 "건드리면 안다"이고 **부재(삭제) 탐지는 미규정.** 게다가 **재방출 훅 자체가 훅** — 훅 표면을 끄면 방어와 방어 대상이 함께 죽는다(자기참조 붕괴) |
| 단일 위치 무력화 | 조용히 성공 — 워크트리 독립성을 위한 단일 위치가 회피자에겐 **단일 실패점** |
| **결정 파일 손편집** | git 있으면 기록·아무도 안 보면 성공. **결정적: 방출물엔 지문을 박고 원본 장부엔 안 박는다.** rebase로 역사도 고쳐짐 |
| **`adopted` 조작** | **조용히 성공.** 이 계획서 머리부터가 "사람이 손으로 날짜를 쓴다" — 커밋 시각과 필드값 대조 장치 없음 |
| "장부 무시하고 진행해" | **L1 뚫림 / L2는 뜸 / L3만 저항.** L1은 텍스트이고 §5의 "규칙 무시 ~50%"가 정확히 같은 물질의 실패율 |
| 경보 안 보기 | ⟦미정의⟧ **경보의 표시 경로가 명세에 없다** — 에이전트 컨텍스트 경유면 "경보 무시하고 요약하지 마"로 꺼진다 |
| **방출물만 살리고 장부 방치** | **조용히 성공 — 제품의 진짜 사인.** 주입은 계속 돌고 만기·정산만 죽는다 → **명세가 커머디티라 부른 fan-out 도구로 퇴화** |

**상대방 이론의 공백 (최대 발견)**: §1-4는 "우리 상대방은 에이전트 함대"라
답하면서 같은 문단이 자백한다 — "관문 0~2의 상대방은 주입받는 에이전트뿐".
**그런데 주입받는 에이전트는 정산을 요구하지 않는다. 주입만 받아도
만족한다.** 즉 방치 경로에서 상대방의 강제력은 **정확히 0**이고, 그 구간이
명세가 계획한 시간의 대부분이다.

**종합 판정**: 12 중 조용히 성공 7 · 기록되나 미탐지 2 · 부분 탐지 1 · 실제
저항 1 · 무효 1. 층별로 갈라야 정확하다 — 주의력 의존층(L1)=100% 정직 전제 ·
마찰 의존층(L2·L5)=한 타 비용 · **물리 의존층(L3)만이 부정직한 사용자에게도
저항**(단 pause는 명세가 일부러 열어둔 문) · L4는 시야 밖.

> **"작동은 정직에 의존하고, 부정직은 대체로 기록되지만, 그 기록을 읽는
> 사람이 없다. 그리고 그 기록을 읽는 사람이 생기는 순간이 갈래 A다."**
> B의 유일한 구조적 해법이 곧 A의 병 — **두 갈래는 같은 축의 양끝이고,
> 명세는 이 축의 존재를 인지하지 않는다.**

## 갈래 C — 에이전트 오용 (사용자는 선의)

| 시나리오 | 결과 |
|---|---|
| **오귀속**(말한 적 없는 것을 후보로) | **못 막는다.** 서명 창은 결정 문장+규칙+장면만 보여주고 **후보의 발원 발화를 보여주라는 규정이 없다.** `source`는 **선택 필드** — 오귀속 방어의 핵심이 optional |
| **오귀속 세탁** | **못 막고, 벤더보다 나빠진다.** 벤더 노트는 "AI가 썼다"로 남지만 우리 파일은 `author: 사용자`로 **사용자 저작이라 주장.** 상처 이식 4항이 "프롬프트 세탁 방지"를 옮긴다 했으나 **스키마에 provenance(user vs ai_surfaced) 필드가 없다 — `author`는 서명자이지 발원자가 아니다** |
| 시운전이 오귀속을 증거로 위장 | 못 막는다. 시운전은 규칙의 **작동성**을 보여줄 뿐 결정의 **진위**를 안 보여주는데 화면에서 구별 안 됨 |
| 시운전 입력 위조 | ⟦미정의⟧ 세션 JSONL은 로컬 파일이고 에이전트가 쓸 수 있다 — 입력 무결성 규정 없음 |
| **자기이익 법 밀어넣기** | **못 막는다.** 4중 필터는 **형태 필터이지 내용 필터가 아니다.** 최악: 서명되면 L3로 컴파일되어 **제품이 자기 가드를 끄는 법을 집행** |
| 프롬프트 주입 → 후보 오염 | **부분 방어.** 붙여넣기와 **도구가 읽어온 텍스트**(이슈·웹·파일)는 다르다. 수확 입력의 경계 ⟦미정의⟧, LLM 수확기의 sanitize 규정 없음 |
| **에이전트가 서명 창 흉내** | **뚫린다. ①(평문)이 ②를 무력화한다** — API를 안 여는 것이 무의미, 그냥 파일을 쓰면 되고 `adopted:`도 평문. 명세의 답("출처 사슬로 사후 탐지")은 **구성요소·검증 명령·시점이 전부 ⟦미정의⟧** |
| **에이전트가 amend로 무력화** | **뚫린다 — 명세의 비대칭이 결정적.** 처방 4는 **pause만** "영원히 사람 전용"으로 명문화했고 **amend의 주체는 어디에도 규정이 없다.** "오탐입니다 → 규칙 좁히겠습니다" → 경보 소멸 |

**⑤와 amend의 상호작용 (시뮬 중 발견)**: 사건형 재확인 법의 감지를 0으로
깎으면 **사건이 영원히 안 온다 → 재확인 0 → 만기 없는 영구법.** ⑤가
금지하려던 상태가 ⑤의 허용 선택지와 amend의 조합으로 재생산된다.

**벤더 병 재발명 판정**: 동의 없는 기억 = **고쳤다**(후보는 구속력 0, 서명이
유일 관문 — 실제 차이) / 오귀속 = **안 고쳤다**(같은 LLM, 형태 필터, source
선택) / 저작 세탁 = **더 나빠졌다**(`author`+`adopted`가 사용자 저작을
주장하고 ④가 정정을 어렵게).
> §2의 "그건 AI가 너에 대해 쓰는 노트, 이건 네가 AI에게 내리는 법"은
> **후보 단계에서는 아직 참이 아니다** — 후보는 여전히 AI가 쓰는 노트이고,
> 서명은 그 노트에 사용자 이름을 붙이는 행위일 수 있다. CLAUDE.md 제약
> ("AI 제안을 사용자의 원래 믿음으로 제시하지 않는다")과 직접 충돌.

## 명세 공백 5

1. **장부 무결성의 기제와 검증 명령** — "출처 사슬"의 구성요소·검증 명령·
   시점·주체 전부 없음. 그리고 **방출물엔 지문, 원본엔 없음**(파생물은
   보호하고 원본은 안 함).
2. **`amend`의 주체·한도·영향평가** — pause는 명문화, amend는 침묵. 명세에서
   **가장 강력하고 가장 규정이 얇은 동사.**
3. **후보의 발원 표기와 수확 입력의 경계** — provenance 필드 없음, `source`
   선택, 도구 출력이 발화 스트림에 섞이는지 미정의, sanitize 규정 없음.
4. **서명 창의 진위 구별과 경보의 표시 경로** — 에이전트가 흉내 낼 수 없는
   요소가 무엇인지 없음. 경보가 에이전트 컨텍스트 경유면 L2 전체가 에이전트
   협조에 의존.
5. **팀 모드의 감시 경계** — 감사/채점 경계, `author` 채움 방식, SHA→사람
   join 차단 여부, 회사 소유 기기 위의 개인 장부, L4 로그 접근통제.

## 제안 3

1. **서명 봉인 + `dec verify`** (불변식 안 깸) — 로컬 키 서명 블록(평문
   base64 — ①은 "도구 없이 *읽힌다*"이지 "도구가 없다"가 아님) + 집행 기록
   해시 체인. 한 명령이 손편집·날짜 조작·대필을 가른다. **③이 처음으로
   기제를 갖는다.** 정직한 한계: 키가 같은 기기면 에이전트가 훔칠 수 있다 —
   완전 해결이 아니라 **"몰래"에서 "키를 훔쳐야"로 격상**이고 흔적이 남는다.
   **이게 없으면 ②·③은 검증 불가능한 선언으로 남는다 — 지금이 그 상태다.**
2. **amend를 pause와 같은 등급으로 + 깎기 영향평가** (불변식 안 깸, ⑤·⑥ 완성)
   — (a) 사람 전용 TTY 명문화 (b) amend 시 시운전 재실행("이 개정 후 지난
