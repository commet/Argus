# Argus 코어 — 무엇이 심장이고 무엇이 껍질인가

> 창업자 지시(2026-08-19): *"진짜 core를 딱 아키텍쳐 잘 고민해서 아주 탄탄하고
> **누구나 이해 가능하게** 쌓아나가자."*

이 문서는 **처음 온 사람이 30분 안에 이 저장소를 이해하게 하는 것**이 목표다.
지도(`ARGUS-MAP-2026-08-19.md`)가 *무엇이 있나*를 답한다면, 이 문서는
*무엇이 중심이고 왜 그런가*를 답한다.

---

## 1. 한 문장

> **Argus 의 코어는 원장(ledger)이다. 사용자가 쓴 말만 담기고, 지워지지 않고,
> 다시 읽으면 언제나 같은 상태가 나오는 한 줄씩 덧붙는 파일.**
> 나머지는 전부 그 위의 표면이고, 표면은 갈아 끼울 수 있다.

이게 왜 코어인가: 제품의 약속은 *"기한이 오면 먼저 찾아와서, 그때 실제로 무슨
일이 있었는지 당신의 말로 남긴다"* 이다. 그 약속을 지키는 유일한 물건이 원장이다.
UI 가 바뀌어도, 모델이 바뀌어도, 호스트가 바뀌어도 원장이 남아 있으면 제품이 남는다.
원장이 틀리면 나머지가 전부 맞아도 제품은 없다.

---

## 2. 다섯 층 — 이 그림 하나면 된다

```
 ┌──────────────────────────────────────────────────────────────┐
 │  L4  껍질            랜딩 · /design/* · /admin/*             │  없어도 제품은 돈다
 ├──────────────────────────────────────────────────────────────┤
 │  L3  표면 4개        MCP(터미널) · 웹앱 · 플러그인 · 텔레그램  │  갈아 끼울 수 있다
 ├──────────────────────────────────────────────────────────────┤
 │  L2  공개 도구 6개   capture predict check_in                │  계약. 바꾸면 호스트가 깨진다
 │                      resolve patterns settings               │
 ├──────────────────────────────────────────────────────────────┤
 │  L1  코어 28 모듈    append · replay · state-machine ·       │  ★ 여기가 심장
 │                      premises · spine · resolve-today        │
 ├──────────────────────────────────────────────────────────────┤
 │  L0  원장 파일       .argus/ledger/ledger.jsonl              │  진실. 한 줄씩 덧붙기만
 └──────────────────────────────────────────────────────────────┘

            읽는 방향 ↑ 위층은 아래층을 안다
            쓰는 방향 ↓ 아래층은 위층을 절대 모른다
```

**한 줄 요약**: 위는 아래를 알고, 아래는 위를 모른다. 이 화살표 하나가 이
아키텍처의 전부다.

## 3. 각 층이 정확히 무엇인가

### L0 — 원장 (`.argus/ledger/ledger.jsonl`)

한 줄에 이벤트 하나, JSON, **덧붙이기만**. 수정도 삭제도 없다.
결정 하나가 열리고 · 계획이 붙고 · 예측이 봉인되고 · 기한에 결과가 적히고 ·
정산되고 · 규칙 한 줄이 남는 전 과정이 여기 순서대로 쌓인다.

왜 파일인가 — 사용자 기기에 있고, 계정이 없어도 돌고, 서버가 죽어도 남는다.

### L1 — 코어 28 모듈 (`argus-mcp/src/lib/` + `src/v2/`)

원장을 **쓰고 · 읽고 · 상태로 접는** 결정론 층. 12개 뿌리에서 도달하는 28 모듈이
전부이고, 그 목록은 `argus-mcp/src/lib/__tests__/core-boundary.test.ts` 가 기계로 고정한다.

| 무엇 | 어느 모듈 | 하는 일 |
|---|---|---|
| **쓴다** | `ledger-append` | MCP 존의 canonical writer (`O_APPEND` 관용구가 여기 · 플러그인에 손-베낌 하나 더 있다 — §4.1) |
| **읽어서 접는다** | `ledger-replay` | 이벤트 나열 → 현재 상태. 같은 파일이면 언제나 같은 결과 |
| **상태를 지킨다** | `state-machine` | `settled` 는 종착이다 — 되돌아가는 전이가 없다 |
| **기한을 안다** | `resolve-today` · `premises` | 오늘이 며칠인지, 무엇이 도래했는지 |
| **입을 열지 판단한다** | `overfire-gate` · `spine` | 평평한 결정에 말을 걸지 않는다 |

**코어가 아는 바깥 세계는 이것뿐이다**: node 내장 모듈 + `zod`.
MCP SDK 도, 네트워크도, 화면 문구도 코어에 들어올 수 없다 — 구조적으로 차단돼 있다.

### L2 — 공개 도구 6개 (`argus-mcp/src/tools/index.ts:10`)

호스트(Claude Code, Claude Desktop …)가 보는 전부.

| 도구 | 언제 |
|---|---|
| `argus_capture` | 결정을 연다 · 계획을 붙인다 · 단계 결과를 적는다 |
| `argus_predict` | 예측을 봉인한다 (나중에 채점되는 것은 사람이 아니라 이 예측이다) |
| `argus_check_in` | **제품이 먼저 말을 거는 자리.** 도래한 것이 있으면 여기서 나온다 |
| `argus_resolve` | 정산한다. 그 자리에서 규칙 한 줄을 사용자 말 그대로 받는다 |
| `argus_patterns` | 지난 기록을 본다 |
| `argus_settings` | 말 거는 빈도 등 |

이 여섯 개의 **이름과 스키마는 계약**이다. 바꾸면 남의 호스트가 깨진다.
내부에는 도구가 16개 있지만 열 개는 내부 전용이고 공개 목록에 없다.

### L3 — 표면 넷

| 표면 | 어디 | 상태 |
|---|---|---|
| **MCP (터미널)** | `argus-mcp/` | 1차 표면 — 창업자 봉인(CANON §9 결정 2) |
| **웹앱** | `src/` | 같은 개념의 두 번째 표면 |
| **플러그인** | `argus-plugin-v2/` | 스킬 마크다운이 스크립트를 부르는 구조 |
| **텔레그램** | `src/app/api/telegram/` | 알림 |

표면은 원장을 **경유해서만** 서로를 안다. 표면끼리 직접 부르지 않는다.

### L4 — 껍질

랜딩, `/design/foundry`, `/design/workspace`, `/admin/utm-builder`.
**없어져도 루프는 그대로 돈다.** 그래서 여기 코드는 코어 규율의 적용을 받지 않는다.

## 4. 네 가지 규칙 — 전부 기계가 지킨다

산문 규칙은 규칙이 아니다. 각각 어느 테스트가 지키는지 함께 적는다.

| # | 규칙 | 지키는 기계 |
|---|---|---|
| 1 | **코어의 바깥 의존은 node 내장 + zod 뿐** | `core-boundary.test.ts` — SDK·네트워크·표현층이 들어오면 빨간불 |
| 2 | **폐포 = 매니페스트.** 코어에 import 하나만 더해도 목록을 같은 커밋에서 갱신해야 한다 | 같은 파일. 실제로 타입 import 한 줄이 표현 계층 전체를 끌고 들어온 적이 있다 |
| 3 | **MCP 존 안에서** 원장에 쓰는 손은 둘뿐 (`ledger-append` · `v3/store`) | 같은 파일이 `O_APPEND` 관용구의 위치를 전수 검사 — **단 `argus-mcp/src` 안에서만 돈다**(§4.1) |
| 4 | **두 존에 같은 로직이 있으면 바이트까지 같다** | `premises-core-drift.test.ts` — 6개 파일 쌍 |

### 4.1 규칙 3 은 저장소 전체에 대해서는 참이 아니다 (2026-08-19 확인, 철회·정정)

이 문서의 첫 판은 규칙 3 을 *"원장에 쓰는 손은 하나"* 라고 적었다. **틀렸다.**
`core-boundary.test.ts` 의 전수 검사는 `argus-mcp/src` 를 걷는다 — 그 존 안에서만
참이다. 저장소 전체에서 `O_APPEND` 를 가진 소스는 넷이다:

| 파일 | 존 | 지키는 기계 |
|---|---|---|
| `argus-mcp/src/lib/ledger-append.ts` | MCP | ✅ core-boundary |
| `argus-mcp/src/v3/store.ts` | MCP | ✅ core-boundary (사유 등재됨 — 별도 파일 `semantic-v3.jsonl`) |
| `argus-plugin-v2/scripts/decision-ledger.js` | 플러그인 | ❌ **없음** |
| `argus-plugin-v2/scripts/push-webapp.js` | 플러그인 | ❌ **없음** |

그리고 플러그인 쪽 `decision-ledger.js:79` 는 **MCP 와 같은 파일**
(`.argus/ledger/ledger.jsonl`) 에 쓴다. 파일 헤더가 스스로 *"MIRROR of
argus-mcp/src/lib/ledger-append.ts"* 라고 적어 두었는데, 그 약속을 지키는
테스트는 없다.

**락은 호환된다** — 양쪽 다 `<원장파일>.lock` 을 쓰므로 동시 쓰기로 원장이
찢어지지는 않는다(플러그인 `decision-ledger.js:151`, MCP `ledger-append.ts:155`).
위험한 것은 경합이 아니라 **규율의 드리프트**다: 한쪽만 고친 append 규율이
다른 쪽에 반영되지 않으면 같은 파일에 서로 다른 규칙으로 쓰게 된다.

→ 처분은 §8 에. 이 칸을 비워두지 않으려고 여기 적는다 — **문서가 코드보다
좋게 들리면 그건 문서의 결함이다.**

여기에 이번에 둘을 더한다:

| 5 | **진입점에서 못 닿는 파일이 늘지 않는다** | `scripts/check-reachability.mjs` (기준선 래칫) |
| 6 | **런타임 순환 import 가 늘지 않는다** | `scripts/check-cycles.mjs` (아래 §6) |

## 5. "이걸 바꾸려면 어디를 만지나"

처음 온 사람이 가장 많이 묻는 것.

| 하고 싶은 것 | 만질 곳 | 함께 봐야 할 것 |
|---|---|---|
| 기한에 하는 말을 바꾼다 | `argus-mcp/src/lib/surfaces.ts` | 한국어 문자열에 em-dash 금지 가드 |
| 새 이벤트 종류를 만든다 | `lib/ledger-append` + `ledger-replay` fold | **먼저 `CONTEXT.md` 낱말 11개를 읽는다.** 같은 개념을 여섯 번째 이름으로 다시 만든 전례가 있다 |
| 도구에 필드를 더한다 | `argus-mcp/src/tools/public-tools.ts` | 그 필드를 **읽는 곳**이 실재해야 한다 (생산만 하면 dead-on-arrival) |

| 루프가 도는지 확인한다 | `cd argus-mcp && npm run loop:demo` | 모델·키·대기 없이 한 바퀴 |

## 6. 지금 코어의 실제 건강 상태 (2026-08-19 전수 실측)

인상이 아니라 기계가 낸 숫자다.

| 항목 | 값 | 판정 |
|---|---|---|
| 코어 폐포 | 28 모듈, 외부 의존 = node + zod | ✅ 잠겨 있다 |
| 원장 writer | MCP 2 (등재됨) + 플러그인 2 (**기계가 안 지킴**) | ⚠️ §4.1 |
| 런타임 순환 import | **3** (전체 19 중 16은 `import type` 이라 컴파일에서 지워진다) | ⚠️ §6.1 |
| 안 쓰는 npm 의존성 | 앱 36개 중 0 · MCP 10개 중 0 | ✅ |
| 링크 없는 페이지 | 31개 중 3 (`/design/*` 2 + `/admin/utm-builder`) | ✅ 의도된 내부 도구 |
| 호출처 없는 API | 66개 중 1 (`/api/epistemic/commands`) | ⚠️ 미배선 |
| 진입점 미도달 | 앱 42파일 · MCP 15 · 플러그인 12 · 스크립트 34 | §6.2 |
| **"정본은 저쪽" 주석** | 22곳 중 **13곳은 지키는 기계가 없다** | ⚠️ §6.3 |

### 6.1 런타임 순환 셋

```
1. lib/persona-prompt → lib/context-builder → lib/epistemic/control-plane
                      → lib/epistemic/prompt-renderer → lib/persona-prompt
2. components/workspace/progressive/WorkerPanel ↔ AgentSidebar
3. antefact/cli/antefact.mjs ↔ spokes.mjs
```

1번이 유일하게 중요하다 — `control-plane` 은 CLAUDE.md 가 *"파생 기억의 유일한
권위"* 라 부른 파일인데, 프롬프트 조립기와 서로를 부른다. 권위가 고리 안에 있으면
누가 먼저인지 읽어서 알 수 없다.

### 6.2 "참조 0" 은 아홉 가지 이유로 생긴다 — 이게 이번 감사의 가장 큰 교훈

미도달 파일을 곧바로 "죽었다"로 읽으면 안 된다. 이번에 **다섯 번 틀렸고**, 그중
하나는 지웠으면 웹 빌드가 죽는 것이었다. 참조가 0인 이유 전부:

| # | 이유 | 예 |
|---|---|---|
| 1 | 프레임워크 규약으로 진입 | `page.tsx` · `error.tsx` |
| 2 | **다른 존이 소비** | 앱이 `argus-mcp/dist/v3/reducer.js` 를 쓴다 |
| 3 | 테스트가 **경로 문자열**로 읽는다 | `readFileSync('../../x.tsx')` |
| 4 | 앰비언트 선언 (import 되지 않는 종류) | `*.d.ts` |
| 5 | **스킬 마크다운이 셸로 부른다** | `node "${CLAUDE_PLUGIN_ROOT}/scripts/decision-ledger.js"` (1,757줄) |
| 6 | 사람이 직접 도는 CLI | `node scripts/sim/run-sim.mjs` |
| 7 | 게이트가 분류로 관리 | `argus-mcp/evals/*` (`gate-coverage.mjs`) |
| 8 | **외부 HTTP 호출자** | 텔레그램·Slack 웹훅, MCP OAuth 클라이언트 |
| 9 | 호스트 설정으로 배선 | 플러그인 statusline (`doctor.js §11` 이 이 침묵을 알린다) |

**규칙: 미도달은 "죽었다"가 아니라 "아홉 중 어느 것인지 물어라"는 뜻이다.**
아홉 중 어디에도 안 들어가면 그때 (a) 미배선 / (b) 폐기 / (c) 의도된 라이브러리로
판정한다.

### 6.3 "정본은 저쪽" 22곳 — 13곳은 약속만 있고 기계가 없다

세 표면이 코드를 공유하는 방식이 **다섯 가지**다. 이게 이 저장소가 명료하게
읽히지 않는 가장 큰 이유다 — 읽는 사람이 매번 "이건 어느 방식이지?"를 먼저
풀어야 한다.

| 방식 | 건수 | 기계가 지키나 |
|---|---:|---|
| 진짜 import (`webapp → mcp/dist`) | 7 | ✅ 컴파일러 |
| byte-핀 복제 (6파일 1,413줄) | 6 | ✅ `premises-core-drift.test.ts` |
| 공용 적합성 픽스처 | 9 | ✅ 픽스처 |
| **주석만 "정본은 저쪽"** | **13** | ❌ **없음** |
| 승인된 예외 채널 (`webapp → harness`) | 23 | ✅ `harness.test.ts` |

기계 없는 13곳 중 무거운 셋:

1. `argus-plugin-v2/scripts/decision-ledger.js:104` ← `ledger-append.ts` — **원장 쓰기 규율**
2. `argus-plugin-v2/scripts/validate-gates.mjs:22,61` ← `validate-seal.ts` — **봉인 게이트**
3. `argus-plugin-v2/scripts/push-webapp.js:469` ← `a0/account-connect.ts` — **OAuth PKCE**

셋 다 안전에 관한 규율이고, 셋 다 "주석으로 부탁"만 하고 있다.

### 6.4 같은 이름이 다른 뜻 — 25종

존을 가로질러 같은 파일명이 25종 있고 그중 **19종은 내용이 다르다**.
`types.ts` 7곳 · `reducer.ts` 5곳 · `run.mjs` 3곳 · `store.ts` 3곳 ·
`ledger.ts` `mirror.ts` `surfaces.ts` `plan.ts` 각 2곳.

사람이든 AI든 `reducer.ts` 를 열었을 때 **전체 경로 없이는 어느 것인지 모른다.**
이것이 "누구나 이해 가능한 구조"의 반대말이다.

## 7. 코어가 아닌 것 — 그리고 왜 그게 중요한가

`src/lib/` 안에 있다고 코어가 아니다. 지금 코어 규율 **밖**에 있는 큰 덩어리들:

| 무엇 | 줄 | 왜 코어가 아닌가 |
|---|---:|---|
| `src/lib/cognition/` | 4,658 | 순수 엔진. 창업자 봉인이 존치를 명시했지만 **대화 루프 편입이 아직 안 됐다** — 이 저장소 최대 미완 부채 |
| `src/lib/epistemic/` | ~7,000 | 파생 기억 제어면. 본체는 살아 있고 둘레(컴파일러·어댑터·서버 감사기)가 미배선 |
| `src/lib/review/` · `boss/` · `twin/` | ~14,000 | 웹 표면의 기능들 |
| `scripts/sim/` | ~19,000 | 일회성 측정 하네스. 결과 덤프는 증거라 남긴다 |

**중요한 이유**: 이 목록이 없으면 다음 사람이 `src/lib/` 를 열고 "여기가 코어구나"
하고 224,317줄을 코어로 오해한다. 코어는 28 모듈이다.

## 8. 이 저장소의 병 — 이름을 붙여둔다

전수 감사가 내린 결론은 "쓰레기가 쌓였다"가 **아니다**.

> **만들고 안 이은 것이 쌓였다.**

미도달 파일의 대다수가 **전용 테스트를 갖고 있다.** 만들었고, 테스트까지 썼고,
부르는 화면만 없다. 이 병은 이미 `CLAUDE.md` 가 이름 붙여 두었다 —
*"생산된 필드는 기본이 dead-on-arrival이다. 소비를 가드한다."*

그래서 다음 작업의 우선순위는 **더 지우는 것이 아니라 잇는 것**이고,
가장 큰 하나는 `cognition/` 4,658줄의 대화 루프 편입이다 (창업자 봉인의 남은 반쪽).
