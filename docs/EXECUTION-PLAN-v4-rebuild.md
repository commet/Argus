## A. 목표 형상 — 통합 Argus: 하나의 루프, 세 개의 시계, 두 개의 표면

**제품 = 루프다.** 알아봄(측정) → 봉인("물어봐 줄까요?") → 귀환("그래서, 어떻게 됐어요?") → 자차표.
나머지 전부는 이 루프로 들어오는 **문**이고, 문마다 시계가 다르다:

| 시계 | 문 | 표면 | 역할 |
|---|---|---|---|
| **시간 단위** | `/argus:helm` — 에이전트가 짠 계획의 승인 전 탐침 | 플러그인 | **루프의 부트스트랩 도메인.** 내기가 몇 시간 만에 정산되므로 귀환 습관과 자차표가 여기서 처음 형성된다 (§C+ 루프 압축) |
| **일 단위** | watch — 이미 나눈 대화에서 결정 수확, 세션 훅 | 플러그인/CLI | 입력 0의 수확. 원장을 자동으로 채운다 |
| **주 단위** | 깊은 세션 — 무거운 인생·업무 결정 | 웹앱 | 검증된 몰입 경험(긴 입력→질문→답). 단, **질문의 원천을 AI 의견에서 측정으로 교체** — 이것이 갈아엎기의 심장 |

**원장은 하나다.** 세 문이 같은 decision 객체에 쓴다. 그래야 도메인 횡단 자차표가 성립한다 —
"계획 승인에서도, 사업 결정에서도, 당신은 일정 가정을 그냥 통과시키는 경향이 있어요."
이 문장이 통합의 존재 이유이고, 경쟁 시스템(OMC/gstack/Superpowers) 누구도 영원히 못 하는 문장이다.

**두 표면**: 웹앱 = 깊은 세션 + 원장의 집(자차표가 사는 곳). 플러그인 = dev 속도로 도는 루프.

## B. 갈아엎기의 정의 — 무엇을 부수고 무엇을 남기나

**부순다 (경험과 엔진):**
1. 질문 생성의 원천: AI 의견(감지형·판정형) → **측정(분기·하중 탐침)에서 기계 변환** (v2 P2 설계)
2. 세션 아크: 산출물-클라이맥스 → **시험 항해 극장 → 키잡이 질문 → 봉인 종막 → 산출물은 가져가는 것**
3. reframe의 판정형("네 진짜 문제는 X") → 목적-수준 분기 측정 (v2 P1.3)
4. 랜딩 3막 → 세이렌 1화면. IA 6개 진입점 → 단일 진입
5. 17 에이전트의 *역할*: 의견 패널 → 탐침 실행자 + opt-in 관점 (페르소나 자산은 유지, 위치만 이동)

**남긴다 (배관과 검증된 강점):**
- 스트리밍 분석 극장, 질문 루프 UI 골격, convergence 게이지(방향만 역전), i18n, Zustand/Supabase
  배관, 인증·쿼터(견고함 확인됨), DecisionContractCard, signal-recorder, watch CLI, 플러그인 뼈대
- **새 레포 금지.** 갈아엎기의 대상은 경험과 엔진이지 배관이 아니다 — 배관 재작성은 3주를 태우고
  아무 가설도 검증하지 않는다. ✋창업자 확정

## Z. 이 계획 자체의 봉인

> 갈아엎기의 1순위 위험은 품질이 아니라 **무기한화**다 — "계획·재설계가 가장 편안한 모드"라는
> 긴장(v3.1 §3 인용)은 갈아엎기 결정으로 사라지지 않는다. 더 커진다. 그래서 기한이 게이트다.
