# 히어로 영상 파이프라인 (원본 관리 + 워터마크 제거 + 반영)

> 랜딩 히어로의 "움직이는 판화"(`public/voyage/voyage-film.mp4`)를 만드는 방법.
> 원본은 계속 추가되므로, **원본 관리 → 처리 → 검증 → 반영**을 이 문서 하나로 고정한다.
> 사용자는 비개발자이므로 클로드가 이 문서의 레시피대로 처리한다.

최종 검증 커밋: box-only 방식으로 좌측 바 + 반짝이 동시 해결 (2026-07-01).

---

## 0. 한눈에 (TL;DR)

```bash
# 1) 새 원본을 관리 폴더에 넣는다 (아래 명명규칙)
#    assets/hero-originals/NN_설명_장면.mp4
#
# 2) 워터마크 제거 (박스-only, 검증 포함)
scripts/process-hero-clip.sh assets/hero-originals/NN_...mp4 /tmp/clip_NN.mp4
#
# 3) (여러 클립이면) 이어붙이기 → public/voyage/voyage-film.mp4  (§5)
# 4) 포스터 재생성  (§5)
# 5) 커밋
```

핵심 원칙 **딱 하나**만 기억하면 된다:

> **워터마크는 "박스 밖을 절대 안 건드리는" 방식으로만 지운다.**
> 전체 프레임에 뭔가를 덧씌우는(pad/shift/blur/vignette) 순간 좌측 바·더블링이 생긴다.

## 1. 폴더 구조 / 원본 관리

| 위치 | 내용 |
|---|---|
| `assets/hero-originals/` | **깨끗한 원본**(사용자가 준 것). 지우지 않는다. 정본. |
| `assets/hero-originals/MANIFEST.md` | 각 원본의 장면·순서·워터마크 위치·비고 |
| `public/voyage/voyage-film.mp4` | 배포되는 **최종 결과물**(처리+이어붙임) |
| `public/voyage/voyage-poster.jpg` | 로딩 전 첫 프레임(§5에서 자동 생성) |
| `scripts/process-hero-clip.sh` | 워터마크 제거 + 검증 스크립트 |

**명명규칙:** `NN_주제_장면.mp4` (예: `01_ulysses-defies-sirens_wide-ship.mp4`).
`NN`은 최종 영상에서의 등장 순서.

**원본을 새로 받으면:** ① 위 규칙으로 `assets/hero-originals/`에 저장, ②
`MANIFEST.md`에 한 줄 추가, ③ §0 레시피로 처리.

## 2. 지금까지 파악한 문제들 (전부 실제로 겪음)

### 2-1. 반짝이(sparkle) 워터마크 — Veo 생성물의 흔적
- **정체:** 4각별 반짝이가 화면 **고정 위치 (1158, 597)**, 약 60px, 밝기 피크 ~200+.
  움직이지 않는다(전 구간 시간추적으로 확정). 원본에도 들어있다(제거 대상 맞음).
- **탐지법:** 프레임을 `gblur` 후 하단-우측에서 가장 밝은 blob → 항상 (1158,597) 부근.
  (스크립트가 자동으로 출력한다. 새 원본이 다른 위치면 여기서 드러남.)

### 2-2. ❌ "좌측 회색 바" — **우리가 만든 아티팩트였다** (원본엔 없음)
- **증상:** 왼쪽 ~75px에 full-height 회색 세로 띠. 몰입을 깬다.
- **오진들:** 판화 자체 테두리다 / 비네트다 → **둘 다 아님.**
- **진짜 원인:** 워터마크를 지울 때 쓴 "전체 프레임 shift + `pad`(왼쪽 80px 검정)
  + `maskedmerge`" 방식에서, **마스크의 검정이 0이 아니라 Y=16(limited range)**
  이라 maskedmerge가 이걸 **6% 불투명도**로 해석 → pad의 검정이 왼쪽 전체로 6%
  새어나옴 = 회색 바. 동시에 shift된 프레임이 6%로 전체에 겹쳐 = **배경 더블링**.
  → **바와 더블링은 같은 한 가지 버그.** 사용자가 "같은 이슈"라고 한 게 맞았다.
- **검증법(중요):** **시간평균**. 40초를 평균 내면 움직이는 내용은 지워지고 고정
  오버레이만 남는다. 원본 평균 = 균일 크림(바 없음), 버그 버전 평균 = 왼쪽 회색 바.
  → `Left(x2)`와 `Mid(x120)`의 평균 밝기가 **같아야** 정상.
- **교훈:** 컬럼 밝기 몇 개 비교로 "문제없다" 판정하면 안 된다. **시간평균**으로 봐라.
  그리고 **처리 원본과 비교하지 말고**(그 원본이 이미 오염됐을 수 있다) 사용자의
  진짜 원본과 비교하라.

### 2-3. ❌ delogo — 선화 위 뭉갬
`delogo`는 박스 경계에서 보간 → 종이 위(바다/여백)는 OK지만 **선화(노·노받이) 위에서
회색 뭉갬**. 18초 노 젓는 장면에서 확인. 금지.

### 2-4. ❌ 밝기 캡(luma cap) — 마름모 잔상
밝은 반짝이 중심만 낮추면 반짝이의 **어두운 외곽 링**이 남아 희미한 마름모로 보인다.
배경(예: 바다 175 vs 선화 122)마다 적정값이 달라 상수 하나로 못 맞춘다. 금지.

### 2-5. color range 함정 (여러 버그의 뿌리)
- `color=black` lavfi / PNG를 영상 입력으로 넣으면 검정이 **Y=16**(limited)로 변환됨.
- `maskedmerge`·`overlay` 알파는 **raw 0–255**를 쓰므로 16은 곧 6% 누출.
- `signalstats`의 YAVG/YMAX도 limited 기준으로 읽혀 **측정 자체가 헷갈린다.**
- → 마스크 계열은 신뢰하기 어렵다. **박스-only overlay(§3)** 가 이 함정을 통째로 회피.

## 3. 정답 레시피 — 박스-only overlay-patch

`scripts/process-hero-clip.sh` 가 이걸 한다. 원리:

1. 프레임을 `split` → `base`, `src`.
2. `src`에서 워터마크 박스 **왼쪽 80px 이웃**을 `crop`(같은 행 → 파도선이 이어짐).
3. 그 patch에 **가우시안 페더 알파**를 입힌다(`geq ... a=`), 시그마 38.
4. patch를 워터마크 위치에 `overlay`.
5. **박스(130px) 밖은 base 그대로** → 전역 아티팩트 불가능.

왜 왼쪽에서 당겨오나: 오른쪽 80px엔 판화 테두리선이 있어(넓은 배 장면) 겹침선이
생긴다. 왼쪽은 열린 바다/여백이라 깨끗. 세로가 아니라 **가로 이동**이라 수평 파도선이
어긋나지 않는다.

새 원본에서 반짝이가 (1158,597)이 아니면:
```bash
scripts/process-hero-clip.sh IN OUT  <새X> <새Y>
```
(스크립트 상단 자동탐지 출력으로 새 위치를 확인.)

## 4. 검증 (반드시 통과)

스크립트가 자동으로 하지만, 수동 확인법:

```bash
# (a) 좌측 바 없음 — 시간평균 Left ≈ Mid
ffmpeg -y -i OUT.mp4 -vf "select='not(mod(n\,20))',tmix=frames=60" -frames:v 1 avg.png
#   avg.png 왼쪽과 중앙 밝기가 같아야 한다 (차 ≤ 2~3).

# (b) 반짝이 없음 — 워터마크 영역 눈으로
ffmpeg -y -ss 2 -i OUT.mp4 -vframes 1 -vf "crop=200:200:1058:497,scale=400:400:flags=neighbor" wm.png

# (c) 전역 무변화 — 박스 밖은 원본과 동일해야
#     (박스-only 방식이면 구조적으로 보장되지만, 다른 방식 썼을 때 점검)
```

**판정 기준:** (a) Left≈Mid, (b) 반짝이 안 보임, (c) 왼쪽/네 모서리에 균일한 띠 없음.

## 5. 이어붙이기 + 반영

여러 클립이면 순서(`NN`)대로 이어붙인다:
```bash
# 각 원본을 먼저 §0로 개별 처리한 뒤:
printf "file '/abs/clip_01.mp4'\nfile '/abs/clip_02.mp4'\n..." > list.txt
ffmpeg -y -f concat -safe 0 -i list.txt -c copy public/voyage/voyage-film.mp4
# (해상도/fps가 동일해야 -c copy 가능. 다르면 각 클립을 1280x720/동일fps로 먼저 정규화.)

# 포스터(로딩 전 첫 프레임) 재생성:
ffmpeg -y -ss 1 -i public/voyage/voyage-film.mp4 -vframes 1 -q:v 3 public/voyage/voyage-poster.jpg
```

인코딩 표준: `libx264 -crf 19 -preset medium -pix_fmt yuv420p -movflags +faststart -an`.
(무음. 히어로는 자동재생 muted loop.)

## 6. 앱에서의 표시 (레이아웃)

`src/components/landing/SirenHero.tsx` — 영상을 **액자(plate)처럼** 중앙에 놓는다:
- 폭 `min(92vw, 1160px)` 중앙 정렬, 통짜 16:9(**크롭 0** → 얼굴 안 잘림).
- 은은한 그림자로 띄워 판화 테두리가 "의도된 액자"로 읽히게.
- 중앙정렬은 **flex**로(`transform`은 `bp-fade-up` 애니메이션과 충돌하므로 금지).
- 모바일(<640px)은 `VoyageFilm`의 콘텐츠-주도 스택(영상 + 캡션 거터).

주의: `object-fit`을 쓰되 박스 비율이 영상과 같으면(16:9=16:9) 크롭 0이다. 높이를
`max-h`로 캡하면 `cover`가 위아래를 잘라 **얼굴이 잘린다**(과거 실수). 폭으로 제어하라.

## 7. 트러블슈팅 표

| 증상 | 원인 | 처방 |
|---|---|---|
| 왼쪽 세로 회색 바 | 전체 프레임 pad/shift 누출(§2-2) | 박스-only 방식(§3). 시간평균으로 검증 |
| 배경 흐린 더블링 | 위와 같은 6% 누출 | 위와 동일(같은 버그) |
| 반짝이 마름모 잔상 | 밝기 캡 외곽 링(§2-4) | 박스-only overlay로 교체 |
| 선화 위 회색 뭉갬 | delogo 보간(§2-3) | delogo 금지, overlay 채우기 |
| 채운 자리 파도선 겹침 | shift 방향/거리 부적절 | 왼쪽에서 당김, SHIFT는 반짝이폭보다 크게(80) |
| 얼굴이 잘림 | `max-h`+`cover` 크롭(§6) | 폭으로 제어, 통짜 16:9 |
| "문제없다"는데 사용자는 보임 | 컬럼 몇 개만 확인 / 오염된 원본과 비교 | **시간평균** + **사용자 진짜 원본**과 비교 |
