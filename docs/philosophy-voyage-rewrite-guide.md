## §1 핵심 철학: 왜 Argus인가

**§1.1 — 오케스트라가 가져온 본질 → 항해가 가져온 본질**

기존: "서곡의 400년 진화(정숙→예고→독립)가 존재 이유". 음악사 앵커.
교체 앵커(택1, 작성자 선택):
- (A) **오디세이아의 구조** — 출항·표류·귀환. Argus는 표류를 줄이는 도구.
- (B) **항해술의 진화** — 별 → 나침반 → 해도 → 정밀항법. "도구가 정교해질수록 *어디로 갈지*의 판단이 더 중요해졌다"가 핵심 테제와 직결. (로드맵 §9와 자연스럽게 연결됨 → B 추천)

서곡의 3역할 → 항해의 3국면으로 재매핑:
| 기존(서곡) | voyage 대응 | Argus에서의 대응(유지) |
|---|---|---|
| 정숙시키기 | **출항 준비** — 흩어진 의도를 한 배에 싣기 | 흩어진 생각을 모아 본질에 집중 |
| 예고하기 | **해도 그리기** — 목적지·항로의 윤곽을 먼저 | AI에 넘기기 전 결과물 윤곽 |
| 독립하기 | **항해 자체가 목적** — 항해일지가 곧 가치 | 사고 과정 자체가 산출물 |

**§1.3 제품이 믿는 것** (4개 신념 직역):
- "악보 없는 오케스트라는 소음이다" → **"해도 없는 항해는 표류다."**
- "지휘자는 악기를 연주하지 않지만 악보를 읽을 줄 알아야 한다" → **"선장은 노를 젓지 않지만 해도를 읽을 줄 알아야 한다."**
- "좋은 서곡은 그 자체로 아름답다" → **"좋은 해도는 그 자체로 가치 있다."**
- "서곡은 끝이 아니라 시작이다" → **"해도는 끝이 아니라 출항이다."**

## §2 본편 구조: 4단계 (음악적 의미 → 항해적 의미)

4단계 라벨은 코드·README와 이미 통일됨:
**항로 재설정 → 선원 배치 → 리허설 → 항로 수정 → 이타카(산출물)**, 독립 유틸 = **종합**.

단계별 "음악적 의미" 문단을 "항해적 의미"로 재집필 (앵커만 제시):
| 단계 | 폐기된 음악 앵커 | voyage 앵커(재집필 소재) |
|---|---|---|
| 항로 재설정 | 카라얀 vs 번스타인의 악보 해석 | 같은 바다를 두 항해사가 **다른 해도**로 읽는다. 같은 목적지도 항로 선택에 따라 다른 여정. |
| 선원 배치 | 현악4중주 vs 풀오케스트라 편곡, 악기 진입 순서 | **누구를(AI/사람) 어느 자리에**(노·돛·키·망루) 앉히고, 어떤 순서로 움직이는가. |
| 리허설 | 본공연 전 연주 → 호른 음역·리듬 충돌 발견 | **출항 전 모의 항해 / 선원 회의** — 해도 위에선 완벽하던 항로의 약점이 드러남. |
| 항로 수정 | 밸런스 조율 → 하나의 소리로 수렴 | 항로를 거듭 잡아가며 **한 방향으로 수렴**. 한 번에 완벽한 항로는 없다. |
| 이타카(산출물) | 공연 = 관객에 전달 | **이타카 도착** — 그 뒤엔 전 단계의 항해가 축적됨. |
| 종합(독립유틸) | 오보에 A4 튜닝 = 음높이 맞춤 | **관측 보정** — 여러 해도/판독을 나란히 놓고 교차 검증. |

산출물 4종 비유명(이미 통일): **항해일지 · 선원 지시서 · 전체 해도 · 점검표** (영문명 동일).
- 항해일지(Project Brief) = 항해의 서사가 담긴 기록
- 선원 지시서(Prompt Chain) = 각 선원이 받는 자기 몫의 지시
- 전체 해도(Agent Spec) = 선장이 보는 전체 항로, 모든 파트 한눈에
- 점검표(Execution Checklist) = 출항 당일 순서·타이밍

## §3 네 터치포인트

| 절 | 폐기된 음악 앵커 | voyage 앵커 |
|---|---|---|
| 3.1 첫인상 | 몬테베르디 토카타 9마디 = 시작 신호 | **닻을 올리는 신호 / 첫 뱃고동** — 짧지만 분명한 출항 신호. 빈 상태: "아직 출항하지 않았습니다." |
| 3.2 맥락 누적 | 글루크 개혁(끊김 없는 서곡→1막) | **항로가 끊기지 않고** 다음 구간으로 흘러듦. 한 다리(leg)의 끝이 다음 다리의 시작. |
| 3.3 AI 결과 순간 | 모차르트 돈조반니 주제 예고 실현 | 출항 전 그린 **해도의 항로가 도착지에서 실현**되는 순간 — "내가 그린 항로대로 왔구나." |
| 3.4 작업 후 성찰 | 코다(베토벤 5번) + 멘델스존 독립 | **항해일지(Logbook)** 작성 / 귀항 후 성찰. 코다→항해일지로 이미 UI 통일. 메타 튜닝 = 항로 감각 자체의 보정. |

온보딩 내러티브(§3.1 코드블록)도 항해로 재집필: "악기가 좋아도 악보 없이는…" → "배가 빨라도 해도 없이는 표류일 뿐…", "첫 악보를 펼쳐볼까요?" → "첫 해도를 펼쳐볼까요?"

## §4 언어 체계
용어 매핑 테이블 전체를 [[branding-voyage]] §2·§6·§7로 대체(중복 정의 금지, 참조만).
마이크로카피(로딩/빈상태/전환)는 코드에 이미 반영됨 — 이 문서는 *원칙*만:
- 로딩: "항로를 그리고 있습니다…" / "선원을 배치하고 있습니다…"
- 전환: "항로가 잡혔습니다" / "선원이 배치되었습니다" / "첫 선원 회의가 끝났습니다" / "항로가 잡혔습니다"
- 원칙 유지: **항해 비유 + 업무명 항상 병기**, 한 문장에 비유 2개 금지.

## §8 브랜드 카피
- "악보 없는 오케스트라는 소음입니다" → **"해도 없는 항해는 표류입니다."**
- "시장에 악기는 21개… 악보를 쓰는 도구는 없었다" → **"시장에 배는 21척… 해도를 그리는 도구는 없었다."**
- "…결정이 시작되는 서곡입니다" → **"…결정이 시작되는 첫 항로입니다."**
