# 06 — 낯선 사람의 첫 3분: 언어의 문턱 감사 (2026-07-03)

> 감사 방식: Argus를 처음 보는 사람의 눈으로, 실제 코드 경로를 따라 첫 3분을 통과했다.
> 경로 = 랜딩(`/`) → 히어로 입력 → `/workspace?q=` 자동 제출 → 밧줄 묶기(BindCard) → 분석 →
> 첫 질문 → (세션 끝) 현재 방위 카드 → 봉인 버튼. 보조 경로 = 히어로 오른쪽 문 → `/tools/review`.
> 모든 판정은 코드를 직접 열어 확인한 문자열 기준이다.

## 요약 (5줄)

1. **전체적으로 이미 잘 다져진 길이다.** 세이렌=AI를 영상 도입부가 직접 설명하고(VoyageFilm), 낯선 단어 옆에 일상어를 붙이는 "다리 패턴"이 곳곳에 살아 있다 — 예: "결론 요약 한 장(현재 방위)", "정산하기 (현실 기록)". 첫 3분을 못 넘기게 만드는 P0급 언어 장벽은 **없다**.
2. 가장 큰 남은 문제는 **같은 물건의 이름이 둘**인 것: 랜딩·가이드·워크스페이스 안내는 전부 "현재 방위"를 가르치는데, 정작 사용자가 만나는 결과물 카드는 "현재 항로"라고 적혀 있고, 같은 "현재 항로"라는 말이 다른 화면에선 전혀 다른 뜻(갈래 전환)으로도 쓰인다.
3. **첫 입력의 순간(히어로 입력창)에 기대 설정이 없다** — "무료·로그인 없음·30초"는 두세 화면 아래에만 있어서, 정작 처음 타이핑하고 버튼을 누르는 지점에서는 무슨 일이 벌어질지 알 수 없다.
4. 랜딩에서 "읽어봐 주세요"를 누른 사람이 처음 만나는 화면(밧줄 묶기)은 **부탁한 '읽기'가 진행 중이라는 신호가 0**이고, "밧줄 묶기"라는 은유가 첫 만남에서 설명 없이 나온다.
5. "봉인" 버튼과 "내 lean" 등 소수의 어휘가 첫 만남에서 다리 없이 노출된다 — 고유 어휘는 유지하되, 첫 만남에만 한 줄 다리를 놓는 스펙을 아래에 적었다.

## 발견 목록 (심각도순)

### P0 — 없음

첫 3분을 코드로 전수 추적한 결과, 진행 자체를 막거나 근본적으로 오해하게 만드는 언어 장벽은 없었다. 랜딩·입력·질문·검수 경로의 핵심 문장은 이미 일상어다. 아래 P1 네 건이 "멈칫하는 지점"의 전부다.

### P1-1 · 같은 물건에 이름이 둘: "현재 방위" vs "현재 항로" (+ '현재 항로'는 뜻도 둘)

- 배우는 단어: 랜딩 영상 3곳(`VoyageMapFilm.tsx:358`, `DecisionVoyageFilm.tsx:751,804`), 워크스페이스 첫 화면 3단계 안내(`workspace/page.tsx:536` "(현재 방위)"), 가이드 제목·FAQ(`guide/page.tsx:47,93,127`), 내보내기 문서 제목(`src/lib/current-bearing.ts:239`) — 전부 **"현재 방위"**.
- 만나는 단어: 정작 세션 끝의 결과물 카드 눈썹은 **"현재 항로"**(`CurrentBearingCard.tsx:101`), 복사 버튼 라벨도 "현재 항로 복사"(:112), 타임라인 라벨도 "현재 항로"(`DecisionReplayTimeline.tsx:120`).
- 더 나쁜 것: 같은 "현재 항로"라는 말이 프로젝트 헤더의 **갈래(브랜치) 전환 칩**에서 전혀 다른 뜻으로 쓰인다(`workspace/page.tsx:148` "현재 항로 · 총 N개 — 눌러서 갈아타기"). 낯선 사람 기준: 3단계 안내에서 "(현재 방위)"를 외웠는데, 도착하니 "현재 항로"가 두 군데서 서로 다른 걸 가리킨다.
- 참고로 영어는 양쪽 다 "Current Heading"으로 이미 통일돼 있다 — 한국어만 갈라졌다.

### P1-2 · 첫 입력의 순간에 기대 설정이 없다 (무료·30초·로그인 없음)

- 히어로 입력창 주변(`SirenHero.tsx:328-355`)에는 "⏎ 한 줄이면 충분해요"와 "읽어봐 주세요" 버튼뿐. **무슨 일이 벌어지는지(무료인지, 얼마나 걸리는지, 가입이 필요한지)** 를 말하는 문장이 히어로에 하나도 없다.
- 그 문장("로그인 없이 무료 · 30초 안에 첫 분석")은 스크롤 두세 화면 아래에만 있다: `Act2DecisionVoyage.tsx:113`, `Act3OnDeck.tsx:127`.
- 부수: 히어로 상단 주석(`SirenHero.tsx:11-12`)은 "a marginal privacy note"가 있다고 적어 놨지만 실제 코드에는 없다(주석 드리프트).

### P1-3 · "읽어봐 주세요" → 밧줄 묶기 화면의 이중 공백

랜딩에서 결정을 적고 "읽어봐 주세요"를 누른 사람은 `/workspace?q=`로 이동해 즉시 자동 제출되고(`workspace/page.tsx:290-308`), 첫 화면으로 BindCard를 만난다(`workspace/page.tsx:814-818`).

- (a) **부탁한 '읽기'가 진행 중이라는 신호가 0.** 분석은 실제로 뒤에서 병렬로 돌고 있지만(설계 의도, `workspace/page.tsx:310-334`), BindCard에는 그 사실을 알리는 문장이 없다(`BindCard.tsx:83-196` 전체 확인). 낯선 사람의 자연스러운 독해: "읽어달라고 했는데 왜 나한테 되묻지? 눌러진 건 맞나?"
- (b) **"출항 전 · 밧줄 묶기"(`BindCard.tsx:103`)와 "묶고 계속"(:190)** — 영상(포스터 상태라 대부분 재생 안 함)을 안 본 사람에게 '밧줄/묶기'는 첫 만남 무설명 은유다. 기능 설명(:111 "안 적어도 됩니다…")은 좋지만, 은유와 행동을 잇는 반 문장이 없다.

### P1-4 · "봉인" 버튼이 첫 만남에서 자기 뜻을 말하지 않는다

- 세션 끝 결과물 카드의 금색 버튼 "결정으로 봉인"(`CurrentBearingCard.tsx:154`)과 검수 경로의 "후속 예측 봉인하기"(`ReceiptView.tsx:240`)는, 누르기 전에는 무엇이 일어나는지("정한 날 다시 물어준다") 알 길이 없다. '봉인'은 일상어에서 "잠근다/못 바꾼다"는 어감이라, 조심스러운 사람일수록 안 누른다 — 그런데 이 버튼이 바로 47/0 깔때기의 그 지점이다.
- 눌러 들어간 뒤의 설명은 이미 모범이다: `SealModal.tsx:67` "나중에 현실이 맞다/틀리다로 답할 예측을 하나 봉인합니다. Argus가 판단하지 않습니다 — 확인일에 당신이 정산합니다." 이 문장의 반 토막을 버튼 곁으로 이식하면 된다.

### P2-5 · 한국어 UI에 영어 낱말 "lean" 노출

- `SealModal.tsx:105` "지금 내 lean", `ReceiptView.tsx:354` "내 lean: …". 비개발자 한국어 사용자에게 lean은 무의미한 철자다. (BindCard와 SealMoment는 같은 개념을 이미 "지금 마음은 어디로 기울어요?"라고 일상어로 말한다 — 그 어휘를 그대로 쓰면 된다.)

### P2-6 · 영문 마이크로라벨 "LOG ENTRY" / "ON FILE"

- `SirenHero.tsx:278,395`, `workspace/page.tsx:610`. 한국어 병기("결정을 적는다" / "문서를 올린다")가 항상 붙어 있어 뜻은 통하지만, KO 로케일에서 첫 시선이 영어 대문자에 먼저 닿는다. 정체성 스타일(모노 활자)은 유지하되 KO에서는 한국어를 앞세우는 게 문턱을 더 낮춘다. (우선순위 낮음 — 병기 덕에 실패하진 않는다.)

### P2-7 · 검수 목록 버튼 "내 항로"

- `ReviewFlow.tsx:499`(입력 화면 우상단), `:325`(영수증 화면 "← 내 판단 항로"). 검수 문맥에서 '항로'가 "내가 검수한 문서들 목록"이라는 걸 첫 방문자는 유추하기 어렵다. 다행히 이 버튼은 기록이 1건 이상일 때만 뜬다(:497) — 즉 두 번째 만남부터라 심각도는 낮다.

### P2-8 · 히어로 주석 드리프트 (개발자용 메모)

- `SirenHero.tsx:8-12` 주석이 ForkPath 모티프·프라이버시 노트·데모 경로를 서술하지만 현재 코드에는 셋 다 없다. 사용자 영향 0, 다음 수정자가 헤맬 뿐. 주석만 갱신.

## 스파인 충돌 검토

- **S1~S7 전부 "서술 추가/이름 통일"이며 판정·점수·기울어진 조언이 없다.** 새 카피는 모두 기계 상태(읽고 있어요), 기능 정의(봉인 = 정한 날 묻기), 사실 서술(무료·30초)만 말한다.
- S3-2의 오디세우스 반 문장은 사용자를 평가하지 않고 행동의 이유만 잇는다. BindCard의 SPINE INVARIANTS(스킵 지배, 프리필 금지, 포크 금지 — `BindCard.tsx:16-21`)는 손대지 않는다.
- S2의 "내용은 분석에만 쓰여요"는 가이드 FAQ의 기존 약속(`guide/page.tsx:116` "분석에만 쓰여요. 사람에게 전달되지 않고…")과 동일 문장 계열이라 새 약속을 만들지 않는다. 단, 04-betrayal이 지적한 "메일·알림은 보내지 않아요" 모순(guide:124)과 달리 이 문장은 실동작과 일치함을 확인했다.
- "30초 안에 첫 읽기" 주장은 이미 랜딩에 2회 존재하는 문장(Act2:113, Act3:127)의 위치 이동/복제라 새 성능 약속이 아니다. 다만 실측이 20~40초(workspace:888 "보통 20~40초")이므로, 정확성을 위해 S2 문안을 **"30초 안팎"** 으로 다듬는 선택지도 명시해 둔다: `로그인 없이 무료 · 30초 안팎이면 첫 읽기가 와요`.
- 어휘를 버리는 제안은 없다(뺄셈 아님·대체 아님): 봉인·정산·항로·방위·묶기 전부 유지, 첫 만남에만 다리를 놓는다. 유일한 개명 제안 둘(S1-4 갈래 칩, S7 검수 버튼)은 고유 어휘의 **오용 지점**(딴 뜻/딴 맥락) 정리다.
