## 0. 문제

Argus를 MCP/플러그인으로 지은 의도: **사용자의 실제 작업 흐름 속에서 판단을
수동적으로 포착**하는 것. 사용자가 예측·전제를 받아쓰게 하는 양식이 아니라,
어시스턴트가 **알아채는** 것.

핵심 질문(창업자): *"감지를 제대로 체계적으로, 구조적으로, 코드로 하는가?
100% 안 되면 최대한 더 높게."*

## 1. 확인된 사실 (추측 아님 — 코드/스펙/검색으로 확인)

### 1.1 MCP 감지는 2층이고, 코드가 될 수 있는 건 한 층뿐

- **서버는 대화를 못 본다.** MCP는 클라이언트가 부를 때만 서버가 깨어나고,
  JSON-RPC로 **구조화된 툴 인자만** 오간다. `argus_open_decision`이 받는 건
  `decision`(중립 한 문장)·`status_quo`·`load_bearing_assumption` 같은 **이미
  추출된 필드**이지 대화 원문이 아니다 (open-decision.ts에서 확인).
- 따라서 *"대화 중 알아채기"* 그 행위는 **구조상 호스트 모델의 몫**이다.
- **`"100% 코드 감지"라고 주장하지 말 것.** 프로토콜상 불가능하다.
- 반면 **알아챈 뒤의 루프**(기록·상태전이·정산·귀환)는 코드가 결정론적으로
  소유한다. 여기는 전부 코드로 검증·수정 가능하며, 실제로 그렇게 했다(§2.1).

### 1.2 상향 경로 2개 — 하나는 오늘 막혀 있고, 하나는 열려 있다

| 경로 | 무엇 | 현실 |
|---|---|---|
| **MCP `sampling`** (`sampling/createMessage`) | 서버가 클라이언트 LLM에 역으로 추출을 요청. mem0의 자동-메모리가 이 패턴(대화 넣으면 저장명령 없이 사실 추출; extraction→update 2단계) | ❌ **Claude Desktop/Code 미지원** (anthropics/claude-code#1785 오픈). 이론상 최강이나 오늘 안 돎 |
| **플러그인 hooks** | `UserPromptSubmit`이 매 프롬프트마다 **모델보다 먼저** 결정론적으로 실행되고, stdout이 컨텍스트로 주입됨 | ✅ **호스트-독립, 오늘 작동.** Claude에서 유일한 구조적 방아쇠 |

`elicitation`(서버→사용자 out-of-band)은 호스트 게이트(Desktop 지원). 이미
ambient 정산 픽커에 사용 중.

### 1.3 MCP 서버가 모델 컨텍스트에 닿는 통로는 4개뿐

1. `SERVER_INSTRUCTIONS` — 접속 시 **1회**
2. **툴 설명** — 항상 컨텍스트에 존재 ← *가장 저평가된 통로, 미탐색*
3. **툴 결과** — Argus 툴을 부를 때만
4. `elicitation` — 사용자에게, 지원 호스트만

→ **MCP엔 "매 턴" 방아쇠가 프로토콜에 없다.** 이것이 현재까지 확인한 벽이다.

### 1.4 코드가 이미 계획해뒀던 것

플러그인 `scripts/lib/decision-signals.js`의 원래 주석:
> *"purely DETERMINISTIC keyword scan (NO LLM — **that is Layer 2, later**)"*,
> *"Conservative recall on purpose… **Layer 2 widens later**."*

즉 Layer 2는 불가능이 아니라 **미뤄둔 것**이었다.

### 2.2 Layer-2 결정론 감지기 (`0047c0fa`)

`argus-mcp/src/lib/detect-signals.ts` — 순수·무의존 규칙 스캔, 3감각:

- `prediction`: 양상어 ∧ (측정치 ∨ 완료동사)
- `outcome`: 과거형 종결 ∧ 열린 예측과 토큰 겹침(한국어 조사 대응 접두 매칭)
- `assumption`: 조건·인과 마커 ∧ 하중 단서

사용자의 말 그대로(`span`)를 반환하고 지어내지 않는다. 규칙이라 **테스트가 핀함**
(LLM-glue 불변식: plausible이 correct인 척 불가). 13 테스트 통과.

### 2.3 플러그인 훅 배선 + 드리프트 가드 (`2242a798`)

- 플러그인은 MCP를 `npx -y argus-decision-mcp@^1`로 온디맨드 로드해 컴파일
  감지기에 못 닿음 → `decision-signals.js`에 **CJS 미러**(패턴 verbatim).
- **행동 드리프트 가드** `detect-signals-drift.test.ts`: 두 구현을 같은 코퍼스로
  돌려 결과 일치를 CI가 강제 (문자열 비교보다 견고).
- `scripts/sense-signal.js` — 신규 `UserPromptSubmit` 훅. 매 턴 스캔 → 감각이
  잡히면 **사용자의 말 그대로**를 담은 출처-명시 원샷 넛지 주입.
- 발사 게이트 보수: 세션당 1회 · 선택적 · 스킵이 최종 · flat이면 침묵 ·
  MCP 없으면 조용히 무시. 실호출 하네스 **6/6**.

### 2.4 raw-MCP 정렬 (`7be7e3e3`)

raw-MCP엔 대화 원문이 없으므로 **서버-측 감지 floor와 sampling seam은 dead
wire** → honest-structure 불변식대로 **짓지 않았다.** 대신 모델-센서
(`SERVER_INSTRUCTIONS`)를 결정론 감지기와 **같은 구체 단서**에 정렬:
감각1 "the tell = 방향/목표 + 지평 또는 숫자", 감각3 "the tell = 결정이
뒤집힐 as long as/because/only if 조건절".

*(선행: `9c92b3e9` — SERVER_INSTRUCTIONS를 3감각 상시 배경감각 중심으로 재작성)*

## 3. 창업자 지적으로 드러난 설계 교정 ⚠️ **가장 중요한 절**

구현 직후 창업자가 정확히 찌른 것들. **다음 세션은 여기서 시작한다.**

### 3.1 규칙은 감지기가 될 수 없다 — 특히 전제에서

> *"우리는 사용자와 AI의 상호작용 중에 그 이면에 있는 **숨은 전제**들까지 다
> 직접 뽑아내는 걸 중요한 value로 내세우지 않았던가."*

**정확한 지적.** `~하는 한 / as long as` 같이 **표시된** 전제는 쉬운 10%고,
Argus의 가치는 **표시되지 않은 90%**다. 숨은 전제는 정의상 표지가 없으므로
**규칙으로는 원리적으로 불가능**하다. 여기는 AI 말고 답이 없다.

### 3.2 올바른 구조 — 방아쇠와 감지의 분리

| | 현재 (틀림) | 바뀌어야 |
|---|---|---|
| 방아쇠 | 훅 = 매 턴 ✅ | 그대로 (이것이 구조적 이득) |
| 감지 | **규칙(정규식)** ❌ | **AI 의미 판단** |
| 규칙의 역할 | 주 감지기 | 비용 아끼는 사전필터 + 못 흔들리는 최저선 |
| 진단 시점 | 사용자 메시지만 | 턴 전체(`Stop`) 진단 → 다음 턴 개입 |

훅이 매 턴 하는 일은 "규칙으로 잡기"가 아니라 **"AI에게 이번 턴을 진단하라고
결정론적으로 시키기"**여야 한다. 그러면 AI의 의미 이해력(숨은 전제 포함)을
쓰면서도 잊어버릴 수 없게 강제된다. **훅의 가치는 규칙이 아니라 매 턴 재주입.**

### 3.3 개별 구멍들

- **"확인 가능한 주장" 기준이 조잡함.** 현재 `미래표지 + (숫자|완료동사)`는
  "이 방향이면 3분기쯤 무리가 올 것 같은데"를 놓친다. 진짜 기준은
  *"참/거짓으로 판명될 미래 상태를 함의하는가, 언제 판명되는가"* — 판단이지 패턴이 아님.
- **대명사 참조로 결과 대조가 깨짐.** 토큰 겹침은 "**그거** 잘 됐어"를 못 잡는다.
  AI는 맥락으로 "그거=서버 이전"을 안다. → 코드의 일은 대조가 아니라 **열린 예측
  목록을 AI 눈앞에 놓아주는 것**(check_in `open_predictions`가 이미 함), 대조는 AI.
- **잡담 구분도 의미 판단.** 현재 규칙은 잡담을 구분하는 게 아니라 "주장 형태"를
  볼 뿐. 코드는 명백한 것(질문·명령·초단문)만 미리 걸러 비용 절약.
- **진단 시점이 반쪽.** 전제와 추론은 **AI가 답하는 과정에서 더 많이 드러나는데**
  현재 훅은 사용자 메시지만 본다.

### 3.4 미결 — 창업자 답변 대기 → **답변됨 (2026-07-20 후속): (b) 확정, §7에 시공 기록**

규칙 감지기를 **(a) AI 감지로 갈아엎을지 (b) 사전필터로 강등하고 그 위에 AI
감지를 얹을지.** 세션 종료로 미답. **추천은 (b)** — 규칙은 공짜고 안 흔들리니
최저선으로 남기고, 판단은 AI가.

## 4. 더 찾아내야 할 것 (다음 세션 작업 아이디어)

### 4.1 MCP에서도 반드시 되게 — 창업자 강한 요구, 미탐색 3갈래

> *"플러그인 말고 MCP에서도 해야만 해. 방법을 반드시 찾아야 하고, 찾을 수 있을 거라고 생각함."*

1. **툴 설명을 상시 지침 통로로.** 툴 설명은 **항상 컨텍스트에 있다** — 접속 시
   1회인 instructions와 달리 매 턴 존재한다. 감지 지침을 여기 심으면? 실측 필요:
   모델이 툴 설명의 행동 지침을 실제로 얼마나 따르는가.
2. **툴 결과마다 지침 갱신.** Argus 툴 호출 시마다 짧은 "감각 갱신" 라인을 결과에
   실어 재주입. 한계: Argus를 안 쓰는 턴엔 못 닿음(순환).
3. **최신 MCP 스펙에 새 메커니즘이 있는지** — tasks, notifications, MCP Apps/
   extensions. 이번 세션 검색이 도중 불능이 되어 **미완**. 최우선 재개 항목.

추가 갈래:
4. **sampling 지원 로드맵 추적**(#1785). 지원되는 순간 서버-주도 추출이 열린다.
5. **다른 호스트의 sampling 지원**(Cursor / VS Code / Windsurf) — 지원 호스트에선
   **지금도** mem0식 서버-주도 추출이 가능. raw-MCP 사용자 일부는 이미 구제 가능.
6. **Claude Desktop에 hook 등가물이 있는지** (Skills·connectors 등).

### 4.2 감지 품질 — 지금 **측정 자체가 없다**

7. **감지 품질 측정 하네스가 최우선.** 실제 대화 코퍼스에 라벨(예측/결과/전제/
   잡담)을 붙여 recall·precision을 재는 장치가 없으면, 규칙→AI 전환이 나아진
   건지 알 방법이 없다. **개선보다 측정을 먼저 지어야 한다.**
8. **AI 감지 프롬프트 설계** — 무엇을 물을 것인가. 특히 숨은 전제를 끌어내는
   질문 형태(스파인: 평결 금지, 포크 금지, 한 개만).
9. **열린 예측 목록 주입 방식** — 압축·상한·어느 시점에.
10. **숨은 전제 심층 패스 타이밍** — 매 턴은 과하고 비싸다. 결정 형성/종결
    시점에만? `Stop` 훅에서?
11. **비용 관리** — 매 턴 AI 감지의 토큰 비용. 사전필터로 언제 스킵할지.

### 4.3 발사 정책 (스파인)

12. **3훅 조율** — anchor(결정 시작)·ambient(due 결과)·sense(내용 감각)가 합쳐서
    over-fire 하지 않도록. 현재 각자 세션당 1회.
13. **도그푸딩 튜닝** — 발사 빈도는 창업자가 실사용으로 정할 스파인급 판단.

## 5. 잊지 말 것 (스파인 제약)

- **max detect, min fire.** 감지는 고-recall, 발화는 절제. **over-fire도 스파인
  위반**(mirror clause) — 감지를 넓히는 것과 더 자주 말 거는 것은 다른 일이다.
- **숨은 전제 추출이 제품 가치의 핵심.** 표면 전제만 모으는 건 Argus가 아니다.
- **죽은 배선은 짓지 않는다.** 통로가 없으면 채워 넣지 말고 정직하게 비운다
  (raw-MCP floor를 안 지은 이유).
- **"100% 코드 감지"라고 쓰지 말 것.** 프로토콜상 불가능하고, 그 주장 자체가
  신뢰를 깬다.

  진짜 모호한 예측이 falsifiability 게이트를 통과했다.
  - `"The launch will probably go well for the team."` → **"launch"**(명사)가 앵커로 매칭
  - `"이번 출시는 잘 될 것 같다 아마도"` → **"출시"**가 앵커로 매칭
  - 즉 완료-단어 하나가 명시적 얼버무림("probably/아마도/것 같다")을 무력화.
- **적용한 수정(워킹트리, 미커밋):** 앵커를 **HARD/SOFT로 분리**하고 **HARD만**
  vibe 검사를 무력화하도록 변경. 손-동기화 미러 **양쪽 모두** 수정:
  - `argus-mcp/src/lib/validate-seal.ts` (정본): `OBSERVABLE_ANCHOR` → `HARD_ANCHOR`
  - `argus-plugin-v2/scripts/validate-gates.mjs` (미러): 동일
  - `HARD_ANCHOR = /\d|[%<>=≤≥]|(이상|이하|미만|초과)|\b(at least|more than|less than|no more than)\b/i`
  - 완료 단어(ship/launch/출시/배포/계약/완료/체결/도달/달성/넘는…)는 앵커에서 제외.
- **1.4.6 과발화 재발 아님:** vibe 검사는 vibe 문구가 **있을 때만** 돌므로,
  `"we ship the app by Friday"`처럼 vibe 없는 완료형 예측은 그대로 통과한다.
- **손 검증 완료(실행은 못 함 — 세션 말 도구 불능):** 플러그인 29 케이스와 MCP
  `validators.test.ts` 6건 + `seal-confirm-draft.test.ts:81`을 대조해 전부 양립 확인.
  나머지 케이스는 `goodSeed.predicate`(vibe 문구 없음)를 써서 영향 없음.
