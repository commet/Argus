# Argus 인계 문서 — 2026-08-07

**지위: 비규범 (인계).** 이 문서는 정본이 아니다. 규범을 정하는 것은
`ARGUS-METHOD-V1.0.md`(방법)와 `ARGUS-BLUEPRINT.md`(빌드 순서)이고, 그 둘과
충돌하면 언제나 그쪽이 이긴다.

이 문서의 목적은 하나다 — **다른 세션이 처음부터 다시 알아내지 않게 하는 것.**
그래서 의도적으로 굵게 썼다. 다음 사람이 "무엇을 해야 하는지"까지 여기서
받아 가면 그건 인계가 아니라 구속이고, 이 리포에서 좋은 판단은 대부분 코드를
직접 대조하다가 나왔지 문서를 읽다가 나오지 않았다. 아래 §6은 **방향과 이유**만
적고 설계는 비워 둔다. 비어 있는 것이 실수가 아니다.

## 1. 지금 서 있는 자리 (한 문단)

Argus는 "사람들이 이미 있는 곳(채팅)에서 결정을 붙잡고, 계획을 세우고, 기한이
되면 현실로 돌아와 정산하는" 원격 MCP 서버다. 그 위에 **판단 분신(TWIN)** 이
얹혀 있다 — 사용자가 결정할 때 분신도 같은 시험을 치고, 답안을 봉인했다가,
정산 시점에 현실과 나란히 열어 채점받는다. 배관은 대부분 깔렸고 게이트도
초록이다. **그런데 실사용자가 아직 한 명도 통과한 적이 없다.**

### 이 구간의 방법론 — 이게 산출물보다 중요하다

**감사를 먼저 기계로 만들고, 그 기계가 다음에 지을 것을 고르게 했다.**
`twin-wiring.test.ts`(선언↔소비 가드)를 쓰자마자 구멍 둘이 즉시 튀어나왔고,
그중 하나가 이 제품의 심장이었다 — **판단 프로필이 쌓이기만 하고 절대 줄지
않았다.** 반례 컬럼 셋이 죽어 있었고 확신도가 첫인상에 얼어붙어 있었다. 즉
"일할수록 쌓인다"는 핵심 주장이 구조적으로 반증 불가능했다. 같은 규율이 나중에
"M5는 지을 수 없다"는 **내 기획 판단 자체가 틀렸다는 것**도 드러냈다 (사용자
사전등록 확신도는 이미 `materialBeliefs`로 존재했다).

교훈 한 줄: **선언↔소비 구멍은 코드만 오염시키지 않는다. 기획 판단까지 오염시킨다.**

## 3. 무엇이 실제로 돌았고, 무엇이 아직인가

> **2026-08-09 갱신 — 이 절의 제목이 바뀌었다.** 원래 "아직 **한 번도** 돌지
> 않은 것"이었고, 그때는 맞았다. 지금은 아니다: 프로덕션 `/api/mcp/v2` 를
> 도그푸드 계정 + `argus.decisions` PAT 으로 **커넥터와 같은 방식으로 두 번
> 완주했고**(인테이크 포함 전 도구), 원장을 SQL 로 대조했다. 플라이휠이 돌았다.

**그 두 번이 결함 다섯을 걸어냈다** (#359, #360). 전부 같은 형태다 — 그럴듯한
성공 응답 뒤에서 조용히 틀리는 것:

- 통과한 짚기가 원장에 안 남았다 (응답은 "기록했습니다"라고 답하는데)
- 안내문이 약속한 귀환 경로가 막혀 있었고, 우회하면 관찰이 이중 기록됐다
- 성공한 append 가 `isError` 로 신고돼 호스트 모델이 실패로 읽었다
- 귀환 없이 채택만 한 케이스가 "이미 정산이 끝났습니다"로 막혔다 — 정산은
  시작도 안 했는데. 그 경로의 케이스는 영영 정산 불가였다
- 그 수리 중, 연쇄 귀환의 `return_closed` 리셋 때문에 fold 상태로는 "정산된 적
  있음"을 판별할 수 없다는 것이 드러났다 (판별자는 원장의 `record_revealed` 실존)

**이 다섯을 CI 도, 5,500개 테스트도, 이 문서의 어떤 가드도 잡지 못했다.**
전부 실제로 한 번 몰아 보고 **원장을 SQL 로 대조해서** 나왔다. 다음 사람이
이 절에서 가져갈 것이 있다면 그것이다 — 정적 검사와 실주행은 다른 종류의
증거이고, 이 제품에서는 후자가 압도적으로 비싸다.

**아직 안 돈 것:**

1. 실제 **커스텀 커넥터** 왕복 (Claude 호스트 UI ↔ 서버). 위 완주는 PAT 을 들고
   같은 방식으로 몬 것이지 호스트가 붙은 것은 아니다 — OAuth 정문 넷은 동작
   테스트로만 덮여 있다(#358)
2. 봉인 → 정산 → 개봉의 **한 사이클 전체**가 실데이터로
3. 프로필 추출·위임 채점·시뮬레이션 극장 — 표본이 쌓여야 의미가 생긴다

**커넥터를 붙이기 전에 확인할 것 (2026-08-09 추가).** 프로덕션에
`ANTHROPIC_API_KEY` 가 실제로 있는지부터 본다. 없으면 결정은 정상적으로 열리고
기록되지만 **봉인 예측이 하나도 만들어지지 않는다** — 봉인은 `after()` 안의
부가 기능이라 사용자 흐름을 막지 않는 것이 옳고, 크론 백스톱이 재시도하므로
코드에는 결함이 없다. 문제는 그 상태에서 보이는 것이 "잠김 0건" 하나뿐이고
그것이 **"아직 결정을 안 열었다"와 구분되지 않는다**는 것이다. 스키마 진단은
전부 초록인 채로. 이제 설정 화면이 그 경우에만 원인을 이름으로 말한다(#358).
4. **분신의 집을 브라우저에 띄워 눈으로 본 적이 없다.** 이 컨테이너에는
   Supabase 키가 없어 `/[locale]`이 500이고, 프리뷰 배포는 네트워크 정책이
   CONNECT 단계에서 403으로 막는다(둘 다 시도해서 확인). 대신 렌더 테스트
   9개로 분기별 동작을 기계로 고정해 뒀다 — 봉인 본문 미노출, 못 읽음 ≠ 없음,
   표본 미달 시 숫자 감춤 등. **다만 그것은 조판·간격·색이 실제로 어떻게
   보이는지는 말해 주지 않는다.** 첫 실사용자가 이 화면을 볼 때 눈으로 한 번
   보는 것이 남아 있다

**창업자만 할 수 있는 것 둘:**

- **커스텀 커넥터를 실제로 붙이는 것.** 위 §3-1 의 유일한 열쇠다. PAT 으로 몬
  것과 호스트가 OAuth 로 붙는 것은 다른 경로이고, 후자는 아직 아무도 안 지나갔다.
- **GitHub Actions 시크릿 `DOGFOOD_EMAIL`/`DOGFOOD_PASSWORD` — 재실측에서도 실패.**
  **여기서 두 가지를 섞지 말 것:** 도그푸드 계정이 **PAT 으로** 프로덕션 도구를
  부를 수 있다는 것(#359 에서 실증)과, 그 계정이 **이메일+비밀번호 로그인**으로
  들어가진다는 것은 다른 사실이다. CI 의 `live-loop` 는 후자를 쓴다.

  실측 2026-08-09 08:26 (`main` 에서 workflow_dispatch, 실행 31303350525):
  · **익명 루프는 초록** — 프로덕션에서 봉인까지 완주했다(2분 52초). 즉 앱도

    **그 조합 자체가 프로덕션에 없다.**

## 4. 이 리포에서 반복해서 무는 함정

`CLAUDE.md`가 정본이고 여기 적는 것은 **최근에 실제로 물린 것들**이다.

- **로컬 초록 → CI 빨강.** `npm test`는 커버리지를 안 재는데 CI는 잰다.
  큰 파일을 테스트 없이 추가했으면 `npx vitest run --coverage`를 먼저 돌린다.
- **조용히 깨지는 배선 여섯 종류.** ① 선언만 하고 소비 안 되는 필드,
  ② 어디서도 링크 안 된 라우트, ③ 정의 안 된 CSS 변수, ④ `argus_*` 에 없는
  컬럼을 쓰는 service-role 경로(PostgREST 가 행 **전체**를 거부하고 에러는
  로그로만 간다), ⑤ RLS 없이 나가는 사용자 테이블, ⑥ 없는 환경변수로 조용히
  무력화되는 파이프라인. **여섯 다 에러가 아니다** — 빌드·타입·테스트를 전부
  통과하고 화면에서만, 혹은 프로덕션에서만 틀린다. 여섯 다 이제 가드가 있다
  (`twin-wiring` / `route-reachability` / `css-token-contract` /
  `argus-write-contract` / `rls-coverage` / `twin/status` 의 `engine` 보고).
- **정적 SQL 스캐너는 동적 DDL 을 못 본다.** `epistemic_*` 여섯 테이블은
  `DO $$ … EXECUTE format('ALTER TABLE %I ENABLE ROW LEVEL SECURITY')` 로 RLS 를
  켠다. 이것을 모르는 스캐너는 **영구 오탐**을 내고, 영구 오탐은 곧 무시되며,
  무시되는 검사 옆에서 진짜 누락이 지나간다. `rls-coverage` 가 DO 블록을 읽는다.
- **고쳤으면 가드를 남긴다.** 미정의 CSS 변수는 이번이 **세 번째 재발**이었다.
  앞의 두 번은 고치기만 하고 가드를 안 남겨서 다시 왔다.
- **전체 `vi.mock`은 그 모듈의 다른 export를 전부 없앤다.** 상수를 추출하는
  순간 임계값이 `undefined`가 되어 비교가 조용히 무너진다. 부분 목을 쓴다.
- **면제 목록을 추측으로 채우지 않는다.** 도달 가능성 가드의 면제를 일곱 개
  적었다가 전부 확인 없이 쓴 것임을 깨닫고 셋으로 줄였다 (`terms`·`privacy`는
  `Footer`가 이미 링크하고 있었다).

## 5. 살아 있는 자산 지도 (다음 사람이 모르면 다시 만들 것들)

- **`/tools/review`** — 기존 문서·계획·AI 답변을 붙여넣거나 올려서 근거에 앵커된
  검수 영수증을 받는 표면. 랜딩·워크스페이스에서 도달 가능하고 산출물이
  `review_receipts`로 실제 소비된다. **콜드 스타트의 이미 지어진 답이다.**
- **`/import`** — 플러그인 원장(`.argus/ledger/`) 동기화. 가져온 기록은 절대
  자동 승격되지 않고 "내 판단으로 다시 기록" 버튼을 거친다 (저자성 불변식).
- **`argus-plugin-v2`의 `/argus:history scan`** — 과거 대화에서 결정 *후보*를
  복원한다. 봉인은 안 하고 후보만 남긴다.
- **`method-harness/`** — 모델 없이 도는 결정론 검증기. `src/`와 무접촉.
- **`epistemic/control-plane.ts`** — 파생 기억 영향력의 유일한 권위.
  trace를 못 남기면 영향력 0으로 fail-closed.

### (A) 첫 3일 안에 "어떻게 알았지?" 순간을 만드는 것 — 최우선

이 제품의 가장 큰 위험은 기술이 아니라 **첫 수익(return)이 너무 늦는 것**이다.
지금 구조는 정직하게도 정산 시점에 가치가 발생하는데, 그 시점이 몇 주 뒤다.
그때까지 사용자는 아무것도 못 받는다.

창업자가 지적한 답의 씨앗이 이미 있다: **사용자가 이미 쓴 것에서 시작한다.**
과거 문서·기존 로그·지난 대화를 읽고, 날카로운 질문 몇 개로 감을 잡고, 첫
return을 그 자리에서 준다. 웹에는 `/tools/review`가 그 형태로 이미 서 있다.

이 절이 처음 적은 문제는 **비대칭**이었다: 웹에는 답이 있는데 실제 입구인
채팅의 원격 도구 여섯 개는 기존 자료를 하나도 받지 못했다.

> **해결됨 (2026-08-09, PR #357).** `argus_open` 에 `materials` 입력이 열렸다.
> 여섯 도구 서약은 유지하고 새 도구를 만들지 않았다. 핵심 규율 셋:
> 자료는 하네스의 `external_source` 슬롯에 **증거로만** 들어가 재derivation 에는
> 쓰이되 `baseline` 을 절대 채우지 않는다(저자성 세탁의 뒷문 차단); 인용은
> 원문 그대로만이고 상한(8건·1200자)을 넘으면 **자르지 않고 거절한 뒤 그 사실을
> 말한다**(절단된 인용은 인용이 아니고, 조용한 드롭은 모델이 기록됐다고 믿게
> 만든다); 자료를 읽고 가정 후보를 뽑는 것은 호스트 모델의 일이라 서버는 LLM 을
> 부르지 않는다.
>
> 검증(2026-08-09): 자료 인용문이 **봉인 프롬프트에 닿지 않는다.** 그림자 시험에
> 넘어가는 opening 은 `utterance`·`lean`·`statedReasons`·`consideredAlternatives`
> 뿐이고, 크론 백스톱도 `user_utterance` 이벤트만 읽는다. 즉 외부 문서 문장이
> 분신의 예측을 오염시키는 경로가 없다.

**그래서 이 절에 남은 것은 "입구가 없다"가 아니라 "그 입구가 실제로 첫 return 을
주는가"다.** 자료를 받는 것과, 받은 자료로 3일 안에 "어떻게 알았지?"를
만드는 것은 다른 문제다. 후자는 아직 실사용자가 통과한 적이 없다.

주의할 것 둘 — 둘 다 스파인 위반으로 이어진다:
- 문답이 **심문**이 되면 안 된다. 과발화 금지(거울 조항)는 여기에도 적용된다.
  #357 이 "한 번에 하나만 확인한 뒤 `argus_sharpen`" 으로 못박아 뒀다.
- 읽은 자료에서 뽑은 문장이 사용자 소유 필드를 조용히 물려받으면 안 된다
  (`authored:'user'` 불변식). `/import`의 "다시 기록" 버튼이 그 선례이고,
  #357 의 `external_source` 경계가 같은 규율의 원격판이다.

### (B) 실사용 1회를 통과시키는 것

§3의 전부가 여기 걸려 있다. 코드를 더 쓰는 것보다 이게 먼저다.

### (C) 실데이터가 생긴 뒤에야 의미가 생기는 것들 (그 전엔 짓지 않는다)

보정 거울의 도메인별 분해, 극장 페이지네이션, 신뢰 사다리의 다음 칸.
표본 없이 지으면 숫자가 소음이고, 소음을 노출하면 판정 금지 원칙을 어긴다.

### (D) 갚아야 할 빚

`src/lib/epistemic/`에 소비되지 않는 export가 49개 있다(래칫으로 상한만
고정해 둠). §8 판정 과제다 — 살릴 것과 지울 것을 가르는 일이지 새로 짓는
일이 아니다.

## 7. 마지막으로 — 이 제품에 대한 정직한 한 문장

정직함은 이 제품의 **철근**이지 사람들이 타러 오는 **놀이기구**가 아니다.
사람을 데려오는 것은 "어떻게 알았지?" 순간이고, 붙잡는 것은 정산 때 열리는
봉투다. 정직한 구조는 그 둘이 가짜가 되지 않도록 떠받칠 뿐이다.

랜딩 카피를 "우리는 판정하지 않는다"로 쓰지 않는 이유도 같다 — 잔여 기울기는
비가역이라 그건 주장할 수 있는 상태가 아니다. `zero judgment`은 접근하며 공개
선언하는 **점근선**이다.
