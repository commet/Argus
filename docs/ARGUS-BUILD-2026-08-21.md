# 아르고스 시공 계획 — 무엇을 짓고, 무엇을 살리고, 무엇을 버리나 (2026-08-21)

> 기획서(`ARGUS-PLAN-2026-08-21-V5.md`)는 **무엇을 만들지**를 정했다. 이 문서는
> **어떻게 만들지**를 정한다. 코드는 한 줄도 안 짠다 — 기획서 머리의 `adopted`가
> 비어 있는 동안은 시공 0이 규칙이다.
>
> **이 문서를 쓴 이유**: 기획서가 기존 코드를 *"박물관(동결) — 재사용하는 것은
> 기계가 아니라 배운 것"*이라 한 줄로 처분했는데, **실측해 보니 그게 과했다.**
> 안 보고 처분하면 이미 있는 것을 다시 짓거나, 살아 있는 것을 지운다.

## §0. 시공 세션 규약 — 이 문서를 살아있게 쓰는 법

> **이 문서는 읽고 치우는 계획서가 아니라, 시공 기간 내내 대조하고 고쳐 쓰는
> 작업 문서다.** 계획에 오류가 남아 있어도 — 반드시 남아 있다 — 아래 규약이
> 그것을 구현 중에 잡는다. 규약 자체가 이 제품의 원리(계획도 결정이고, 결정은
> 현실과 대조해 닫는다)의 자기 적용이다.

**세션을 시작할 때 (시공 작업이면 반드시):**
1. 이 문서의 **§9 시공 일지 마지막 5줄**과 **§5 순서표의 현재 단계**를 읽는다.
2. 지금 하려는 단계의 **"됐다"의 정의**를 소리 내어 옮겨 적는다 — 정의를 안
   읽고 시작한 작업은 끝났는지 판정할 수 없다.
3. 그 단계가 닿는 파일이 **§4 처분표에서 "읽고 다시 판정"이면, 지금 읽는다.**
   판정 결과를 §9에 한 줄 적기 전에는 그 파일을 고치지도 지우지도 않는다.
4. **누락 점검 — 계획에 *있어야 할 것이 빠졌는지* 묻는다.** (2026-08-21 추가:
   배포 구성이 기획서에 아예 없던 것을 규약이 못 잡고 창업자가 잡았다. 규약에는
   *"계획에 없는 걸 만나면 멈춘다"*만 있었고 *"계획에 있을 것이 없다"*를 보는
   눈이 없었다.) 지금 단계에 대해 넷을 묻고, **하나라도 계획서에서 답이 안
   나오면 그것이 공백이다** — §9에 "공백:"으로 적고 3-(a)/(b)로 처분한다.
   - **어디에 실리나** — 이게 어느 배포 단위에 들어가나(플러그인 · 엔진 · 웹앱).
     계획서가 그 단위를 이름으로 부르나.
   - **누가 부르나** — 부르는 것이 실재하나(훅 · 도구 · 명령). *"AI가 그 문서를

   - **사용자가 뭘 보나** — 화면에 나갈 문장이 계획서에 있나. 없으면 U6 규율로
     지금 쓰고 §9에 남긴다.
   - **틀리면 뭐가 보이나** — 조용히 넘어가는 자리가 있나. 있으면 그 자리부터.

**단계를 닫을 때 (하나라도 빠지면 안 닫힌 것):**
1. **"됐다"의 정의를 명령으로 실증한다** — 실행한 명령과 출력 요지를 §9에 적는다.
2. **일부러 한 번 깨뜨린다** (이 저장소의 '주입 확인' 관행): 방금 만든 검사가
   실제로 빨간불을 낼 수 있는지, 핵심 한 줄을 뒤집어 확인하고 되돌린다.
   빨간불을 못 내는 검사는 검사가 아니다.

**계획이 틀렸다는 걸 발견했을 때 (반드시 이 순서로):**
1. **멈춘다.** 코드를 계획에 맞추려 우기지도, 조용히 계획을 벗어나지도 않는다.
2. §9에 적는다: 무엇이 달랐나 · 네 자리 확인(생산·저장·소비·표면 — CLAUDE.md

4. 같은 종류의 오류가 **두 번** 나오면 §6 함정 목록에 항목으로 승격한다.

**밀기 전에 도는 것 (2026-08-21, CI 를 두 번 빨갛게 만든 뒤 추가):**
로컬 초록이 CI 초록이 아니다. 두 번 다 **안 돌린 검사**에서 걸렸다.

```bash
cd argus-mcp && npx tsc --noEmit && npm test    # 엔진
cd argus-mcp && npm run verify                 # src/lib/ 를 고쳤으면 필수 (§6-9)
npm test                                        # ← 루트. **MIT 존만 고쳤어도 돈다** (§6-12)
node argus-plugin-v2/scripts/validate-plugin.js # 플러그인을 고쳤으면
node argus-plugin-v2/hooks/<새 훅>.test.mjs      # 새 훅을 더했으면
```

```bash
node scripts/check-reachability.mjs                 # ← 새 파일을 더했으면 필수
node scripts/check-capability-duplication.mjs origin/main
```

**`npx tsc --noEmit` 는 테스트 파일을 안 본다** (2026-08-21 발견).
`tsconfig.json` 의 `exclude` 에 `src/**/*.test.ts` 가 있다. 그래서 **import 를
빠뜨린 테스트가 tsc 초록으로 지나간다** — `os is not defined` 를 vitest 가
런타임에야 잡았다. 테스트를 고쳤으면 tsc 말고 **vitest 를 돌려서 확인한다.**

`verify` 에 대해 둘 (2026-08-21 실제로 걸림):
- **도는 동안 소스를 고치지 마라.** 이 하네스는 파일을 복사해 회귀를 심고
  **원본이 바이트로 안 변했는지** 확인한다. 도는 중에 `src/lib/` 을 고치면
  *"격리 자기검증이 원본을 바꿨다 — 배포 금지"* 가 뜬다. 제품 결함이 아니다.
- **`| tail` 로 받지 마라.** 파이프의 종료 코드는 `tail` 의 것이라 **실패가
  0 으로 보인다.** 위에서 실제로 ❌ 인데 exit 0 으로 읽었다. 파일로 받고
  `echo $?` 를 같이 남긴다.

**속도 규율:** 위 규약이 무겁게 느껴지는 날이 반드시 온다. 그날 버리는 것은
규약이 아니라 **그 단계의 크기**다 — 단계를 쪼개서 규약이 가볍게 돌게 만든다.
규약을 건너뛴 단계는 §5 표에서 "됐다"로 표시할 수 없다.

### §1-b. 배선을 끝까지 따라가 보니 — 한 곳이 끊겨 있다

**첫 보고는 틀렸다.** 파일 이름·줄 수·맨 위 주석만 보고 "있다"고 적었다. 주석은
*무엇을 하려 했나*이지 *무엇을 하나*가 아니다. 실제로 돌리고 따라간 결과:

**돌려서 확인한 것**: `npm run build` 통과 · `npm test` **143파일 1,297개 전부 통과**.
부품은 실재하고 테스트도 산다.

**따라가 보니 끊긴 곳**:

```
소비 쪽   check_in 도구 → drainCaptureOnCheckIn → capture-runtime.ts:65
          → runHarvestSweep                                        ✅ 이어져 있다
생산 쪽   capture-scan 명령 (argus-mcp/src/index.ts:17)             ✅ 있다
          ← 부르는 것: argus-plugin-v2/scripts/decision-ledger.js:750 ✅ 있다
            ← 부르는 것: **훅이 아니라 스킬 문서**
               (skills/review/pipeline.md · clarify.md)            ⚠ 여기가 문제
```

플러그인 훅은 12개 걸려 있는데(SessionStart 3 · UserPromptSubmit 3 · PreToolUse 2 ·
PostToolUse 2 · Stop 2) **그중 `decision-ledger.js`를 부르는 것이 하나도 없다.**
부르는 것은 스킬 마크다운이고, 그건 **AI가 그 문서를 읽고 셸 명령을 칠 때만 돈다.**

이 저장소는 이 패턴을 이미 알고 이름까지 붙여 뒀다 — `ARGUS-CORE.md` §6.2의
"참조 0의 아홉 이유" 중 다섯째: *"스킬 마크다운이 셸로 호출."* 죽은 코드가
아니라는 뜻이지만, **자동으로 돈다는 뜻도 아니다.**

**그래서 판단이 갈린다: 부품은 재사용하고, 배선은 재사용하지 않는다.**
지금 배선은 CLAUDE.md가 금지한 모양이다 — *"라우팅·순서는 결정론 구조가 갖고,
LLM은 셀 안의 창의 작업만."* AI가 그날 그 문서를 안 읽으면 수집이 안 된다.
→ **N6(아래)이 새로 생긴다.**

**세 번째 존을 빠뜨렸다**: 첫 보고는 `argus-mcp`와 `src/` 둘만 셌는데,
`argus-plugin-v2`가 **JS 6,674줄에 훅 12개**로 따로 있다. 훅 표면은 전부 여기다.

> **정정 (2026-08-21, 단계 0-b 착수 시).** 위 추적도 반쪽이었다. **경로가 둘이다.**
>
> ```
> 경로 A (자동)  SessionStart 훅 → hooks/session-start.js:62 이 큐에 harvest 항목을 넣는다  ✅ 자동
>                └ 그 큐를 **비우는** 것: capture-runtime.ts → runHarvestSweep
>                   ← 부르는 것: tools/check-in.ts:93 **하나뿐**              ⚠ 여기가 진짜 문제
> 경로 B (수동)  스킬 문서 → decision-ledger.js:747 → capture-scan 명령          (§1-b 가 본 것)
> ```
>
> 즉 **큐에 넣는 것은 이미 훅이 자동으로 했다.** 안 되던 것은 **비우는 것** —
> 대화를 실제로 읽어 후보로 바꾸는 일이 `check_in` 도구 안에서만 돌았고, 그건
> AI 가 그 도구를 부르기로 마음먹어야 도는 일이다. 결론(N6 이 필요하다)은
> 그대로지만 **N6 이 할 일이 달라졌다**: 넣는 훅을 새로 만드는 게 아니라
> **비우는 방아쇠를 훅으로 옮긴다.**

> **이 발견이 계획을 바꾼다.** 기획서 §4.2의 *"기존 커널 코드는 박물관(동결) —
> 재사용하는 것은 기계가 아니라 배운 것이다"*는 **틀렸다.** 배운 것만이 아니라
> **기계도 상당 부분 그대로 쓸 수 있다.** 다만 조건이 하나 있고, 그게 §3이다.

## §3. 진짜 갈림길은 하나뿐이었다 — 결정을 어디에 저장하나 【확정: B+】

나머지 모든 판단이 여기에 딸려 온다. **2026-08-21 확정됐다**: 창업자가 B+
기울기를 밝히고 최종 숙고를 지시 → 숙고가 같은 답에 도달 → 계획 본문(v5 §4.2)에
반영. `adopted` 서명이 함께 비준한다. 아래는 그 숙고의 전문이다 — 왜 A(위키형)와
B(읽기전용형)가 **둘 다 우리 자신의 문장에 의해** 탈락하는지.

### 두 안

| | **A안 — 마크다운 파일이 진실** (기획서 현행) | **B안 — 기록 파일이 진실, 마크다운은 사본** |
|---|---|---|
| 결정 1건 | `decisions/D-0012.md` 한 파일 | `~/.argus/.../ledger.jsonl`의 사건들 |
| 사람이 읽는 것 | 그 파일 | `decisions/D-0012.md` (기계가 만들어 준 사본) |
| 편집하면 | **법이 바뀐다** | **아무 일도 안 일어난다** (다음에 덮어써짐) |
| git | 역사 그 자체 | 사본의 역사 |
| 기존 코드 | 대부분 못 씀 | **8,296 + 4,572줄을 그대로 씀** |

### 왜 이게 그냥 취향 문제가 아닌가

**A안은 우리가 이미 찾아낸 결함을 되살린다.**

기획서 §4.10에 이렇게 적혀 있다 — *"평문이 서명 대리 불가를 무력화한다.
에이전트가 그냥 파일을 쓰면 되는 세계에서는 무의미하다."* 이건 우리가 스스로
공격해서 찾은 구멍이고, 처방으로 서명 봉인(키·해시)을 붙이기로 했다.

**B안에서는 그 구멍이 애초에 안 생긴다.** 확인은 도구를 거쳐야만 기록에 남고,
마크다운은 기계가 만든 사본이라 **AI가 그 파일을 아무리 고쳐도 법이 안 바뀐다.**
봉인 장치가 필요 없어지는 게 아니라, **없어도 반쯤 막힌다.**

그리고 이미 `v2/ledger.ts` 주석에 이 설계가 적혀 있다 — *"worktree의 .argus/에는
projection만 산다."* 우리가 예전에 같은 답에 도달했던 것이다.

### 무엇을 잃나 (정직하게)

- **"에디터가 곧 편집 도구"라는 그림을 잃는다.** 파일을 고쳐서 법을 바꾸는 건
  못 한다. 대신 `dec amend` 같은 명령을 써야 한다.
- **기획서 문장 하나를 고쳐야 한다** — §4.2의 *"git이 역사·동기화·병합을
  담당한다"* → *"git은 사람이 읽는 사본의 역사를 담당하고, 진실은 기록 파일이다."*
- **여러 대에서 쓸 때 동기화가 git 공짜가 아니다.** 다만 이것도 이미 있다
  (`v2/outbox.ts` + `tools/sync.ts` 400줄).

### 확정 (B+) — 그리고 왜 이것이 취향이 아니라 도출인가

**우리가 이미 서명하려는 문장 세 개가 세 안을 각각 판정한다:**

1. *"네 서명으로만 법이 되게"* (v5 §2 한 문장) → **A 탈락.** 에이전트가 파일을
   일상적으로 고치는 저장소에서 파일=법이면, **파일을 쓰는 모든 손이 서명자다** —
   사람 전용 서명이라는 유일한 차별점을 구조가 스스로 지운다.
2. *"모든 공백은 크게 실패하거나 정직하게 드러난다 — 조용히 메우지 않는다"*
   (CLAUDE.md 정직 구조 원칙) → **B 탈락.** 사용자가 파일을 고쳤는데 아무 일도
   안 일어나는 것은 조용히 끊긴 전선이다.
3. *"때가 되면 현실과 대조해 닫는"* (같은 문장) → **원장은 공통 비용.** 걸린
   횟수·다시 물은 날·답 같은 사건은 어느 안에서도 어딘가에 쌓여야 한다. A를
   골라도 사건 기록을 따로 지어야 하므로("진실이 두 군데" 병 — S2-3이 찾은
   두 법전 문제), 원장은 B+의 추가 비용이 아니다.

**유일한 생존자가 B+다**: 원장이 진실, 파일은 사람용 정본 표면, 손편집은
지문으로 감지해 "개정으로 받을까요?"로 회수.

**위키 유행에 대한 답** (창업자가 신경 쓴 지점): 그 유행이 실제로 검증한 것은
**"에이전트와 사람이 만나는 자리는 마크다운 파일"**이라는 표면 선택이고, 우리는
그 표면을 100% 그대로 쓴다(사용자가 만지는 것은 처음부터 끝까지 파일이다).
유행이 말하지 않는 것이 **"아무 손이 고친 것이 곧 진실"**이라는 권위 모형인데,
그 모형의 도달점이 지금의 CLAUDE.md다 — 아무나 고치고, 낡고, 세션의 절반이
무시한다. **이 제품은 위키의 병을 고치려고 존재한다. 위키의 권위 모형을 심장에
이식하면 병을 고치는 것이 아니라 병에 이름을 붙이는 것이다.** 그리고 개발자는
이미 "고치기"와 "역사로 만들기"가 다른 행위인 세계(git: 작업 트리 → 커밋)에
산다 — 편집=법이 오히려 그 세계의 예외다.

**B+가 위키의 미덕을 잃지 않기 위해 지켜야 할 약속 다섯** (시공 조건):
1. **파일 하나에 전부** — 문장·이유·그때의 원문·현재 상태. 원장을 열 일이 없다.
2. **편집은 벌 받지 않는다** — 고치면 다음 확인 때 시운전과 함께 "개정으로
   받을까요?" 한 타. 에디터로 일하는 사람에게는 그것이 곧 개정 흐름이다.
3. **원장도 평문(JSONL)** — 숨긴 데이터가 없다(불변식 ①은 진실 층에도 적용).
4. **`dec verify`가 일치를 증명** — 원장에서 파일 전부 재생성 → 바이트 비교.
5. **떠나는 날 파일이 곧 산출물** — 지문만 떼면 평범한 마크다운 폴더다.
   (한 줄 요약: **위키를 산출물로 갖는 통장.**)

**정직한 비용 셋**: ① "편집=제안"을 배우는 30초(git 커밋을 아는 사람에겐 이미
아는 모형) ② 생성기 버그가 잠깐 낡은 파일을 만들 수 있음 — verify·테스트가
전선 ③ 기계 간 동기화가 git pull만으로 안 됨(원장은 outbox 경유) — 관문 0~2는
한 기계라 당장 무관, 시공 세부로 미룬다. 원장의 위치(홈 vs repo 안)는 장부
두 모드와 함께 1주차에 확정한다.

## §5. 순서 — 무엇부터, 그리고 "돌아간다"의 뜻

각 단계마다 **눈으로 볼 수 있는 증거**를 정의한다. 증거가 없으면 다음으로 안 간다.

| 순서 | 짓는 것 | "됐다"의 정의 |
|---|---|---|
| **0** ✅ | **새 경로의 원장 쓰기를 MCP 바이너리 한 관문으로 모은다** (합치는 게 아니라 *새로 짓는 것이 두 번째 구현을 안 만들게* 한다) | ① 새 사건을 쓰는 코드가 `appendLedger` 하나만 부른다 ② 플러그인의 새 기능은 원장 파일에 직접 안 쓰고 바이너리를 부른다(`captureWithCanonicalRuntime` 선례) ③ **그걸 어기면 테스트가 빨간불** — 기존 두 구현은 그대로 두고 프로토콜 동일성을 대조 테스트로 못박는다 |
| **0-b** ✅ | **N6 훅** — 대화 수집이 자동으로 돈다 | 세션을 끝내고 아무것도 안 했는데 큐에 항목이 쌓인다. **이게 되기 전에는 나머지가 다 "손으로 쳐야 도는 기능"이다** |
| **0-c** ✅ | **파일 생성기 + 지문 + `verify`** (판정 10의 몸통) | 원장에서 `decisions/*.md`가 생성되고, 손으로 고치면 다음 명령이 알아채고, `verify`가 재생성·바이트 비교로 일치를 증명한다 |
| **1** 반 | 새 사건 종류 더하기 (확인·개정·폐지·이탈…) | 사건을 쓰고 되읽어 같은 상태가 나온다. **셋(서명·개정·폐지)은 0-c 에서 앞당겨 지었다** — 파일 생성기를 그것 없이는 시험할 수 없었다. **일시정지도 지었다**(`dec_paused`·`dec-pause` — 단계 9 에서 차단을 달면서 "막지 말고 쉬게 하라"가 필요해졌다). 남은 것: **이탈**(`dec leave`)·**정산**(우편함·영수증·빈티지 고정 — 지금은 `dec-close --prevented` 로 입력구만 있다) |

## §6. 이 저장소에서만 걸리는 함정 (미리 적어둔다)

1. **CI의 `check` 잡이 로컬보다 넓다.** `npm test`는 덮개율을 안 재는데 CI는 잰다.
   테스트 없는 큰 파일을 더하면 **로컬 초록 · CI 빨강**이 난다. 새 파일마다
   테스트를 같이 쓴다.
2. **MIT 존과 앱 존을 한 PR에 섞으면 막힌다** (`zone-purity` 검사). 새 코드는
   거의 다 `argus-mcp/`(MIT)라 대부분 한 존이지만, 화면 쪽을 건드리는 순간
   PR을 갈라야 한다.
3. **MIT 존을 고치면 로컬 `npm test`가 아무것도 검증 안 한다** — 자체 검사기를
   갖고 CI에서만 돈다. 로컬에서 초록 봤다고 안심하면 안 된다.
4. **잠금 규율을 깨면 조용히 데이터가 깨진다.** `lock → 되읽기 → 전이 검사 →
   쓰기 → 잠금 해제`가 범위이고, 영수증·내보내기는 **잠금 밖**이다. 지금 코드가
   그렇게 돼 있고 이유가 주석에 적혀 있다.
5. **날짜 계산을 직접 하지 않는다.** `resolve-today.ts`가 "기한은 오늘보다 커야
   한다"를 강제한다. 이걸 우회하면 하루 짜리 왕복이 이틀이 된다 (이미 한 번 겪음).
6. **인용문은 바이트로 대조한다.** `harvest.ts`가 이미 그렇게 한다 — 인용이
   원본에 진짜 그대로 있는지 확인하고, 없으면 버린다. **이 검사를 끄면 제품이
   지어낸 인용을 사용자에게 보여주게 된다.**
7. **이름·주석으로 판단하지 않는다 — 함수를 읽는다** (2026-08-21 승격: 같은
   종류 2회째). 이 저장소는 파일 이름과 머리 주석이 **의도**를 말하고 실제
   배선은 다른 곳에 있는 일이 잦다. 두 번 다 같은 방식으로 틀렸다 —
   *"harvest가 대화를 읽는다"*(실은 훅이 아니라 스킬 문서가 시작시킨다) ·
   *"원장 writer가 셋이다"*(실은 하나는 미러, 둘은 패키지 경계 때문의 의도된
   이중 구현). **"있다/없다"를 적기 전에 호출자를 끝까지 따라간다.**
9. **`argus-mcp/src/lib/` 를 고쳤으면 `npm run verify` 를 돌린다** (2026-08-21
   실제로 CI 를 빨갛게 만든 것). `evals/verify-all.mjs` 는 **게이트가 아직
   무는지**를 시험한다 — 사본에 회귀를 일부러 심고 그 게이트가 빨간불을 내는지
   본다. 그런데 심는 방법이 **소스의 특정 한 줄을 문자열로 갈아치우는 것**이라,
   그 줄을 리팩터로 옮기거나 지우면 심을 자리가 없어지고 검사가 조용히 무효가
   된다(다행히 *"회귀를 심지 못했다"* 로 크게 실패한다). `npm test` 도 `tsc` 도
   이걸 안 잡는다 — CI 의 `npm run verify` 스텝만 잡는다.
   **지금 겨냥된 파일 열**: `lib/ambient-elicit.ts` · `lib/apps-ui-html.ts` ·
   `lib/elicit.ts` · `lib/ledger-replay.ts` · `lib/render-receipt.ts` ·
   `lib/untrusted.ts` · `server.ts` · `tools/premises.ts` · `tools/seal.ts` ·
   `tools/settle.ts`.

11. **브랜치를 안 가르고 MIT 존 파일을 더하면 `zone-purity` 가 막는다**
   (2026-08-21 실제로 걸림 — **§1 에 내가 직접 적어 둔 규율을 내가 어겼다**).
   검사는 `HEAD~1` 이 아니라 **origin/main 과의 공통 조상**부터 본다. 즉
   브랜치에 앱 존 커밋이 하나라도 있으면, 그 뒤에 MIT 존 파일을 한 개만
   더해도 브랜치 전체가 두 존이 된다.
   **시작할 때 정하는 것이 유일한 값싼 순간이다** — 나중에 가르려면 이미
   푸시된 브랜치를 되감아야 하고, 그건 사람이 정할 일이 된다.
   순서: `git log --oneline $(git merge-base origin/main HEAD)..HEAD -- src/`
   를 **첫 커밋 전에** 돌려 보고, 결과가 비어 있지 않으면 새 브랜치를 딴다.

12. **MIT 존만 고쳤어도 루트 `npm test` 를 돌린다** (2026-08-21, 두 번째
   CI 빨간불의 뿌리). 루트 스위트에는 **저장소 전체·브랜치 전체를 보는 가드**가
   산다 — `zone-purity`(브랜치가 두 존을 건드리나) · 도달성 래칫 · 스키마 드리프트 ·
   저장 선언. `argus-mcp` 안에서 도는 검사는 그것들의 존재를 모른다.
   나는 엔진 스위트만 돌리고 "전체 통과"라고 말했고, 두 번 다 틀렸다.

10. **새 필드를 더하면 따라와야 하는 것들이 있다.** 이 저장소는 그걸 규약으로
   갖고 있다(CLAUDE.md의 필드 추가 점검표·스키마 동기화). 새 사건 종류를
   더할 때 같은 규율을 따른다.

13. **재발 방지 장치를 손으로 관리하면 같이 썩는다.** 화면 글이 없는 명령을
    가르치는 걸 막으려고 가드를 만들면서 **검사할 파일 목록을 손으로 적었고,
    바로 다음에 `render.ts`(사람이 제일 많이 읽는 화면)를 빠뜨렸다.** 목록·
    허용목록·기준선을 새로 만들 때는 **훑기로 대신할 수 있는지 먼저 본다.**
    (같은 종류 2회째 — `LEDGER_WRITERS` 허용목록도 처음에 둘을 빠뜨렸다.)

14. **초록 테스트가 결함을 못박고 있을 수 있다.** `dec misfire D-0001` 은
    그대로 치면 안 도는 형태인데, 내 테스트가 `toContain('dec misfire D-0001')`
    로 그걸 고정하고 있었다. **화면 글을 검사할 때는 "지금 나오는 것"이 아니라
    "쳐서 도는 것"을 적는다.**

  걸렸는지 판정하는 자리에 모델을 넣으면 되돌릴 수 없다.
- **임베딩·그래프 검색** — 기획서가 이미 금지했다. 시공에서 다시 유혹이 온다.

- **"전제" 개념 되살리기** — 808줄이 있어서 쓰고 싶어지지만, 새 기획에 그
  개념이 없다. 잠근다.
