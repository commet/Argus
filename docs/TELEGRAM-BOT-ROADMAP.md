# Telegram Bot Roadmap — Argus의 장점을 텔레그램으로

작성 2026-06-24. 목표: @Argus00bot을 "전제 한 번 짚는 도구"에서
**"내 판단을 같이 세우고, 봉인하고, 정한 날 돌아와 묻는 동반자"**로 키운다.
지금은 reframe 1단계만 라이브(맛보기 한 입). [[telegram-reframe-bot]]

## 변하지 않는 4원칙 (모든 단계에 적용)

1. **두뇌는 공유, 복제 금지.** 각 기능의 프롬프트·로직을 `*-core.ts` lib으로
   추출 → 웹앱과 봇이 같이 import. (이미 reframe-core가 그 본보기.) 플러그인은
   TS 공유 불가지만 그 core 프롬프트를 정본으로 따라간다. (CLAUDE.md 단일출처)
2. **스파인 준수 = zero judgment / 절제.** 봇은 사용자를 판정하지 않는다. 방향
   단정·가중 양극 분기 금지 → **하나의 하중 큰 전제 + 중립적 크럭스 질문**만
   내고 손잡이는 돌려준다. (CLAUDE.md 미러 절). 봇 카피도 이 규약을 탄다.
3. **텔레그램의 강점 = 푸시 + 버튼.** 무거운 생성(팀 분석·문서)은 채팅에 욱여넣지
   말고 웹앱으로 딥링크 핸드오프. 봇은 **앞단(전제·질문·봉인·리허설) + 알림**에 집중.
4. **신뢰성·비용.** 강제-JSON(tool use)으로 파싱 무결, 동기 처리, 연결 사용자만 +
   일일 한도. 무거운 기능일수록 캡 타이트하게 or 웹앱 핸드오프.

## 사용자 여정 (이게 곧 Argus 스파인 = 판단의 사다리)

```
결정 던짐 → ① 전제 점검(reframe) → ② 진짜 질문 다시 세우기
         → ③ 내기로 봉인(seal) → [정한 날] ④ "어떻게 됐어요?"(settle)
         → ⑤ 쌓인 기록으로 내 판단 패턴/자차표
```
①만 지금 있음. **③④가 Argus의 핵심 약속이자 해자** — 그래서 다음 1순위.

---

## Phase 1 — 핵심 루프 닫기: 봉인 → 정산 (최우선, 해자)

**왜 1순위:** Argus의 진짜 약속("정한 날 돌아와 묻는다")이고, 텔레그램이 제일
잘하는 푸시 알림과 정확히 맞고, 판단의 사다리 루프(전제→약속→현실→보정)를 완성한다.

- **Seal:** reframe 뒤(또는 요청 시) 봇이 결정에서 *반증 가능한 예측 + 확인일*을
  초안 → 사용자가 버튼으로 확정/수정 → 원장에 기록.
- **Reminder:** Vercel cron(이미 `CRON_SECRET` 있음)이 매일 확인일 도래한 내기를
  찾아 "그래서 어떻게 됐어요?" + [발생/회피/부분/아직] 버튼 DM.
- **Settle:** 버튼 → 결과 기록. 누적 5건부터 자차표(calibration) 의미.
- **추출:** seal-core.ts (예측·확인일 초안 프롬프트, argus-watch/ledger.mjs 로직과
  정합). 봇 결정 저장 테이블(또는 plugin_decisions 재사용).
- **신규 인프라:** cron 1개. (중간 규모)

## Phase 2 — reframe 완성 + 절제 크럭스

- **reframe 2단계:** 전제만 말고 *"네 진짜 질문은 사실 X 아니야?"* 질문 재정의.
  reframe-core 확장.
- **절제:** 하중 가장 큰 전제 하나를 **중립 크럭스 질문**으로 (판정 아님, 미러 절).
- 신규 인프라 거의 없음. 스파인 충실도 ↑. (작음)

## Phase 3 — Rehearse (상사·이해관계자 시뮬레이션)

- "이 계획을 [상사/투자자]에게" → 봇이 그 사람 반응·우려·승인 조건을 시뮬레이션.
- 추출: rehearse-core (페르소나 시뮬 프롬프트) + 선택적 페르소나 입력(MBTI 등).
- LLM 비용 ↑ → 캡 주의. 텔레그램 적합도 좋음(대화형). (중간)

## Phase 4 — Patterns / 자차표 인사이트

- Phase 1 정산이 ≥5건 쌓이면: 블라인드스팟·보정 기록("예측과 다른 곳 도착 N건")을
  주기적으로 푸시. 의미-언어는 표본 크기 스케일 빈도 진술만(CLAUDE.md).
- Phase 1 데이터 의존. 텔레그램 강점(푸시)으로 전달. (작음~중간, 데이터 대기)

## Phase 5 — Recast + 무거운 본체는 웹앱 핸드오프

- **recast**(AI/사람 역할 분담): 가벼워서 봇 가능.
- **team 전체 분석 + 최종 문서:** 채팅엔 과함(느리고 길고 비쌈) → 봇이 **웹앱
  딥링크 생성**("팀 전체 분석은 여기서 →"). 채팅은 가볍게, 무거운 건 웹앱.
  ← 정직한 경계선.

## 가로지르는 후속: 대화 라우터 / 메뉴

기능이 늘면 봇이 의도를 분기해야 함 — 가벼운 인텐트 감지 or 인라인 메뉴
(전제점검 / 내기봉인 / 리허설 / 내 기록). Phase 2~3 즈음 도입.
